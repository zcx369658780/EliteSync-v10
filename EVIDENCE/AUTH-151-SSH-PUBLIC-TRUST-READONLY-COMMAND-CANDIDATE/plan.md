## `NOT_FIXED` 的首个技术停点

`FIRST_BLOCKER=RUNNING_SSHD_TO_PUBLIC_KEY_ASSOCIATION_NOT_FIXED`。当前没有可信固定的**正在提供目标 SSH 服务**的进程/单位、其实际启动参数与有效配置来源，也没有从该服务的 host-key 配置指向**公有**对象的已核定映射。`sshd_config(5)` 的 `HostKey` 指令指定的是**私钥**；用发行版默认目录或在其路径后机械附加 `.pub` 只能得到文件名猜测，不能证明该文件是公钥、不是指向私钥的链接，更不能证明运行服务实际使用它。Owner 允许最多四个候选，不代表可扫描目录或先截取四个任意 `.pub` 作为成功；遇第五个或多义性必须失败即停。

OpenSSH 官方 [`sshd(8)`](https://man.openbsd.org/sshd.8) 描述 `-G` 为解析并输出有效配置，但默认解析结果**不自动等于运行中进程的配置**；实际进程可能使用不同配置文件或参数。该手册描述 `-T` 还执行 `-t` 的额外检查，而 `-t` 涉及密钥健全性；在“不读取 host 私钥”硬边界下，本任务不能提交 `sshd -T`。即便用 `-G` 而抑制其配置全文输出，也尚无已审方式把该解析结果与正在监听的 sshd 关联，或由 `HostKey` 私钥对象安全地取得实际公钥；官方语义未保证可借 `-G` 单独完成这两项。Ubuntu Server [OpenSSH 说明](https://documentation.ubuntu.com/server/how-to/security/openssh-server/)的默认主配置/包含片段只是通用布局，不能当本实例事实。

仅用系统工具读取监听（例如只读服务/套接字元数据）也只可给某一进程/端口候选，不能从中自动得出该进程提供的公钥。把**任意** `.pub` 文件的指纹与监听端口并列输出，不满足“当前有效 sshd 的公有 host key”这一目的。若文件实际为私钥或链接指向私钥，打开它便违反 Owner 明示禁令；文件名、权限或后缀本身不足以排除该风险。因此，本轮不给出猜测路径、默认算法/端口、未限定文件读取或 `ssh-keyscan`/首次握手替代命令。`HOST_KEY_SOURCE=UNKNOWN`、`EFFECTIVE_LISTENER=UNKNOWN`，不是技术 PASS。
