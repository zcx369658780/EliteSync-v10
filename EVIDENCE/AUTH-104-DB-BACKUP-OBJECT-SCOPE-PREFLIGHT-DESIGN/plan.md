## 独立权威全集与受控集合比较

1. **先固定同一目标。** 后继现场任务必须先用独立接受的目标身份门固定实例、库及时间窗，再指定 DBA/数据责任方有权访问的权威目录来源，以及拟备份账号的实际身份。若目标、账户或时窗未锁定，全部比较为 UNKNOWN。不得凭 `.env` 文本、本地迁移数、AUTH-65 的 43 或 `SHOW GRANTS` 文本推定完整。
2. **权威全集。** DBA/数据责任方使用能覆盖目标库全部对象类型的独立高权限只读目录视图或经核验的管理目录；先核验该来源自身权限与对象类别覆盖，不能只把另一个受限 `information_schema` 视图称为权威。以规范键（对象类型、库内标识及必要父子关系）在获授权进程内构造集合，覆盖基表、视图、触发器、存储过程/函数、事件，以及选定 dump 方式需要的依赖、定义与权限元数据。权限无法证明覆盖某类别时，该类别及全集均 UNKNOWN。
3. **拟备份账号视图。** 使用与最终 dump 相同的账号、有效角色、目标实例/库、连接路径和会话条件，只读收集其可见集合；分类比较对象**集合相等**、类型计数、可读定义与数据权限。只做计数相等不能排除一缺一多；集合相等也不证明数据可完整导出、事务一致或隔离恢复可用。原始对象标识和比较用暂态标记仅在受控内存处理，完成即丢弃；普通证据只记类别、计数及 MATCH/FAIL/UNKNOWN，不记录集合摘要或对象名。若确需追查差异，在另行授权的受保护渠道由 DBA 处理，不写普通回执。
4. **失败即停。** 权威来源不独立、权限不全、任一类别不可见、集合不等、角色/定义权限不明或观测期间结构变化，停止“完整范围”判定；不补猜对象、不临场扩大查询，也不以备份账号的可见 0 推断真实 0。
