## 1. 精确记录形状与来源边界

拟新增独立 family `MESSAGING_CONSENT_STATE_TRANSITION_DERIVED_PROJECTION`，不复用现有 Product Connection family。记录使用现有逻辑 repository 的顶层键集：`logical_record_identity`、`record_family`、`bindings`、`source_revision`、`source_condition`、`currentness`、`freshness`、`logical_intent`、`authoritative_outcome`、`authoritative_outcome_metadata`、`correction_metadata`、`projection_metadata`、`transport_observation`、`private_fixture_extensions`、`derived_projection_payload`，不得多键或缺键。`private_fixture_extensions=[]`。现有 repository 尚未接受此 family；这是待 Work 审查的新增合同，不表示代码已支持它。

`bindings` **恰为真实 Common Authority 十一个键**：`authority_owner`、`authority_scope`、`actor`、`actor_role`、`subject`、`participants`、`audience`、`purpose`、`aggregate_context`、`lifecycle_identity`、`terminal`。前八项中除 `participants` 外均为非空字符串；`participants` 是恰两个不同非空 synthetic 参与者引用组成的列表；`aggregate_context` 与 `lifecycle_identity` 为非空 consent identity；`terminal` 为 bool。`authority_owner='MC_DERIVATION'`、`actor='MC_DERIVATION'`、`actor_role='DERIVED_NON_AUTHORITATIVE_CORRELATION'` 只标记**派生记录的作者**；`subject` 是所绑定的当前 Product Connection identity，`audience='INTERNAL_APPLICATION_PERSISTENCE'`，`purpose` 只能是 `CONVERSATION_LIVE_READ` 或 `CONVERSATION_LIVE_SEND`。`authority_scope` 须把 family、payload kind 和该 purpose 固定在同一规范化值。来源证据自己的 `required_bindings.actor/actor_role/authority_owner/authority_scope` 和转移 `actor` 保存在独立 dependency 中，不能被顶层派生 actor 覆盖或冒充。逐字段严格比较十一键及值/类型；仅 associative key 的插入顺序不影响等价。两个 purpose、两个 consent identity、两个 Connection aggregate 绝不共享记录或 revision lineage。

`source_revision` 顶层也恰有 Common Authority 五键：`authority_owner`、`authority_scope`、`lineage`、`aggregate_context`、`value`；前四项非空字符串且 owner/scope 与顶层派生 bindings 一致，`value` 为非负整数。它是派生记录**本地相关性修订**，lineage 由 `(consent identity, purpose, payload kind, MC 来源 lineage)` 规范化确定，value 只映射所关联的 MC 来源本地 revision；来源 MC 的原 owner/scope/lineage/value 在 dependency 中另存。它不是 MC writer 的 source revision，不与 CN revision 合并，也不构造全局 revision。`logical_intent` 恰有 `intent_identity` 和规范化的 `semantic_input`；同一 synthetic 来源断言的不可变 evidence identity（转移时为 transition identity）决定稳定 intent identity，`logical_record_identity` 由 family、payload kind 和该 intent identity 决定，**不把可变内容放入 identity**。`semantic_input` 固定全部允许的脱敏输入与依赖摘要；同 identity 同语义/结果为 `EXACT_DUPLICATE`，改任何状态、身份、绑定、修订、角色、用途、结果为 `CHANGED_INPUT_REUSE_REJECTED`。不存正文、真实账号、密码、Token、Safety 或历史 Conversation 内容。

`derived_projection_payload` **恰含** `schema_marker`、`payload_kind`、`consent_identity`、`connection_identity`、`participant_references`、`requester`、`recipient`、`purpose`、`classification`、`current_state`、`proposed_state`、`reason_categories`、`connection_dependency`、`consent_state_dependency`、`transition_dependency`、`terminality`、`invalidation`。`schema_marker` 为 `mc-source-state-correlation-v1` 或 `mc-transition-derivation-v1`；`payload_kind` 分别为 `MC_CURRENT_STATE` 或 `MC_TRANSITION`。identity/context/requester/recipient/purpose 为非空 synthetic 引用；参与者恰两个且与当前 CN context 精确相同，requester 与 recipient 是其中不同的人，旧 consent identity 上不能交换。`reason_categories` 为固定、去重的非私密枚举。当前态 kind 的 `classification` 为**来源报告**的 MC 六态之一或 `UNKNOWN`，`proposed_state=null`、`transition_dependency=null`；转移 kind 的 `classification` 仅 `ADMISSIBLE/REJECTED/UNKNOWN`，from/to 状态为六态或 null。`terminality` 恰为 `current_state_terminal`、`proposed_state_terminal`、`terminal_reopen_rejected` 三个 bool；`invalidation` 恰为 `invalidated` bool、`relation` nullable string、`dependency_identity` nullable string、`lifecycle_reset=false`、`consent_reopened=false`。不接受额外状态、`MC_PAUSED/MC_CLOSED`、额外字段、错误类型或未知 marker。

每个非空 dependency 仅是**一份已给定来源证据的脱敏固定投影**，不是来源签发或当前性证明。`connection_dependency`、`consent_state_dependency` 各恰含 `evidence_identity`、`required_bindings`（上述十一键，保持来源实际 owner/actor）、`source_revision`（上述五键，保持来源实际 owner/lineage）、`state`、`source_condition`、`currentness`、`freshness`、`protected_binding_satisfied`。`state` 各限 CN 或 MC 正式 vocabulary；后三项分别为字符串枚举、bool|null、bool|null、bool，不得混型。`transition_dependency` 另含 `transition_identity`、`actor`、`from_state`、`to_state`、`expected_state_revision`，其中 expected revision 必须逐字段等于所依赖 MC 当前态来源的五键 revision，不能用 CN revision 替代。来源 actor 和 requester/recipient 的角色按现有 evaluator 的转移规则校验。所需 dependency 缺失时槽位为 null、`classification=UNKNOWN`、不可授权；不能用空对象补位或自行生成“当前”证据。

## 2. `source_condition` 与 bool/null 的确定性保守映射

`source_condition` **只允许字符串枚举** `PRESENT`、`ABSENT`、`UNKNOWN`、`UNAVAILABLE`、`STALE`、`SUPERSEDED`、`INCOMPARABLE`；绝不是 bool/null。对本记录所有必需 dependency：全部为 `PRESENT` 才映射顶层 `PRESENT`；任一缺失或混合非 `PRESENT` 值映射 `UNKNOWN`；全部同为某一非 `PRESENT` 值时保留该值。若已明确同 lineage 不同语义冲突，顶层映射 `UNKNOWN` 并保留受限冲突 reason；不同 lineage 无可比关系可映射 `INCOMPARABLE`，但不得伪造一个较大 revision。该映射只描述输入证据条件，不因 store/readback 成功而更新。

`currentness` 和 `freshness` **各自仅为 bool|null**，独立求保守聚合：若任何必需 dependency 明确为 false，结果为 false；若全部 dependency condition 为 `PRESENT` 且对应 bool 全为 true、无冲突/失效，结果才为 true；其他情况为 null。`ABSENT/STALE/SUPERSEDED` 这类已知不满足条件的输入即使携带 true，也不能生成可用投影；条件为 `UNKNOWN/UNAVAILABLE/INCOMPARABLE` 或依赖缺失时 bool 不得升为 true。correction/supersession/revocation 指向该依赖后，投影另标 `invalidated=true`，保护性读取不可用；不能通过存储成功、晚到重放或删除失效标记恢复 true。即使字符串 `PRESENT` 与两个 true 同时出现，也只是**来源携带并经形状/绑定校验的 synthetic 投影状态**，不等于当前真实 MC authority 或 live permission。

失败表：缺失/`UNKNOWN`/`UNAVAILABLE` → 无 current selection、非权限 `UNKNOWN`；`ABSENT` → 已知无此来源，非权限；`STALE/SUPERSEDED` → 旧记录不得授予；不新鲜或非 current → bool false/null、不可用；同 revision 不同语义 → 冲突拒绝；不可比 lineage → 不选胜者；来源 correction/supersession/revocation → 精确旧 dependency/record 失效；跨 Connection、participant、audience、purpose 或 consent identity → 绑定失败。所有分支都不得产生 live-read/live-send grant，也不得将 transport timeout 当作 authoritative outcome。

## 3. 当前态、转移与 live gate 的真实接口关系

现有 `MessagingConsentConversationLiveGateEvaluator` 的**公开**入口是 `evaluateTransition(...)`、`evaluateLiveGates(...)` 与 `invalidateLiveGate(...)`；它没有公开的 `evaluateCurrent(...)`。内部处理 MC 当前态的函数只服务 live-gate 求值，不能作为独立当前态 API 调用或伪造结果。因此 `MC_CURRENT_STATE` 是对**调用方提供的一份 synthetic、来源携带的 MC state evidence** 建立的脱敏相关性记录：保留精确 evidence identity、bindings、source revision、condition/currentness/freshness、state 和 context；校验形状、同一 consent/Connection/participant/purpose 绑定与本记录自洽性。它**不**声称在多份来源中选出最新、不调用不存在的 evaluator 当前态入口、不从存储顺序判定真实 MC current。若输入为多份相互冲突/不可比的状态证据，repository 只保留各自受限相关性并把 resolveCurrent 判为不可用/不可比，不给一个合成 `MC_ACTIVE`。

`MC_TRANSITION` 才可在**另一个后继 application adapter 任务**中，向公开的 `evaluateTransition(consent, connection, connectionEvidence, consentStateEvidence, transitionEvidence)` 提交完整、同源且经前述校验的 synthetic 集合，存储它返回的分类、原因和 dependency 向量；repository-only 切片不执行该求值，也不推测转移结果。当前 MC state evidence 作为此入口的**输入**，不是该入口的独立 current-state 输出。live-read/live-send 只在使用点（后继独立任务）用公开 `evaluateLiveGates(...)` 以及当次独立取得的 CN 和各用途 MC 来源证据求值；`invalidateLiveGate(...)` 只针对精确依赖失效的已派生 gate，不重新签发来源。send 在提交时重新取并核 `CN_ACTIVE` 与同目的 `MC_ACTIVE`。存储记录、派生投影、transport 观察、离线缓存或历史 Conversation 均不替代使用点权威。真实 MC 来源、writer、auth/session、受保护动作接线仍 `NOT_READY`。

原 MC 转移语义保持：`MC_NONE→MC_PENDING` 仅当前 `CN_ACTIVE` 中一方请求；`MC_PENDING→MC_ACTIVE/MC_DECLINED` 仅绑定 recipient；`MC_PENDING→MC_WITHDRAWN` 仅绑定 requester；`MC_ACTIVE→MC_REVOKED` 由任一绑定参与者。其余直接转移拒绝。`MC_DECLINED/MC_WITHDRAWN/MC_REVOKED` 对旧 consent identity 终态，新尝试须新的 consent context/request identity，重新走 `MC_NONE→MC_PENDING`；generic dependency `REVOCATION` 失效关系不能伪装为来源 `MC_REVOKED` 状态。相同 immutable intent 重放仅可 exact duplicate；changed-input reuse、等 revision 冲突、不同 lineage 不可比、乱序、旧 active 晚到及终态旧 identity 重开均 fail closed。独立 read/send purpose 不能互借，CN 与 MC 修订不合并。
