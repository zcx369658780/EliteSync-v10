## 当前证据和共同安全不变量

AUTH-163 的六个虚构场景首跑通过，但 Work **LEVEL 3 REJECT** 其作为硬监督器：同步 `Popen` 在计时建立前可能阻塞，管道预取可超出应用层计数，只检查直接子进程不能证明子孙清空。AUTH-166 只接受修复/负例合同，三项硬保证仍未解。AUTH-170 在任何人工父启动前停下；AUTH-171/178/180 固定的是部分 Win32 来源和候选顺序，AUTH-177 的十个纯内存测试只证明假适配器的恢复前失败关闭。`KILL_ON_JOB_CLOSE` 文档语义需要限制实际生效、最后句柄关闭及成员关系；它不保证同步调用有界、关闭已完成或无逃逸后代。普通 timeout、直接父退出、静态 ABI 与虚构 PASS 均不能升级为硬总墙钟或 `TREE_CLEARED`。

三条路径都须保持同一认证门：**认证失败、未知、超时、超限或截断时，真实数据库/CMS 消费者调用 0 次、交付 0 字节**；没有经独立核对的认证成功与隔离目标能力时同样不得放行。AUTH-164 已接受的 A/B 只是一份 `NOT_READY` 可行比较：内存方案仍缺 pagefile/转储/锁页/清零和硬监督证据；受控加密暂存仍需介质、位置、密钥与残留责任的 Owner 具体选择。任何路径都不能用“内存中”或“加密”字样代替无敏感明文落盘证明。

## 推荐顺序与 Owner 决策点

**推荐下一张无需 Owner 输入的有界切片：先做 A/B 共用的纯内存“外部观察者与残留阻断”负例。** Work 可另发一张 LEVEL 3 synthetic 任务，只允许一个小型假状态机、定向负例和脱敏回执：用假时钟与假接口模拟启动前阻塞、清理阻塞、IPC 断开、监督者失联及残留未知；每个未确认分支必须阻断假消费者并记录调用/字节均为 0。它检验状态分类和 0/0 传播，**不**宣称真实全链硬墙钟、真实隔离、进程树清空或明文防落盘。首跑预算、精确允许文件和独立审查由 Work 新任务固定，本作者不派发。之后再分别审静态外部监督原语/不可中断调用边界、Job 成员/句柄证据，以及隔离目标与暂存保护；局部 PASS 不合并为现场授权。

在 A 的严格准则下，目前无需 Owner 为下一张纯虚构任务作选择；真实现场动作仍受现有门限制。**仅当 Work 拟用 B 的 `RESIDUAL_UNKNOWN` 替代现行硬总墙钟及清空证明，或拟在 C 中选择真实隔离/暂存介质时，才应停 Owner 决策。** 对准则变更可提交的精确一句问题是：**“是否允许在独立审查的隔离边界持续阻断真实消费者且残留记为 `RESIDUAL_UNKNOWN` 的条件下，以受限阶段超时替代现行恢复前必须证明硬总墙钟与进程树清空的准则？”** 在 Owner 明确回答并由 Work 修订受影响门之前，答案视为**未授权放宽**；任何真实数据、生产、不可逆或 UAC 到场仍需各自具体授权，不能由此句概括批准。
