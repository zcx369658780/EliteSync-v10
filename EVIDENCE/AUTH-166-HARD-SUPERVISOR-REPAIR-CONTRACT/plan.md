## 跨阶段边界与失败语义

计时起点须是**调用入口接受请求之前**由独立于被监督进程的单调时钟记录；终点须覆盖启动、双流读取、停止、整棵进程树存活核对与返回最终状态。预算是同一个绝对截止时刻，不得在 `Popen`、读流、清理时重置。实现候选须在受控、无 UAC、无服务自动启动、无网络依赖的虚构任务上先证明其系统调用与监督者本身的行为。若调用入口、监督者启动或宿主调度不能被截止机制强制约束，**“调用到返回的硬墙钟”仍 `UNRESOLVED`**；只能报局部测量，不把预设 timeout 当硬保证。

失败分类至少区分 `START_ERROR`、`START_DEADLINE`、`STDOUT_LIMIT`、`STDERR_LIMIT`、`READ_ERROR`、`TOTAL_DEADLINE`、`TREE_UNCERTAIN`、`SUPERVISOR_ERROR` 与正常完成。发生任一失败即拒绝消费与后继动作；即使被监督进程随后退出 0，也不得改写失败。超时或清理失败可以返回一个**失败且存活不确定**的回执，但不能同时声称进程树已清空。后继应固定每个失败态的可观察脱敏字段、监督者故障时的隔离责任和停止条件；本合同不定义可执行现场状态机。

## 2. stdout/stderr 底层读取与内存保留的双流硬字节限额

设经后继任务固定的每流限额为 `L_out`、`L_err`。如策略允许超限见证字节，每流**实际从管道读取到监督者用户态的总字节**与其同一时刻保留的内容均不得超过 `L+1`；其中第 `L+1` 字节只证明超限，永不进入可消费内容。若连见证字节也禁止，则改用不读取正文的可信长度/背压判据，当前没有这样的已证机制，记 `UNRESOLVED`。管道内核缓冲中的尚未读取字节与被监督进程自己的内存属于另外的资源边界，不能称已受本限额约束。

| 项 | 可验证修复合同 |
| --- | --- |
| 拟用原语 | 两条**独立并发**的非缓冲句柄读取路径，候选为 Windows `ReadFile` 配合各自固定大小、预先分配的可写缓冲区；每次请求长度 `<= min(剩余额度+1, 固定块上限)`。不用 Python `BufferedReader.read()`、`communicate()` 或在高层计数后再声称底层无预取。对每流分别计数实际完成的读取字节、保留字节和见证字节；不得因解码、日志、异常格式化、复制为不可变对象或跨线程队列形成未经计数的第二份正文。 |
| 最小虚构负例 | 人工子进程并发快速向两流写超过 `L+1` 的不同虚构字节，包含 `L=0`、恰好 `L`、`L+1`、大块一次写入、交错小块写入、一流关闭而另一流持续写、部分读取、读错误及超时竞态。加入能暴露底层预取的“高层只请求 1 字节、底层可获得大块”对照，旧 `read()` 计数方案必须失败。 |
| 测量与 PASS 条件 | 在实际 OS 读取调用边界记录每次请求长度、完成长度、累计值；在用户态分配/复制边界记录同时存在的正文缓冲和峰值，并由独立虚构生产者记录两流发送量。每流累计实际读取和峰值正文保留均 `<= L+1`，正常内容 `<= L`；任一超限即失败并按进程树门清理。异常、双流同时超限、截止竞态下不得丢失限额判定或把部分流当完整输出。计数器本身和固定元数据可以保留，但不得保留正文或扩散到回执。 |
