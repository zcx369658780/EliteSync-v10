## 来源与可得结论

公开官方来源：[OpenBSD OpenSSH `ssh(1)` 手册](https://man.openbsd.org/ssh.1)，`EXIT STATUS` 节；2026-09-26 只读访问该页面，HTTP 200。该节原文为：“`ssh exits with the exit status of the remote command or with 255 if an error occurred.`” 这是 SSH **本地进程**退出值的文档语义。远端命令自身也可能退出 255；仅凭本地数值 255 不能判定是哪一类，统一失败并保持原因 `UNKNOWN`。本手册句子没有说明远端命令内部两个工具子进程的退出，也不证明收到的 JSON 是固定程序生成的。

本地既有证据边界：AUTH-107 [Phase A 方案](../AUTH-107-DUMP-TOOL-READONLY-PROBE-CANDIDATE/plan.md) 只获静态边界 ACCEPT，完整虚构投影测试 `NOT_VERIFIED`，现场 Phase B 未放行；AUTH-108/109 仅接受本地虚构工具捕获与同进程投影；AUTH-110 仅接受调用方给定虚构字节的严格 JSON 解析；AUTH-111 仅接受本地临时虚构进程的采集接线，其 `remote_exit_candidate` 明标 `UNVERIFIED_CALLER_CANDIDATE`，`Popen` 启动阻塞仍未硬限时。这些接受均不证明目标主机、SSH 或真实工具。

## 一种未来候选协议（本轮不执行）

1. **现场前固定对象并另立任务。** Work 锁定单一目标主机与 host-key、SSH 身份、远端程序的精确路径/字节/哈希及其启动方式、工具绝对路径/别名/哈希、环境净化、两组首参数 `--no-defaults` 后分别仅 `--version`/`--help`。审查远端命令如何传给程序，不能因本合同假设 SSH 直接执行参数数组或绕开远端 shell。未经独立固定不得运行。
2. **远端受控采集。** 固定远端程序在受控内存中逐流限额、并发排空两个工具进程；任一次 stderr 非空、退出非零、超限、超时、捕获不完整或来源不符即失败。完整成功时才投影两个**程序实测的工具退出码**，不把原始版本/帮助/stderr、异常、路径或环境带入普通回执。所有选项状态保持 `UNKNOWN`。
3. **唯一输出与退出。** 远端程序只在全部内部门通过后向 stdout 写入并刷新最多一行、总计不超过 2 KiB 的固定 UTF-8 JSON，随后退出 0；失败可不输出或仅输出一行固定安全失败 JSON，并以预定非零值退出。不得设计 255 为远端程序的正常失败码；即便远端意外返回 255，本地仍按歧义失败。JSON 中的 `error_class=NONE`、两个工具 `exit_codes=[0,0]` 是程序声明，不能标为本地独立观测。写入/刷新失败必须令远端程序失败退出；本地仍以收到的完整字节另行核对。
4. **本地联合判定。** 一次获批 SSH 进程的 stdout/stderr 分别限 2 KiB，并发采集且完整结束；stderr 只要非空即失败且不回显。只有本地 SSH 退出 **0**、单行 LF 终止的严格 JSON 通过 AUTH-110 等价格式门、`error_class=NONE`、工具退出声明均为 0，才给“**固定协议下的文本候选**”结论。连接中断、超时、半行/多行、任一超限、SSH 255 或其他非零均失败，即使已经收到看似成功的 JSON；SSH 0 但 JSON 为失败、缺失或不合 schema 也失败。不能把这次 SSH 退出 0 同时记作另一个“独立实测远端退出 0”。

此协议提供**联合一致性检查**，不是三个独立退出量的证明。要把它用于目标主机，仍须先独立验证固定程序和 SSH 通道身份。工具实际来源及权限不由 JSON 自报成立。

## 对现有接口的后继改动门

- AUTH-110 的 `ssh_exit` 与 `remote_exit` 目前是两个调用方输入，无法仅从一个 SSH 本地进程得到两项独立实测值。未来实现任务应保留一个有来源的本地 SSH 退出数值；将“远端程序成功”改为**经固定程序/协议审查的推断或声明状态**，或保留 `remote_exit=UNKNOWN` 并停止肯定投影。不得把 SSH 退出复制成 `remote_exit=0` 以绕过当前解析门。
- AUTH-111 的 `remote_exit_candidate=UNVERIFIED` 正确表达本地虚构阶段；实际现场候选必须先设计、虚构验证上述协议和来源标记，再调整解析/采集接口。它还缺少可严格中断的 `Popen` 启动阻塞处理，以及终止失败、子孙进程继承管道和跨系统行为的验证。不得直接把 AUTH-111 的任意绝对路径接口指向 `ssh.exe`。
- 若未来任务选用该协议，先独立审查固定远端程序如何保证工具两次退出、单行 JSON 与自身退出的顺序和失败语义，再核定一个 SSH 进程、工具调用次数、时限、输出上限、脱敏类别和失败即停预算。AUTH-107 旧 1/1 虚构套件与 AUTH-17 旧 SSH 预算均不重置。
