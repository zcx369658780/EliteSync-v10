## 首个无法闭合的输入与工具风险

**`FIRST_BLOCKER=EXECUTABLE_IDENTITY_AND_SAFE_PUBLIC_SOURCE_NOT_FIXED`。** AUTH-149 只接受 `sshd`、`systemctl`、`service` 在当时 Shell 中的绝对路径形态，未核对普通可执行文件、符号链接终点、文件字节、版本、当前服务进程与配置文件之间的关系。此时把路径候选当可信外部程序执行，会越过本任务的程序身份门；不能从三项字符串输出构造实际服务器命令。

即便后继另行核定了程序身份，现有公开语义也不支持把 `sshd -T` 当成“只读且**不触及私钥**”的安全捷径：OpenSSH [`sshd(8)`](https://man.openbsd.org/sshd.8) 说明 `-T` 扩展测试包含 `-t` 的额外检查，而 `-t` 检查配置和**密钥健全性**；[`sshd_config(5)`](https://man.openbsd.org/sshd_config.5) 明确 `HostKey` 指向**私有** host-key 文件，`Include` 可引入多来源，`Port` 可有多个声明。仅过滤 `-T` stdout 无法证明程序内部没有读取 host 私钥，也无法证明其输出配置与**运行中**进程一致。`systemctl`/其他服务管理工具虽可有只读查询用法，但现时字节身份、单位名称、权限和错误输出未核定；不在此用默认 service 名或命令文本猜测。Ubuntu Server [OpenSSH 配置资料](https://documentation.ubuntu.com/server/how-to/security/openssh-server/)只讲一般布局，AUTH-138 页面镜像标签不证明实例内现状。阿里云[命令助手说明](https://help.aliyun.com/zh/simple-application-server/user-guide/use-command-assistant)证明可配置执行用户/超时、脚本和结果可查看，不证明本实例命令不留存或异常原文安全。

从当前证据也没有一个**既能关联正在监听的 sshd、又能证明只读公有材料而不碰私钥**的固定来源。不能对 `/etc/ssh` 等发行版惯例位置做搜索、不能把私钥路径机械补 `.pub`、不能遍历目录或用 `ssh-keyscan`/首次握手代替控制面锚。故本轮**不提供 `sshd -T`、服务管理器或 Shell 的可运行脚本/参数**，判 `NOT_FIXED`，而非用占位符伪装完整候选。
