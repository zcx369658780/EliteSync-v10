## ACL **预期**合同；允许主体尚 `NOT_FIXED`

比较键必须是可信来源核定的稳定 **SID/身份类别**，不可用显示名、当前用户名字符串、目录可读取性或一段 DACL 文本替代。以下为待 Work/Owner 逐项审定的最小候选，不声称本机存在对应 SID，也不生成 SID/DACL 字符串：

| 身份类别 | 候选处理与仍待决定的事项 |
| --- | --- |
| Owner 当前登录身份 | 候选为可管理一次性目标的唯一普通登录主体。须另核定当前会话与 Owner 的身份绑定、稳定 SID、所需最小权限及创建/清理责任；不能由路径、历史登录名或 `whoami` 猜出。 |
| 本机 SYSTEM | 是否因 Windows/隔离引擎实际运作而必须保留访问，待 Work/Owner 审定；若允许，固定精确 SID、用途和最小权限。不能把“系统通常需要”当默认 Full Control 许可。 |
| 受控管理员身份/组 | 是否允许以及允许何种权限、何时使用，待 Work/Owner 审定。即使 DACL 不列管理员，管理员所有权/备份/恢复等特权仍可能改变或绕过访问边界，须列为残余风险，不宣称完全排除。 |
| 恢复引擎/服务身份 | 如未来确需写目标，只能由独立任务固定其服务身份、SID、作用范围、启动/终止及最小权限后加入；当前**不预先授权**未知服务账号。 |
| `Everyone`、`Authenticated Users`、普通用户/宽泛组、未知 SID、继承宽授权 | 不接受对目标或可替换其名称的父路径授予广泛读取、写入、删除、改 ACL/所有者等有效能力。逐 ACE 和有效权利均须比较；不通过增加显式 Deny 来假装父目录/管理员风险已消除。 |

候选目标 DACL 应采用经审定的显式最小允许清单、明确继承保护与所有者预期；拒绝超出清单的显式或继承允许项。**精确 Owner/SYSTEM/管理员选择、SID、权限掩码、所有者和服务身份尚 `NOT_FIXED`，所以当前没有可比对的最终 ACL 字符串或 PASS 标准。** 父路径也须独立审查：即使目标子目录 DACL 很窄，若其他主体可在父路径创建同名对象、删除/重命名/替换目标，精确路径仍可被劫持。须核对父路径有效的创建、删除子项、重命名及所有权/改 ACL 能力，并控制创建与复核之间的竞态；D: 根 ACL 不等于未来子目录 ACL。若无法限制父路径替换风险，应先让 Work/Owner 重审候选目标与隔离方案，不能临场另选路径。

DACL 还不能单独证明保密性：有效访问受组成员关系、拒绝项、所有权、完整性级别、备份/恢复特权、进程令牌及共享/同步渠道影响。审查须记录这些机制的可证明上限和剩余风险；未知则 `UNKNOWN`，不可用“ACL 匹配”覆盖。不得在普通证据输出原始 ACL、SID 清单、用户名、路径展开或安全描述符。受保护的详细比较材料若有必要，其位置、权限和清理也须独立固定。
