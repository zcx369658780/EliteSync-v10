# v10.1.18计划：UI表达与交互一致性收口

## 1. 产品定位

v10.1.18是B3后的反馈收口版本，不是B4，也不重新打开已接受的B3工程范围。核心是把Owner在真实手机上指出的四项UI问题解决，并补足Buddy诊断和真实冷启动/账号隔离证据。

## 2. 推荐实施顺序

1. 同步Owner反馈、v10.1.17顾问报告和原交付状态，完成反馈追踪表；
2. 全局检索用户可见字符串，建立产品文案词表和状态码映射；
3. 收敛免责声明到权限/说明页，检查首次匹配说明的版本化与一次性展示；
4. 将第二底栏「进展」改为「匹配」，整理匹配结果、轮次、提案和待决定事项；保留旧路由；
5. 统一共享按钮/选项Theme状态，解决selected/pressed对比；
6. 让自动化入口从匹配和我的页面都可发现，但实际控制仍只有一个规范页面；
7. 单独诊断Buddy不能匹配问题，只有确认属于接线缺陷才修复；
8. 在同一模拟器安装中完成A/B账号切换、force-stop和cold-start隔离；
9. 定向验证、构建候选并集中交付。

## 3. 用户文案

先审查所有目标页面和主要空/错/未知状态。每条文案要能回答：
- 当前确定的事实是什么？
- 用户是否需要行动？
- 如果状态未知，如何准确表达而不误导？
- 长说明是否应该移到权限/说明页？

不以“删掉所有解释”为目标，必要权利和隐私说明继续保留。

## 4. 匹配入口

底部第二入口改为「匹配」。主内容围绕当前轮次、结果、提案、历史和本人待决定事项。用户的主观关系体验不由APP评分。保留四入口、旧路由和各业务状态独立性。

## 5. 自动化入口

在匹配页显示简洁参与/自动化摘要，Me中提供清晰设置入口，均跳转B2同一规范授权页。不得在多个页面各自维护自动化状态。

## 6. Buddy诊断

Buddy不能匹配先当作独立问题查证。记录虚构账号、用户状态、请求、响应、候选池和后台任务。只有明确证据支持时修复UI/路由/配置/接口缺陷。算法问题不纳入本版擅自变更。

## 7. 冷启动与账号隔离

使用同一安装、同一模拟器和隔离测试数据，完成A登出→B登录→强制停止→冷启动B→A重新登录。核对内存状态、持久缓存、消息、通知、草稿和离线恢复。不得把本轮Owner观察到的一项“新账号未显示旧消息”扩大为完整隔离通过。

## 8. 成功定义

- 首页与匹配页不再出现明显程序式状态文案；
- 第二底栏清晰显示「匹配」，用户能找到结果、提案和历史；
- 按钮/选项所有交互状态文字清晰可读；
- 自动化入口可在匹配与我的中找到，控制仍唯一；
- 一般说明归位，必要决定不被静默；
- Buddy问题有可复现诊断或有边界的修复；
- 同一安装冷启动/账号隔离完成具名验证；
- 交付新的Owner手动检查表和候选APK。
