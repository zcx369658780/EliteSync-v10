## 1. A1｜真实身份门禁：TEST_ONLY永远不能代表合法正式认证

**当前S1源码观察**：`TrustedIdentityService::status`有`DEV_SYNTHETIC_VERIFIED/PROVIDER_NOT_CONFIGURED`，真实provider`PENDING`；准备度与某些报名/自动参与路径仅部分具备真实核验门禁。

**实施目标**：
- 明确隔离测试合成凭据/测试环境业务与正式真实参与资格（手动报名、自动参与grant/resume、匹配轮次执行、候选发布/提案、正式关系需要真实身份前提的写操作）。
- 真实供应商当前未接入必须在正式正向路径**fail-closed**，不能通过本地合成凭据、数据库标志、旧缓存、返回动画或其它弱资格绕过；不能误将可选MBTI、星盘等当作资格必要条件。
- 不扩大真实用户字段、未批准的新KYC个人信息采集、支付或第三方供应商合同。保持Lifestyle与不依赖真实Match的合法社交功能可用；允许在明确标注TEST_ONLY的受控自动化测试环境测试独立已有能力，不得用测试PASS声明真实身份准入。
- 历史/无效/撤销凭据应被拒绝；当前资格变化需阻断高影响参与操作，不能只靠前端置灰。

**未来验收最小AC**：
- `A1-AC1` 真实provider未接入→所有正式报名/自动参与/轮次候选正向路径无法产生真实有效参与状态；有明确不可用安全结果。
- `A1-AC2` 合成TEST_ONLY/过期/撤销/伪造凭据不满足正式资格，后端拒绝；包含复用旧命令/旧回执的否定场景。
- `A1-AC3` 正常Lifestyle、可独立使用的内容/社交和非真实报名路径不被全局禁用；隔离测试特例只在可证明的测试环境生效，产品文案不能宣称已核验。

## 2. A2｜既有候选绑定原合法发布快照

**当前S1源码观察**：`SlowDatingService::projectLocked`调用`ShowcaseWorkflow::visiblePublicationLocked`取得**当前**有效发布版，`user_profile_showcase_publications`按用户唯一当前行，旧候选可能随新发布被动看到新版。

**实施目标**：
- 区分本人预览、当前已发布版、**具体候选在被合法生成/形成时的可访问发布版本**。产生候选时记录可核证的版本绑定/有效发布身份（具体schema由Codex在本地审阅后设计，须有迁移/回滚安全性）。
- 对旧合法候选只提供其原可访问版本，**每次读取仍重新核验**当前受众、Block、账号与业务资格；新发布不自动替换旧候选绑定。
- 当原历史版本不存在、被撤销/失权、未获合法保留许可或无法安全归属时，**隐藏受影响材料**并提供不泄密安全结果，不虚构旧版/自动补授权；避免把持久留存等同永久访问权。
- 可安全沿用现有发布审核/权威回执，不自动赋予向旧候选共享新版的新权利（NEW-PC-04仍非本阶段）。

**未来验收最小AC**：
- `A2-AC1` 新候选合法形成后读当前有效授权版；既有候选合法形成后发布新版本，仍只读旧合法绑定版。
- `A2-AC2` Block/许可撤销/账号失权/提案过期时，原版本内容及媒体不能通过读接口、通知或缓存继续越权显示。
- `A2-AC3` 不可重建旧版本/无合法证据的迁移场景保守隐藏，不静默升级到新版本、不捏造旧快照。
- `A2-AC4` 存在正确版本冲突处理与独立拒绝测试；迁移仅在隔离测试库可执行，不触及真实用户历史数据。

## 3. A3｜UNKNOWN先只读查询，不能自动重放高影响决定

**当前S1源码观察**：`LifestyleController::load`读到本地`pending`后直接调用`retry()`，保留UUID/CAS仍不能替代“先查真实结果”的O09要求。

**实施目标**：
- 对待处理命令在重新登录、重启、断网恢复与读到历史草稿时，先在**当前身份且有权**条件下只读核查原命令是否已生效；在结果未知时保持UNKNOWN+安全返回，不默认再次写入。
- 仅当有可信权威事实证明尚未提交，并且身份/版本/权限及安全幂等条件允许时，才让用户明确选择安全重试；任何`replay`不得默认自动发送。
- 检查阶段A范围内相关高影响写入调用（Lifestyle、提案/Connection、Messaging Consent、形象发布/撤回等）有无同类UNKNOWN自动重放；修复确证的共同模式而非毫无范围地改整个APP。
- UI应区分“服务端已确认”“本机待确认”“无法确认”，不假成功或假失败；本地未发出的合法草稿可以安全保留，不能污染其它账号会话。

**未来验收最小AC**：
- `A3-AC1` 断网/超时/丢回包、待处理命令与重新登录：无自动高影响重发；当前有权且真实查询有结果才准确显示已生效/未生效。
- `A3-AC2` 结果依然UNKNOWN，维持UNKNOWN并安全退出；当前账号/业务版本变更时拒绝旧命令。
- `A3-AC3` 同一请求键/幂等键与CAS仍起保护作用，但测试覆盖“已成功但丢回包”与“真实未提交”的不同路径；不凭客户端动画判定成功。
- `A3-AC4` 不影响S02已接受的“只有保存成功才自动下一题”；失败/未知仍留在当前题。
