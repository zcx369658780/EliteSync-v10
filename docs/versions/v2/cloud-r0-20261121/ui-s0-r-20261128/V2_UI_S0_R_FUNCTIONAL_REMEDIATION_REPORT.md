## R01｜展示资料草稿保存

原 APK 在新建隔离账号中填写昵称与城市，滑离表单再返回后点保存。界面先有输入，随后请求实际携带 `display_name: null` 与 `city: null`，HTTP 200 的 v1 响应和 MariaDB v1 均为空。离屏组件销毁时，它原本是自动释放草稿状态的唯一订阅者。回滚后表单从空值重建，保存按钮据此构造完整的 PUT。Flutter 回归测试使草稿卡真实离开视口后再回滚，在原版复现字段为空。

修复由展示页面持有当前账号草稿状态，表单组件重建时从编辑状态恢复输入。原 DTO 原样发送当前全量草稿，服务端验证、版本检查、名下读写与权限复用逻辑沿既有合同。请求缺少字段仍按现有完整替换接口处理。界面会发出字段，空值或明确清空序列化为 null；只修改昵称时完整请求带上未改城市。具名城市复用经过用途判定，独立手填字段由展示草稿表管理，基础资料走独立权威字段。

- 新 APK 重跑同一滚动路径。请求、200 回执和重进均保留昵称、城市，冷启动再次读取 v1。
- 本机代理一次 503 后保留尚未保存的编辑。重试送出新昵称与原城市并读回 v2。称为 503 的是代理注入，不是 Laravel 持久化失败。
- 显式清空城市，PUT 携带 null。重进及 MariaDB 确认 v3 新昵称仍在、城市为空、审核 `not_submitted`，零已提交审核与零发布。基础资料未被替换。
- 从该账号退出并用另一独立账号登录，实际页面和数据库只显示该账号私有草稿。原候选快照行为另见 R03。

## R02｜聊天附件能力与失败恢复

原 UI-S0 仅文字环境的上传 HTTP 200 与挂载 422 是两次独立请求。现有服务端仅文字限制在挂载时生效，App 原先凭聊天可写启用选择器；收到确定拒绝后，刷新从加密草稿重建未确认消息。修复让消息读取投影提供当前会话附件能力，Flutter 在选择前使用，并在从系统选择器返回时与当前 room_key 一起再核。读取投影和挂载沿用同一环境能力源，服务端仍逐项判断权限和资产归属、可用状态。旧读回包缺该新增字段时沿旧客户端兼容路径，仍须经过现行发送鉴权。

| 情形 | 结果 |
| --- | --- |
| 当前仅文字 | App 呈现准确说明，图片、短视频和语音留言入口禁用。实点图片未打开选择器，期间零媒体上传，文字实际持久化。 |
| 明确 422 | 合法附件环境真实选择并上传图片，代理按单次计划拒绝挂载。页面给出拒绝原因并保存取消入口，刷新后可取消，原文字继续提交成功。已上传未挂载对象留存供既有只读审计。 |
| 结果未知 | 真实 Laravel 图片消息 POST 200 后由回环代理断开响应。App 按原消息编号核对，已读回提交时没有再写一次；独立 HTTP 同一消息键与资产 ID 再提交得到同一回执和 `idempotent_replay=true`。在这次未知结果路径中，新增图片消息与附件挂载各一条。 |
| 当前读权和账号 | 发送端刷新与冷启动重入，接收端换入另一账号后读取图片。撤回 Messaging Consent 后独立 HTTP 对话与媒体读回拒绝，App 刷新无旧图。同一候选另从发件账号切至同库第三个无授权账号，消息列表无旧会话，其直接读取也返回 404。未挂载资产按原留存。 |

本轮服务端已收到并确认的终态拒绝可取消。网络中断仍保留原上传或已挂载动作对应的资产身份和消息幂等键。响应丢失时第一次自动化点击与自动刷新重排撞在一起，记录的点击落在旧坐标；稳定后下一次点击确认成功，期间没有第二次 App POST。图片选择器需要 Done，审计脚本首次遗漏产生的探针超时与服务时延分列。两次真实上传形成两个资产，其中一个被终态拒绝后保留为未挂载对象。原安全读权、独立同意、Block 和媒体留存规则继续适用。

## R03｜授权候选、版本与独立决定

首轮由两个虚构账号完成匹配准备、TEST_ONLY 签发和现行好友流程，各自通过私有草稿、具名提交、合成运营审核及本人正式确认发布，随后按管理员请求、执行和揭晓产生绑定。草稿专用内部审核命令只更新草稿，首次尝试发布被 409 拒绝；重做当前内容版本后，经与 Web 管理共用且检查管理员身份的审核服务批准具名提交，随后调用本人发布入口成功。没有直接写候选绑定或发布记录。

- 两端实际进入候选详情并显示各自有权看的正文。A 接受后看到等待 B。B 独立确认后见双方接受，HTTP 显示 `MUTUALLY_ACCEPTED`。接受后聊天权限仍拒绝；双方分别完成 Connection 和 Messaging Consent 后才开放。
- 候选投影仅包含公共编号、摘要、兴趣标签、生活线索和发布版本。未包含展示草稿其余字段、出生资料、精确坐标和身份凭证。
- A 新发布 v2，已存在旧候选在 B 界面刷新后仍是 v1。B 失去好友受众后，HTTP 和 App 隐藏旧正文，独立聊天授权仍按原规则判断。
- 第二轮使用已具备条件的独立合成查看者，关闭第一轮后经由现有流程再执行和揭晓，独立 HTTP 读到 A 的 v2。该候选明确拒绝后正文投影为空。MariaDB 旧轮绑定为 v1/v1，新轮绑定为 v1/v2，三名虚构账号只有 TEST_ONLY 签发。

运行锚点为 `R03A-01-candidate`、`R03A-03-awaiting-other`、`R03B-03-mutual`、`R03V-01-v1-after-republish`、`R03V-02-permission-lost`。

## R04｜协议和注册密码

已核对当前 Git 树、登录／注册控件、RC-E 证据和 Owner 决策资料。登录与注册的协议控件均未配置可打开的回调。当前树可定位的是通用文档展示控件；没有定位到适用于这轮的 Owner 已接受协议原文、来源和版本。登录、注册现明确表示当前版本未提供可核实的文本，协议按钮仍禁用，同意框默认不选。打开正文及返回后保留字段待可用文本再测。应用既有本地选择与注册服务端门禁沿原合同。真实法律协议和注册可信离线 T0 各按原记录。

注册改为“至少 8 个字符，须包含字母和数字”，输入不合规则时显示改正说明。Flutter 和 Laravel 都以字符数与 Unicode 字母、数字类别判断。登录仅移除注册规则提示，旧账号登录校验沿用。模拟器验证无数字的八字符与七字符不可提交，合法八字符可完成注册，回到主界面。独立 HTTP 的七字符、纯字母和纯数字均 422，合法八字符和九字符均 201。

运行锚点为 `R04-01-login`、`R04-02-missing-number`、`R04-03-too-short`、`R04-04-boundary-enabled`、`R04-05-registered`。
