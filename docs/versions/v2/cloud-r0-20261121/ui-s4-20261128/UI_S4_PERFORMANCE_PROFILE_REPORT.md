# EliteSync V2｜UI-S4 Flutter Profile 性能取证

## 候选、模式与环境

- UI-S4 验收包使用 `com.elitesync.v2uis4qa / 1011818`，Android Debug host 装载 Flutter release AAR，属于其他验收矩阵的唯一运行包。
- 性能专用包 `com.elitesync.v2uis4profile / 1011818`，实际 Android Profile variant 装载 Flutter Profile AAR。APK SHA-256 为 `4695705ffac3bcc154def21cf64222f5e0a77f328ac62838e79facb4cb4944d7`。Flutter 源码固定 `0ca97a15c35e9730a3c1c68a03fbdc5c09afd0f9`，宿主副本调整包名并启用 Profile variant。Dart VM service 在隔离模拟器启动后以本机转发实际读取五份时间线。
- 使用同一台 Android 模拟器 `5592`，1080×2400、420 dpi、60 Hz、字体 1.0×、浅色。设备为 x86_64，APK 内 ARM64 通过 native bridge 执行。固定虚构账号、已保存 v2 三盘和同一个隔离社区夹具。进程冷启保留磁盘数据及登录状态，返回前台保留进程，五次路线连续执行，图片、系统页缓存和编译缓存未逐次清空。
- 五次路线均覆盖首页进入三盘、紫微和西洋切换、西洋图形标签、返回首页、进入好友动态、三个滑动手势及返回。Profile 时间线以进入首页后清空计时，汇总路线上实际发出的 Dart 帧及引擎绘制事件。原始日志留本机。

首趟出现 292.684 ms 绘制异常，原样保留。超显示周期的事件计数用于定位长帧；实际丢帧率、GPU 完成时间和用户感知的加载延迟仍需独立量测。页面重建、首次图片与背景加载以及单独星盘标签的因果切分尚无逐阶段时间标记。首页首帧、确认的热启动首帧、图片冷热缓存、连续翻页产生的卡顿以及原 UI-S3-R 同 Profile 基线保持待证。

UI-S3-R 的既有同设备 Android 宿主单次冷启动为 2,404 ms、路线后 PSS 377,918 KiB。构建模式、样本数、路径与采集方式不同，保留为历史信息。现阶段性能出口为 `PARTIAL`，项目尚无正式性能预算。
