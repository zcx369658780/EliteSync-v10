## 二、普通聊天与已读

### 2.1 同一真实会话合同

核对本候选可达的会话列表、聊天、联系人及通知入口，使其沿同一当前会话身份和真实 API/数据库合同工作。复用当前 Live 主链；无须删除所有历史页面或重构全 APP。另一构建路径的运行结果不能代替本候选。

文字、图片、短视频的选择、发送、上传/处理失败、取消和重试应可操作；失败保留当前合法账号和会话的草稿，切号、撤权及明确取消按既有私密资源规则处理。媒体 ready/failed 与消息提交状态分开，上传完成不等于发送完成。分页、返回会话和重登读回维持顺序与去重。

发送状态以事实为准：正在发送、结果未确认、服务器已持久化、确定失败、对方实际已读。超时或响应丢失时保留原逻辑发送和不可变载荷，按同一 `client_message_id` 重试，不换新编号重复发送。没有独立接收设备回执时，不增加“已送达”承诺；HTTP 200、WS 写入或 Push accepted 不能冒充送达/已读。同号重试只产生一条消息；新增引用或语音业务字段进入服务端指纹及前端稳定重试载荷。

### 2.2 已读和未读默认规则

1. GET 历史、列表预取、搜索及搜索预览均不产生消息已读。本人发送消息也不清除此前尚未呈现的入站未读。
2. 当前账号处于当前前台会话，成功呈现相应入站消息后，显式 ACK 这些消息 ID。复用现有单条 ACK 或有限批量；不要求像素可见度、停留时长统计或复杂阅读追踪。
3. 未读以本人入站消息 `is_read=false` 为事实；旧 `last_read_message_id` 可保留为兼容辅助，不能跨间隙清读。消息已读时间保留首次 ACK；重复 ACK 幂等。
4. 每次 ACK 复核接收人、会话和当前读取权限。混入他人或跨会话 ID 不得改动无权行；异步旧账号响应不更新新账号页面。
5. 历史曾被错误清读的行没有可靠事实可还原，不全量置未读、不编造历史阅读时间；用新增虚构消息证明新语义。

## 三、当前会话搜索与引用回复

### 3.1 搜索

仅搜索当前有权会话的文字正文，不做全站、跨账号、图片识别、语音转写或永久搜索缓存。默认非空关键词为 1–100 个字符，按文字子串比较；用户清空查询时不扫描历史。具体大小写归一实现保持前后一致并记录。

沿现有服务器静态加密合同，在授权后临时解密比较。每次最多扫描 200 条、返回 20 个命中；以实际最后扫描位置推进稳定 cursor，提前到 20 个命中时不能跳过尚未扫描的行。查询、账号或会话改变时重置 cursor，每页重新复核当前权限。界面可继续搜索更早消息；尚未扫完的零命中不得表述为“全部历史无结果”。不对密文做 SQL LIKE，不新建明文索引、正文副本或正文日志，不宣称现有系统是端到端加密。

### 3.2 引用回复

允许引用当前会话中当前有权的原消息，提交同会话原消息 ID，服务器按当前权限形成有限摘要。文字摘要限长，媒体先用类型标签，不通过引用直接暴露私密 URL；原消息不可用或当前失权时显示不可用占位，不用旧摘要继续泄露内容。

引用 ID 属于消息语义，必须进入幂等指纹、不可变重试载荷及现有加密待确认草稿。禁止跨会话引用。可复用已加载历史定位，不要求新增任意历史定位 API、线程系统、转发、撤回或删除体系。

搜索、引用和未读遵守既有当前 CN/MC、拉黑、账号 token、资料受众和 15/30 天加密离线只读合同；离线留存不授予在线搜索、发送或媒体读取权限。本版不重构安全框架。

## 五、现有音视频通话、SFU 与有限恢复

本版的通信功能 PASS 必须包含当前 SFU 正常启动、普通双端发起与接听、实际媒体收发和正常结束，并完成一次具名可恢复故障后的新合法通话接通。复用已有语音入口及视频能力做最短检查，可共用一次带音频的视频通话证据；连接状态本身不能代替实际媒体收发。受控音源/模拟器证明范围和实机听感分别列明。

开工按当前配置、实际端点及当前相关日志检查 SFU exited 的直接原因并修复影响正常使用的缺陷。已有普通 API 与 authority 独立工作池、有限关联诊断可继续复用；仅在具体新线索下使用诊断，不循环等待旧非注入超时、不无限压力测试、不盲增超时或禁用独立 watchdog/撤权检查。普通服务启动和范围内修复沿现有工程授权，无需恢复旧执行器或提升系统/数据库权限。

故障前后的旧 call ID、已结束或已撤权会话不能复活。短暂重连需重新验证当前授权；明确失败后给出可理解状态，释放媒体并允许用户重新发起新合法通话。仅得到安全退出、Room0 或 SFU exited，不能判“通信可用”。

在本版本来需要的一次具名撤权停媒验证中，沿既有 5 秒停媒合同保留授权提交区间、双方原生采集停止观测、时钟/分辨率和保守余量，并采集提交区间上端后完整至少 5 秒尾窗。旧 call51 约 3.968 秒尾窗及条件复算保持原身份；新证据不反向修改旧记录。无须重做旧 25 分钟观察或全套硬件矩阵，手机不使用。

将两项结论分列：**当前功能可用/恢复结果**与**历史非注入超时精确根因**。当前功能达标时，历史根因仍可为 UNKNOWN；有限不复现或注入恢复不等于查明旧原因。若本轮当前 SFU 仍不可用，AC18-04 必须 PARTIAL，明确具体阻碍和最小下一步；其余 AC 继续完成后一起交付，不把整版停在无新信息的排查上。

复用现有持久通知中心、分页、本人未读/已读、偏好、账号隔离及测试投递合同。有限事件表如下，具体 kind 名称由实现选择，但来源与接收方不能含糊。

| 事件 | 生产与接收方 | 当前合法目标及分类 |
|---|---|---|
| 普通消息 | 新消息实际提交后提醒接收人；包括文字、图片、短视频、语音。附件上传、失败或幂等重放不另外产通知。 | 当前会话；`message`。 |
| 通话 | 保留有效来电；对参与人有意义的未接、拒接、结束等终态按一次状态事件提醒。 | 活跃来电可进入当前来电；终态只读本人当前有权结果，不能再次接听旧 call；`rtc`。 |
| 匹配/提案 | 保留本轮揭晓；对方真实接受、拒绝或撤回后提醒另一方当前进展。无候选仍是轮次结果。 | 本人当前慢约进程/合法历史，不能借通知获得 Showcase 或 CN/MC；`match`。 |

| 本人资料审核 | 实际 Web 处理 approved/rejected/needs_revision 等处理结果后提醒资料本人；草稿保存不产提醒。 | 本人当前审核/提交状态；显式映射 `system`。通过不自动发布，旧通知不能覆盖新版审核。 |

### 持久化、打开和未读

- 业务事件与通知在同一实际业务事务内保存，提交后才可见；失败事务无通知。同一稳定来源事件、接收人、生命周期/版本只产生一条，重试、并发与重启不依赖五分钟文案窗口去重。复用最小数据库约束/现有服务，不建通用事件总线；不回放全部历史事件、不清空旧记录。
- 入口显示安全类别与动作，不在通知预览暴露私聊正文、音频、对方敏感资料或审核细节。通知 ID 只是定位，点击先按本人重读通知，再读取当前合法目标；受控路由和业务 ID 不能变成任意 URL 或越权跳转。
- 区分“本人可读结果”与“仍可操作的请求”。过期、撤回、结束或失权时提供适当失效/当前状态，合法本人历史可只读；旧提醒不能执行决定、恢复权限或复活旧通话。切号/注销及权限 epoch 变化后丢弃旧异步响应。
- 通知已读、聊天已读和外部投递三者独立。通知列表预取不标已读；明确单条打开/标读或全部已读只更改本人的通知记录，不接受提案或建立同意。通知点击或标读本身不写聊天已读；若目标聊天页随后在前台实际呈现入站消息，仍按第 2.2 节正常 ACK。
- 进入中心、返回前台、处理通知及相关业务成功后刷新当前服务器记录和未读；可复用 WS 作刷新提示，不以 WS 本身为持久事实。保留失败重试和分页。

### 偏好与 Push

沿现有语义并保留账号设置：分类关闭过滤相应站内列表/未读和外部测试尝试，不删除业务事件或通知记录；静默只停止外部提醒，站内记录仍可用。新增 kind 必须显式归类，不靠未知 kind 默默落入默认类别。系统通知权限拒绝不阻断站内通知、聊天和其他业务，只在用户主动设置时请求权限。

没有真实供应商时保持 `REAL_PUSH_PROVIDER_PENDING`。复用现有 local/testing `test_only` 设备绑定、代际、注销隔离、偏好抑制和最小 envelope；其 TEST_ONLY/SUPPRESSED 回执不是正式注册或真实送达。外部载荷维持 notification_id 与通用文本，不包含消息正文、音频或私密链接。真实锁屏/后台远端送达保持 PENDING，不以公司、内测或购买供应商作为本版前置。
