## 3. 六项验收标准

### AC13-01 R1源码集成与最终候选身份
以R1源码`3e0e75758acf81e1ea754f739c9687226fbfcaff`为APP输入，先核对versionCode占用，建议候选`10.1.13-dev / 1011301`，如已占用顺延。沿用包名`com.elitesync.v1015dev`、签名、ABI和既有数据。构建并安装Debug候选，核验APK SHA256、签名、包名、版本、安装后哈希及源码身份。实机候选至少验证MBTI结果/历史显示用户可读名称、反馈历史/处理时间显示本地化日期及“本地时间”。1011204只作为旧基线，不可冒充R1候选。

### AC13-02 实际Android无障碍/TalkBack
在本机Android模拟器使用系统内置TalkBack/屏幕阅读器进行真实服务会话（不是Widget语义树代证）。覆盖四个底栏入口、设置/反馈表单、聊天输入与发送、MBTI结果/历史、匹配未就绪状态。核对焦点顺序、控件名称/角色/状态、选中态、动作提示、动态内容反馈和返回。另检查至少一个200%文字场景。不得操作Owner手机，不接第三方付费无障碍服务；模拟器系统组件不可用则如实NOT_RUN并说明原因。

### AC13-03 导航、深链与通知入口
有限走查四个主入口、当前分支重选、系统返回、Discover兼容重定向，以及代码中已经存在的关键深链/通知目标。核验登录/未登录、目标不可用、重复打开与返回栈，不创建不存在的通知或伪造真实Push。真实Push仍按`REAL_PUSH_PROVIDER_PENDING`记录。只验证实际已实现入口，不要求全量枚举所有历史路径。

### AC13-04 最终APP受控故障恢复
针对APP最终候选，对反馈提交和文字消息发送各选至少一个有意义的受控失败场景，覆盖服务端已处理但客户端未收到响应/结果未知的恢复语义。核验原request key/不可变payload重试、不会重复创建或重复发送、输入保留、明确拒绝与暂时不可用的区别。可使用本机受控代理/测试拦截器或等效隔离机制；测试控制不得进入发布构建，不得破坏开发库数据。若当前架构无法安全注入，记录NOT_RUN及原因，不以Widget假响应冒充真实APP故障注入。

### AC13-05 API/数据库重启后持久化
只使用本机虚构开发数据，分别验证API进程重启及MariaDB开发容器重启后的登录态/业务读回边界。至少选反馈记录、MBTI历史、文字消息三类已持久数据，核验重启前后ID、revision/状态和归属一致。API与DB重启分开记账；启动窗口的连接错误保留，服务就绪后再做有界重读。不得删除卷、重建数据库、运行迁移或改变生产数据。若DB重启风险超出既有开发服务授权，停止该动作并记录NOT_RUN，其余AC继续。

### AC13-06 有限跨模块联合回归与证据闭环
从同一最终候选选择有限关键旅程：登录/切号隔离、我的/设置/反馈回流、消息文字发送与会话状态、MBTI结果与历史、进展/匹配未就绪及一个社交入口。至少覆盖正常状态和一个非成功状态。核对APP/API/DB/Web分别使用真实产品链还是受控测试；不得用Widget、SQLite、旧截图代替普通真实业务证据。整理本版源码、APK、设备、测试、资源与NOT_RUN/UNKNOWN清单。

3. 安全同步任务文件并提供可核验LOCAL_DOCS_SYNCED回执；GitHub发布不等于本地同步。
4. 先把R1源码纳入实际候选，再执行AC13-01/02/03；受控故障注入与重启验证分别执行，避免多个不确定变量叠加。

6. 真实APP/API/DB/Web链、Widget/单元测试、受控代理故障和模拟器屏幕阅读器分别记账。
7. 候选建议1011301，先核占用；如需修复源码，记录修复提交并确保最终APK绑定最终源码。
8. 集中交付实施报告、manifest、去敏证据、最终源码/APK身份、重启前后持久化读回、TalkBack路径和资源快照。
