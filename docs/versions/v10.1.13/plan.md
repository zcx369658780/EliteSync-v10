# v10.1.13计划：全局集成与关键旅程可靠性收口

日期：2026-11-15（北京时间）。状态：TASK_ISSUED。

## 1. 为什么需要本版

v10.1.12已完成集中UI与信息结构收口，顾问接受其六项AC具名代表性范围，R1-01文案与Web证据修正已关闭。但R1源码未重新构建APK，1011204仍是原源码候选；实际TalkBack、最终APP故障注入、API/DB重启等仍为NOT_RUN。下一步不应再做一轮视觉改版，而应将R1源码纳入实际候选，并补齐少量对真实可用性有决定意义的系统级证据。

本版是质量收口，不是新业务功能，不代表正式发布准备全部完成。

## 2. 六个工作流

### A. R1源码进入最终候选
以v10.1.12 R1源码为APP基线，核versionCode，构建/签名/安装新候选。实测MBTI题型名称与反馈本地时间，确保源码修正真实出现在安装包中。保存APK哈希、签名、包名、版本、设备和安装数据身份。

### B. 真实屏幕阅读器
使用Android系统内置TalkBack在模拟器中实际开启并完成用户路径，不以Semantics tree或Widget测试替代。优先覆盖底栏、表单、消息、测评和状态说明。发现焦点陷阱、重复朗读、无标签操作或不可达按钮时做最小修复。

### C. 导航与外部入口
验证四主入口、系统返回、兼容路由、已实现的深链/通知入口。重点是冷启动/登录态变化时目标页面可理解且返回路径可预测。Push provider未配置不影响本版对现有本地/站内入口的有限验证。

### D. 结果未知与失败恢复
从真实APP入口对反馈与文字消息进行隔离受控注入。重点验证服务器已处理但响应丢失、原幂等标识重试、不得重复业务写入；与明确拒绝、服务暂不可用区分。测试代理与钩子只用于本机隔离验证，不进入正式构建。

### E. API/DB重启持久化
使用现有虚构开发数据库。分别重启API和MariaDB容器，核验原有反馈、MBTI和消息持久记录。保留启动就绪窗口错误，待服务稳定后有界重读。不得重建卷、迁移或改变业务数据模型。

### F. 联合回归
选取有限关键旅程，以同一候选为主线，覆盖账户隔离、反馈往返、聊天、MBTI、匹配未就绪与一个社交入口。验证实际权限与服务端状态，不扩展到全设备、全关系状态、所有图表或历史所有AC。

## 3. 成功定义

- 安装候选确实包含v10.1.12 R1代码，1011204与新候选身份不混淆。
- 主要页面在真实TalkBack会话中可被理解和操作；无法完成的部分有明确证据边界。
- 已实现导航入口无明显死路、重复栈或错误目标。
- 至少对反馈与消息两条APP真实链完成有界结果未知恢复，或明确记录受控条件限制。
- API/DB重启后已选持久业务记录保持一致，或明确记录无法执行的原因。
- 有限联合回归证明集中UI/R1修改未破坏关键既有业务。

## 4. 明确不做

- 不做新的产品功能、视觉重设计、后端业务重构或数据库迁移。
- 不接真实Push、短信、实人核验或付费供应商。
- 不操作Owner手机，不使用真实用户/生产数据。
- 不做RTC硬件、SFU全面诊断、算法独立精度或全社交/排盘矩阵。
- 不做main集成、正式发布、公司/内测/运营/收费。

## 5. 证据纪律

真实APP链、API/DB读回、Widget/单元、PHP隔离测试、TalkBack实际会话、受控故障注入和重启持久性分别记录。每条证据绑定源码、候选、设备、账号类型和运行时间。不得用旧1011204截图声称验证R1源码，不得将受控测试说成真实外部送达。所有NOT_RUN/UNKNOWN/UNVERIFIED保留。
