## 4. 好友与请求：本版开发默认合同

### 4.1 可达场景与防骚扰

新请求接收总开关默认关闭；用户主动开启后也仅接受以下当前有效上下文：服务端认可的指定匹配候选、已成立的双向好友，或接收方主动生成并交出的定向邀请凭据。好友申请可通过该凭据建立独立于恋爱匹配的社交关系，不要求先参加婚恋。不得增加全站用户目录、模糊搜手机号或按递增ID枚举用户。拒绝场景不泄露对方是否拉黑或存在账号。

定向邀请凭据应不可猜测、可撤销，默认24小时失效，兑换后绑定指定申请者及用途；不把原始数据库ID当授权。它只建立可请求上下文，不自动建立好友/CN/MC。请求关闭、任一方拉黑/禁用/注销、凭据失效须在提交与接受时均重验。

本版开发默认：每发送方滚动24小时最多向5个不同账号发起新好友/消息请求，两种用途合计；一对账号同时最多一个未决请求。未决7天失效；撤回或自然到期后同方向重试至少间隔24小时。被明确拒绝后发送方不能自行重新请求，只有接收方主动发起新邀请才可建立新生命周期；解除拉黑不构成邀请。重复重放使用同一幂等键不能新增记录或再次通知；拒绝、过期和取消不是违规或信誉分。

请求正文仅为固定用途选择和最小身份卡，本版不开放自由文本、图片、链接、语音、视频、附件或来电。参数放有版本的配置，测试可用隔离时钟，不改系统时间、不减少生产限制以追测试。上述额度是开发设计值，不是行业事实或未来商业政策。

### 4.2 好友、CN与MC分别成立

好友申请与接受形成独立双向好友事实。交叉申请不自动接受；终态不可单方复活，新申请使用新生命周期ID。

好友接受只授予被选择的好友资料/动态受众，不建立Connection、MC、Conversation或正式恋爱。用户之后可以分别发起Connection，两人明确确认后再分别确认Messaging Consent。消息请求被接受只表示愿意进入这个后续流程，不替代双方授权。

为非恋爱好友复用现有Connection业务服务及同一消息能力判定，允许具名friendship作为可申请来源；不得制造一套绕过原CN/MC的“好友直聊”。任何actor、peer、关系状态或is_admin/verified字段都由服务端当前事实确定。

解除好友只撤销好友专属展示，不暗中撤销仍独立有效的CN/MC；界面同时提供明确的停止交流或拉黑选项并解释区别。暂停/关闭CN必须按原合同限制新消息；恢复普通登录不复活曾撤销授权。

## 5. 资料权限、隐私中心与可信身份

建立单一授权策略消费路径，按数据用途而非一张关系等级表决定访问。默认拒绝、任一方向block/禁用/注销优先于所有分享；未知关系、缺失策略、旧缓存或客户端自报权限不能提供访问。

本版字段受众冻结如下：
- 有合法入口的陌生人：只见应用公开ID与头像，不获得可全局枚举的目录。
- 动态：作者可选择仅自己/双向好友；新发布明确显示受众。旧动态缺少受众时按仅作者处理并允许本人重新选择，不删除原文、不自动转公开。实际覆盖现有状态发布/读取/点赞/作者删除及已有媒体入口，不将未来评论/群组范围混入。
- 喜好、生日、履历、星座等更深资料：默认仅自己。本人可管理未来恋爱分享意向，但真实RELATIONSHIP_SHARED访问必须由服务端已成立的正式恋爱与字段许可共同证明；本版不新增恋爱建立功能，也不提供可被客户端/普通管理员设置为真实核验或恋爱的开关。尚无真实关系时UI明确暂不可向恋爱对象分享，不能伪造对端可见成功。
- 指定匹配Showcase：沿用已批准的匹配用途及本人选择，显式候选范围授权不是全球Profile可见权，不泄露原始问卷/Matching Inputs。不删除已接受Showcase合同来换取表面安全；遇到字段冲突按最小披露记录具体迁移。
- 证件、账号认证材料、精确出生时地、原始私有星盘输入、私聊、Safety/举报/拉黑/征信数据不因好友/付费/关系字段自动公开。本人正常私有访问保持。

实际实现GET/保存/撤回/预览并持久化；本人预览可模拟受众，但普通peer查询不得接受as_friend/as_partner等客户端断言。策略修改、解除好友、拉黑和删除账号须使投影、派生摘要、通知、列表计数、媒体预览及缓存同时失效；晚到响应不能覆盖新的用户/权限代际。

认证仅建立最小可信状态读取适配，未配置provider返回NOT_CONFIGURED/NOT_VERIFIED；运营verify_status不等于实人认证。合成回执只能在双重隔离的测试环境和明确数据集验证，不能在普通用户界面冒真实认证。

## 6. 拉黑、会话隐藏与共享历史

拉黑使用现有共享安全服务并补齐实际遗漏：任一方向存在有效block时，双方新资料/动态访问、请求/重加、普通消息收发、通知内容、媒体取用及RTC入房均不得成功。有正在运行的WS/RTC须执行撤权传播；沿用已批准媒体退出目标，受控测试中5秒内停止有效媒体，新join立即拒绝，旧JWT不能复活。不能只隐藏按钮或等旧token自然过期。

该动作撤销相关好友及联系授权，关闭未决邀请；保留具名内部审计，不将block计为举报/过错。只有拉黑者可解除自己的block；对向block仍有效时不开放。解黑不恢复好友、CN、MC或关系。

隐藏会话是本人持久化视图状态：不影响对方列表，不删除服务器消息，不改变任何授权。隐藏后，只有真正通过当前授权且序号晚于隐藏位置的新消息才可让会话重新出现；旧事件重放、拒收消息或已撤权来信不得唤回。用户可在仍有历史读权时主动找回隐藏会话。

共享历史不等于新交流权。普通解除好友/隐藏不删除既有共享消息；非block场景的历史只读沿用当前已接受合同，不扩权。block/账号禁止状态下不可借历史接口取回对方资料或媒体；本人安全申诉通过既有限权路径处理。已下载或被对方截图的内容不能承诺远程抹除；本APP受控缓存应在已知撤权时清理/屏蔽，离线不冒称已知服务器最新授权。本版新好友资料/请求/隐私页面离线不执行授权变更，不借此重做全套15/30天离线产品。

## 7. 登出与设备会话

必须实现真实服务端当前会话登出、指定本人设备会话撤销及退出全部设备。设备会话是服务器生成的登录/刷新凭据家族，不信任客户端自报device_id就能撤销他人会话；列表不返回token、私钥、精确网络或硬件标识。

在线登出完成后，该家族旧access/refresh凭据及持续WS/RTC授权不再有效；刷新竞态不得生成可用新家族。只撤销一个会话时其他有效会话按原授权正常使用；退出全部/账号禁用或注销则覆盖全部会话。清除本机缓存、切账号与后台晚响应必须同一代际处理。

离线退出立即清本机凭据与显示，但明确服务端撤销尚未确认，恢复网络后按安全流程完成；不能将本地清缓存标记为服务端退出成功。新登录不会恢复之前REVOKED的CN/MC。普通注销和会话撤销不能修改staff角色或别人账号。

## 8. 账号注销：开发合同与真实数据边界

实现正常普通用户角色可发起的注销流程，不能再以手机号90前缀、姓名Smoke前缀判断哪些账号可以删除。运行环境与测试数据归属是独立执行门禁，不是普通产品角色。

本版开发流程：展示注销影响/保留范围 → 当前密码或等价近期认证 → 二次明确确认 → 持久化DELETION_PENDING并立即撤销所有凭据与联系/展示能力 → 后台可恢复重试的数据处理 → 返回如实结果。提交后普通业务登录不得恢复账号；处理中只允许目的受限的本人回执查询，不以此恢复普通token。请求ID、幂等、并发及失败重试均须实际生效。

实际破坏性处理只允许本版初始化时显式登记的虚构数据集成员，包含非管理员普通角色、普通格式手机号/姓名及相关合成内容；登记使用服务端身份和数据集来源，不接受客户端is_synthetic或命名前缀。旧真实库、原备份、未登记管理员和任何其他账号不操作。生产/未知环境该数据处理适配默认关闭，保持PRODUCTION_RETENTION_POLICY_PENDING，不冒称真实用户全量注销政策已完成。

在这些演练对象上：取消发布与新联系、撤销grant与会话；删除/最小化本人独占的资料、原始私有计算输入/结果与受控缓存；只删除无他人引用、非审计/证据保留对象的合成附件。账号可保留不含个人资料的不可复用墓碑以维持共享记录引用。共享会话、对方独立持有记录、必要审计/争议和备份不批量物理销毁，分别列明保留类别、用途与当前访问规则；对端只显示账号不可用，不返回原头像/资料。不能借注销另一个账号清掉其本人消息或独立处罚。

结果区分ACCOUNT_CLOSED、PRIVATE_DATA_ERASURE_COMPLETE、RETAINED_SHARED_OR_AUDIT_RECORDS、FAILED_RETRYABLE，不用“所有数据已彻底删除”掩盖保留项。这项开发验收要求实际的普通角色流程与合成数据处理，不接受仅弹toast、改前缀条件或永远没有执行者的假按钮；也不要求现在对历史真实数据确定并执行法定保留期。
