## 三 功能范围与默认取舍

### F16-01 统一本旅程的真实入口

选定资料/展示旅程的唯一有效APP入口和真实API适配，接现行Laravel鉴权与持久MariaDB。正常开发候选不能落入本地示范连接、受控成功响应或只在内存变化的资料页。

只调整本版旅程需要的路由、配置、consumer和后台；其他模块沿用当前真实实现，不把本版扩展成全APP重构。保留已有聊天、慢约、好友、搭子、活动、正式关系和星盘入口。发现其他两套路径时登记到所属后续版本。

最小修订 services/backend-laravel/README.md：写清当前有效开发入口、业务启动方式与持久数据位置的说明，标明旧Laravel11/MySQL8及旧按ID配对命令为历史，不启用已退役的匹配旁路。私有具体配置不入库。

### F16-02 本人资料与自愿展示

复用现有昵称、城市、头像、关系目标、自我介绍、兴趣、生活线索和开场话题。明确本人编辑与对外展示快照的区别，已发布内容不能直接引用未提交草稿。

本版采用以下最小新增范围，由顾问按版本规划授权确定：

- 自愿展示照片0至6张，复用当前私有图片上传/处理/存储与鉴权。提供新增、排序、移除及清楚状态；不做滤镜、视频主页或公开原图仓库。
- 本人能够查看当前草稿、待处理提交、处理反馈及已发布版，并预览其选择的展示内容。
- 现有字段按用途分别映射；不自动把旧生日、精确出生时地、深层兴趣/履历或问卷原答迁入新的展示快照。涉及相同主题时，由本人明确重新选择或填写用于Showcase的内容。
- 照片与展示信息只对当前合法、本人选定的认识范围可读，不因此开放全局用户目录。涉及新增字段的实际受众与撤回行为记录在一份简洁字段表。
- 学历、职业、身高、婚育及异地偏好等完整择偶语义留给v10.1.7，不在本版无限扩展资料表。

展示图片的存储对象、归属和读取权限落到服务端。删除/撤回后对新的读取请求执行当前规则，不能承诺擦除对方已经离线另存的内容。沿用现有私有媒体安全处理，不为本版重建整个通信媒体栈。

### F16-03 真实提交 审核 发布与撤回

复用现有Showcase接口和版本控制，补齐正常流程：

草稿保存 → 提交 → 实际Web处理（通过、要求修改或驳回）→ 本人读到反馈 → 修改重提或本人明确发布 → 后续撤回。

审核与发布分开；后台通过不自动替本人发布。管理员处理应绑定被审核的内容版本，私下修改不会复用旧批准暴露新内容。编辑已发布资料时保持旧发布快照与新草稿分离；新版本完成相应处理后再替换，或由本人明确先撤回旧版。过时revision、重复请求与失败不产生假成功或重复副作用。

需要的参与资格前置应接现有真实申请/处理接口。受控资格成功响应和直接改库approved不能充当本版成功链。既有开发资格审核与真人实人认证明确区分；真实身份provider未接入不显示已完成实人核验，也不妨碍普通资料功能。

开发管理员通过已授权的初始化方式具名建立即可，不要求先建立运营组织。初始化身份或既有资格前置如需开发数据，应记录来源和范围，不能代替本版提交、审核和发布操作。

### F16-04 获准对象的资料详情

修通当前动态作者等已有资料入口，使其按服务端当前上下文读取实际发布版；不能继续固定无权占位，也不能改成任意数字ID都可查询。

本版至少贯通好友上下文中的动态作者/已有对象入口，以及本人展示预览。已有有效匹配或联系上下文按既有权限复用；不为本版额外注入TEST_ONLY匹配提案或要求重做整套匹配。

详情应说明当前可见内容，缺少发布版、被撤回、不可访问或网络失败分别显示准确状态。服务端同时保护详情字段与图片资源，客户端隐藏不能代替权限。访问资格失效后的旧卡片/旧链接要重新核验。

### F16-05 相识后功能的最小接口

为以后破冰、约见、共同计划、纪念日等记录最小扩展契约：参与者及合法上下文、用途与所需授权、数据归属、撤回要求、当前不可用状态、未来接入点。

优先使用已有能力注册/服务接口机制。若没有相应机制，只补最小应用层接口定义与简短契约，不建立空业务表、队列或假成功端点，不增加普通用户可点击的未实现入口。本版不实现这些新增业务。已有正式关系生命周期与已有手填双人盘继续保留。
