## 四、六项验收标准

### AC14-01 核心用户旅程盘点与问题分级

从现有功能目录、v10.1.6—v10.1.13报告、当前源码和实际候选建立有限旅程矩阵，至少覆盖：
- 注册/登录/退出；
- 个人资料、准备状态和隐私；
- MBTI/星盘等已有特色工具；
- 匹配候选、解释、确认及等待/无候选状态；
- Match → Connection → Messaging Consent → Conversation独立链；
- 好友、社区动态、收藏/互动、Buddy；
- 现有平台活动入口；
- 账号支持与反馈；
- 正式关系及身份核验未配置边界。

每项标记：当前已接受范围、当前实际入口、真实证据、未覆盖条件、阻断等级P0/P1/P2/P3。不得把历史SRC_ONLY/NOT_RUN自动改为失败，也不得将旧候选证据冒充当前候选。

本版只修复有证据的P0/P1真实阻断问题；P2/P3形成后续清单，不借机重做全部产品。

### AC14-02 社区最小视频动态能力

当前基线只有单图封面动态：APP`StatusSquarePage`使用图片选择器，后端`StatusPostController::store`要求封面media_type为image，卡片仅使用认证图片组件。Owner已明确要求5条视频配文动态用于测试，因此本版授权最小视频动态：

- 每条动态最多一个主媒体，图片/视频二选一；保留现有标题和正文语义。
- 复用现有MediaAsset、私有存储、上传状态、`PrivateVideoValidator`和鉴权读取，不另建媒体服务。
- 当前验证器约束：MP4、H.264、可选AAC，最大25 MiB、最长30秒，不转码；以当前实际配置与服务器校验为准。
- 最小向后兼容数据库迁移，原有图片动态不改变。
- APP选择、上传、发布、播放、暂停、加载/失败反馈；播放必须经过当前用户授权媒体端点。
- SELF/FRIENDS受众、拉黑、账号禁用、作者删除、受众撤回与旧媒体访问限制继续生效。
- 不做多视频、相册、剪辑、滤镜、转码服务、直播、自动播放Feed或短视频推荐。
- 如现有私有视频配置/ffprobe不可用，先检查本机现有免费依赖和配置；不得接新供应商或付费服务，不得假成功。

### AC14-03 社区测试内容库：20图文 + 5视频

使用至少3个虚构测试账号（作者、双向好友查看者、非好友查看者），优先复用现有合成账号；如需标记synthetic，只能使用已有开发专用管理界面/受控流程，不绕过管理审计直接改库。

生成并通过普通APP流程发布：
- 20条图文动态，每条原创标题/配文和1张图片；
- 5条视频动态，每条原创标题/配文和1个短视频；
- 内容覆盖旅行/自然、城市生活、居住环境、阅读学习、饮食、兴趣活动等中性主题；
- 以SELF/FRIENDS测试可见性，不发布到真实公网或生产社区；
- 测试作者、好友、非好友的列表/详情/媒体读取边界，以及分页、作者页、现有点赞/评论/收藏/删除操作；
- 切号、重登、冷启动后验证内容和权限仍正确。

素材许可规则：
1. 优先CC0/公共领域，其次明确允许相应用途的开放许可或官方免费素材许可；
2. 逐素材记录来源页面、直接下载页、作者、许可名称/版本、许可URL、下载日期、SHA256、MIME、大小、视频时长；
3. 不得仅因“可免费下载”就推断有复用权；未知许可、影视/社交平台转载、带水印或未获授权个人肖像不使用；
4. 优先风景、建筑、食物、物件等低风险素材，避免可识别人物、未成年人、商标和敏感内容；
5. 配文原创，不复制素材网站说明或他人社区文案；
6. 媒体二进制放本地Git忽略的测试素材目录，不推送GitHub；GitHub只保存去敏素材清单和测试证据；
7. 测试账号凭据、访问令牌和私有媒体URL不得写入GitHub报告。

不得直接SQL插入动态来冒充普通用户发布。若必须通过API辅助建立账号，内容创建仍须经过正常APP/API业务路径。

### AC14-04 核心旅程P0/P1修复与有限验证

按AC14-01矩阵对关键旅程做具名代表性验证，至少包括：
- 登录/登出/切号与本人数据隔离；
- 资料/隐私保存与读回；
- 匹配未就绪、无候选或资格拒绝的准确反馈；
- Connection与Messaging Consent独立门禁；
- 文字聊天基本收发与失败状态；
- 社区图文/视频发布、媒体播放和受众控制；
- 一个好友/Buddy场景；
- 特色工具已有结果/历史读回。

修复只针对真实P0/P1问题；不改匹配算法、关系状态机、隐私默认受众、消息/RTC协议或身份核验语义。真实身份供应商未接入时，正式身份核验及依赖它的正式关系建立保持不可用/NOT_RUN，不用合成回执伪装真实认证。
