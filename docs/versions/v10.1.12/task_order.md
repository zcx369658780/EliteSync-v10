## 2. 唯一目标

在不重写既有业务逻辑、不改变后端合同和权限边界的前提下，完成EliteSync APP主要旅程的集中UI、信息结构与文案统一，并对必要独立Web管理页面做有限一致性收口。

版本用户出口：同一候选中的主要旅程视觉与交互一致；四个底栏入口职责清楚；信息层级适合普通用户；输入、返回、键盘、大字和辅助访问行为可靠；加载、空态、成功、拒绝、错误、离线、重试等状态表达准确；用户能理解当前状态和下一步。

## 3. 执行顺序

1. 我的 / 设置
2. 消息 / 聊天
3. 首页 / 进展
4. 匹配 / 社交 / 特色工具

每一阶段先盘点现有页面、共享组件和真实导航，选取代表性页面建立统一规则，再扩展到关键页面。避免一次性盲目替换所有页面。

## 4. 六项验收标准

### AC12-01 四入口职责与信息架构
核验并明确首页、进展、消息、我的四个底栏入口的职责、命名、选中态、返回栈、再次点击行为和跨分支返回。兼容路由、深链、通知跳转及Navigator/GoRouter混用不得产生迷失或重复栈。只做有证据支持的必要调整，不改变业务可达性与授权。

### AC12-02 统一视觉基础与共享组件
建立或收敛统一的颜色、字体、字号层级、间距、圆角、表面层级、按钮、输入框、卡片、列表、标签、弹窗、顶部栏、底栏和反馈组件。支持现有明暗主题与用户主题偏好；不为统一而破坏既有设计资产。组件应有明确的禁用、忙碌、错误、焦点和可访问状态。

### AC12-03 我的 / 设置与账号体验
优先统一个人资料、设置、隐私、账号安全、密码、反馈与特色工具入口。普通/高级信息分层；危险操作、权限说明和保存结果清晰；表单验证、键盘、滚动、输入保留、返回和取消行为一致。不得修改已接受的账号安全/隐私后端语义。

### AC12-04 消息 / 聊天体验
统一会话列表、聊天页、消息气泡、附件预览、发送/上传状态、失败重试、空态、离线只读、权限失效、通话入口和返回行为。保留当前正式/恢复构建差异及其既有合同，不得将一个构建的控件行为假定为另一个构建。不得改变消息、媒体、RTC或会话授权语义。

### AC12-05 首页 / 进展 / 匹配 / 社交 / 特色工具
统一首页内容层级、进展状态、匹配/连接入口、好友/搭子/社区、MBTI与星盘工具的页面标题、卡片、状态、说明、表单和结果呈现。普通用户优先看到必要信息，高级参数/解释按需展开。不得改变匹配算法、资格、关系状态、隐私受众或特色工具计算逻辑。

### AC12-06 Web与可访问性及有限联合回归
必要独立Web管理页面与APP共享信息命名、状态语义和基础视觉语言，但保持适合桌面端的布局。覆盖动态文字缩放/大字、系统返回、键盘遮挡与焦点、语义标签/对比度、最小触控区域及关键加载/空/拒绝/错误/离线/重试状态。对代表性主要旅程做有限联合回归，确认UI调整没有破坏真实业务链。

## 5. 范围边界

- 本版是体验与UI收口，不新增大型业务，不重写API/数据库业务模型。
- 发现阻碍正常使用的真实功能缺陷，可在同版修复；必须记录原因、受影响范围和定向验证。
- 不改变账号、资料、头像、展示、隐私、好友、搭子、正式关系、消息、媒体、RTC、通知和安全案卷权限。
- 不新增破冰、约见、共同计划、纪念日业务；这些继续只保留接口。
- 不为视觉统一删除必要说明、错误细节、用户输入或失败恢复。
- 不将空页面改成假数据，不添加无动作按钮，不把本地状态伪装成服务端成功。
- 不接新供应商/付费服务，不使用真实用户或生产数据，不操作Owner手机。
- 不合main、不正式发布、不开展公司/内测/运营/收费。
