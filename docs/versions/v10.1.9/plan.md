## 二、好友、联系人选择与真实聊天衔接

1. 复用现有 Social 请求/邀请及 CN/MC。为本版普通需要选人的路径提供联系人选择器，特别替换 Buddy 的“当前好友用户编号”。协议内部可用 ID，普通用户不必知道数据库编号。平台 APP 本来没有用户 ID 文本输入，不为去 ID 重写其数据链；必要 Web 选人显示可识别标签，内部 ID 仅辅助追踪。
2. 联系人来源仅限本人当前合法关系/请求上下文；每个用途再取其策略允许的子集。好友邀请、Buddy 定向邀请、Showcase 读取、聊天的可用动作分别由服务端返回并在提交时复核。某人出现在列表不等于允许所有动作，不通过全站搜索补足候选。
3. 名称/头像使用该用途当前允许的最小投影。没有资料受众权限时使用可区分代称/占位头像，不能为改善显示绕读私有 Showcase 或照片。列表/名称筛选仅在获准集合内，默认及上限每页 20 条，稳定游标。
4. 保留对方主动提供的现行邀请凭据，可复制/输入并显示过期、撤回、已处理等结果；不要求新建二维码、外链或系统分享服务。好友请求的接受、拒绝、撤回、解除及等待方明确可见。
5. 当前 CN/MC 合法时，从好友/联系人进入现有 Live 聊天；只有读取权限时维持只读状态，缺少同意则引导既有独立授权流程。好友、收藏、评论、搭子或活动不自动创建 CN/MC、会话或通话权限。
6. 解除好友沿用现有语义：好友专属内容及 FRIEND 来源授权失效，独立 CN/MC 不因解除好友自动改变；停止交流/拉黑仍走现有操作，界面说明实际影响。

继承现有 Social 默认：邀请 24 小时、未决请求 7 天、撤回/到期后重试间隔 24 小时、过去 24 小时最多向 5 位不同接收者请求（与正式关系共享现有计数）；被拒后须接收方主动新邀请。接收新请求默认关闭，开启也不取消上下文检查。本版不静默放宽。

## 三、社区作者、真实收藏及现有互动

社区动态仍为 SELF/FRIENDS。作者页接入后端已有作者动态读取并增加有界分页；作者动态与 Showcase 独立判权。合法好友动态可读但 Showcase 不可读时，保留动态，展示资料区显示当前不可用；也不能用动态受众扩权资料或私图。

把当前仅 Snackbar 的“稍后再聊”落实为真实“收藏/取消收藏”和“我的收藏”。收藏是当前账号与动态的唯一持久关联，采用“设为已收藏/未收藏”的幂等语义，响应未知不靠再次 toggle。收藏不通知作者、不自动联系、不复制正文/私图/敏感作者字段为历史快照。

本人收藏默认及上限每页 20 条、按收藏顺序稳定分页；每次列表、详情与媒体读取都按当前权限重新投影。作者删除/改为 SELF、解除好友、拉黑或账号不可用后，收藏显示**无正文、无头像/媒体的不可用占位**，仍可取消；只保留本人关联与时间，不从旧响应恢复内容。作者动态分页同样最多 20 条。

动态流、详情、作者与收藏使用同一真实详情/受众链。现有点赞与一级评论复用，必要时修复返回和状态刷新；“低压私聊”等入口应进入当前合法聊天或独立同意页，不再仅跳到 Showcase。既有评论 280 字、5 次/10 分钟、无附件/联系方式/链接约束继续，不扩建多级评论或推荐系统。

网络失败明确显示未确认/失败并保留同账号合法输入；切号、注销、当前授权变化时清理旧投影和在途响应，不能串账号。

## 四、双人搭子：自愿发现与生命周期

### 4.1 继承能力与新发布范围

保持 MEAL/STUDY、创建者加一位 guest、每人最多 3 个未结束活动。创建草稿占创建者槽，成功申请即占 guest 槽，REQUESTED 已计入；终态释放。现有好友邀请、48 小时单次 TOKEN、revision、命令幂等、许可 epoch 和有序锁继续复用。开始必须在未来、结束晚于开始且距今不超过 31 天等现有约束保持。

所有既有活动、草稿与新创建活动默认**仅邀请**，迁移不公开历史活动。作者在 OPEN 且无 guest 时，另行明确选择“发布到发现”；先展示本次会公开的字段。关闭发现、开启 Buddy 偏好与发好友邀请是不同操作。

| 项目 | 冻结默认 |
|---|---|
| 发现受众 | 已登录、当前账号正常、Buddy 已启用且双方未拉黑的用户；作者也须当前允许该用途。无需参加婚恋匹配。 |
| 发现字段 | 活动定位符、MEAL/STUDY、主题（最多 100 字）、用户手选粗城市或“线上”、地点类型、预算档、起止时间与可申请状态；作者只给明确用于发布的最小称呼。没有独立许可的头像用占位。 |
| 不公开字段 | 精确地址/坐标、联系方式、出生或资格信息、私图、Showcase 全文、其他参与者/申请者目录、邀请凭据、内部审核/预算资料。主题等自由文本沿现有敏感信息约束，不通过正文绕传联系方式或精确住址。 |
| 过滤 | 用户主动选择粗城市/线上与 MEAL/STUDY；不从定位或私人资料隐式取城市，不做人员目录。主题文字用于显示，本版不要求全文搜索。 |
| 发布期限 | `min(发布时刻 + 48 小时, 活动开始时刻)`；到期退出发现。重发须明确动作，不后台自动续期。 |
| 分页与请求 | 每页最多 20，稳定游标；每次最多扫描 200 个候选并按实际扫描位置推进，权限过滤后未满页但未扫完不能宣称没有更多。沿现有 30 次/分钟 HTTP 限流；本版 DISCOVERY 每账号 10 分钟最多成功受理 5 次新申请，不改变 FRIEND/TOKEN 规则。 |
| 失效卡 | 未发布、撤下、到期/已开始、非 OPEN、已有 guest、当前许可关闭、拉黑/账号受限或管理员撤下，均不再发现；旧卡/旧游标不能绕过当前检查。 |

发现必须有单独的最小投影，不能公开现有私有 `/buddy` listing/show 返回体。必要新增城市/发布字段与代次只服务本版用途；存储实现由 Codex 选择，不要求第二套活动服务。

DISCOVERY 新申请业务次数按 actor 与幂等 key 去重：同键同请求重放不重复扣次数，同键不同请求冲突拒绝；重放仍复核当前权限并返回当前投影。无权/冲突而未受理的请求不扣业务次数，仍计通用 HTTP 限流，不以重试绕过保护。

### 4.2 申请与参与授权

浏览卡不产生参与同意。用户明确申请时，在事务内复核当前发布代次、活动 revision、双方状态/许可与槽位；首个合法申请占唯一 guest 并变为 REQUESTED，从发现退出。后续竞争者得到“已不可申请”当前结果，不建多申请队列或候补。作者只看本活动 guest 和状态，申请人只看本人状态，不列申请者目录。

作者再明确确认，形成这一次双人活动的参与状态。DISCOVERY 必须是独立来源，不能落入当前 TOKEN/FRIEND 两分逻辑的 FRIEND 分支；可复用现有 Buddy 许可、双方 epoch、pairAllowed 与来源记录，不另建跨模块同意系统。

**公开窗口到期或正常退出发现，只关闭新申请，不撤销已提交且仍合法的 REQUESTED/CONFIRMED 参与授权。** REQUESTED/CONFIRMED 已不在发现，终止须走拒绝、撤回、取消或当前许可撤销。原发布代次只能消费一次，旧链接/幂等结果不能重开参与。关闭 Buddy、拉黑、账号不可用与生命周期终态按当前策略撤权；重新开启不复活旧邀请。解除好友不应误撤独立 DISCOVERY/TOKEN 来源，FRIEND 来源仍按好友当前状态处理。

沿现有状态机完成申请、确认、拒绝、取消/退出和软件自报完结；终态不悄悄重开，若要重新组织则明确创建新活动。完结不是现实到场认证，不新增信誉扣分或自动处罚。

### 4.3 普通操作、通知与 Web

好友定向邀请接入联系人选择器；日期/时间用正常选择控件，显示设备当地时间/时区，提交标准 UTC，不要求普通用户手填 UTC/ISO8601。普通网络失败保留同账号草稿和待确认命令；结果未知时先读服务器事实或同号重试，不能换 key 重复创建。

申请、确认、拒绝、撤回、取消、完结及直接影响参与的撤权复用 v10.1.8 持久站内通知。通知针对相关接收人，每个真实状态事件只产生一次；偏好关闭不改变业务事实。活跃目标复核当前权限，终态回到本人有权最小结果，不泄露失效正文、照片或恢复旧操作。收藏不发通知。不得借本版接入真实 Push。

现有 Buddy Web 面板增加最小的管理员“从发现撤下”及原因审计，沿当前 RBAC/CSRF/session。管理员不能代作者发布、代双方申请或确认；撤下公开卡与已成立参与的业务取消分别处理。现有评论举报和 Safety 能力保留，不重建治理平台。

## 五、平台活动：邀请、报名、候补与必要后台

平台活动继续具名邀请或现行单次凭据，不增加平台公开城市目录；城市/主题发现由自愿 Buddy 卡承担。普通活动入口清楚区分“搭子发现/我的搭子”和“平台邀请/我的参与”，不要求用户理解内部实体编号。

复用现有 Web 草稿、模拟预算审批、开放、邀请、报名确认、候补转正、关闭/取消/完成，以及 APP 报名/取消。Web 邀请选人只在当前管理员有权操作的有限集合内分页并显示安全称呼，保留 ID 辅助追踪，不向普通 APP 暴露后台目录。

| 项目 | 继承规则与本版出口 |
|---|---|
| 容量 | 2–8 席，默认 2；APPLIED 和 CONFIRMED 计占位，WAITLISTED 不占位。 |
| 报名/确认 | 用户主动报名成为待确认或候补；后台人工确认。报名成功不等于已确认席位。 |
| 候补 | 按服务端稳定 wait_order，后台有空位时仅能提升最早合格候补，不超容量、不越序。 |
| 邀请与期限 | 沿用 48 小时单次、只存 hash 的凭据与现有定向邀请；开始未来、结束晚于开始且在 90 天内。 |
| 生命周期 | 每活动/用户一条参与生命周期，取消不自动复活；个人取消、后台关闭/取消/完成给准确状态。 |
| 当前/历史入口 | 当前有权邀请/参与与最近记录可读；列表默认/上限 20、有界稳定分页，避免固定最近 30 条静默丢记录。不扩建跨活动搜索。 |

补齐实际影响相关人的状态回流：现有 invite/apply/confirm/promote 继续，close/complete/cancel/revoke 按事件相关性产生必要的安全最小提醒；同一状态事件/接收人不重复。本人取消要有准确成功收据；旧活动通知按当前权限返回可读结果或不可用，不复活报名。

## 七、实现与验证方式

建议顺序为：复用联系人和作者/收藏 → 明确 Buddy 发现来源及最小迁移 → APP 发现/参与和必要 Web → 平台入口及状态回流 → 统一必要验证与交付。Codex 可按依赖调整顺序，不需先交设计再等批准。

- 新权限、唯一槽位/容量、revision 与幂等是本版具体风险，做有意义的正反例；涉及 MariaDB 并发/迁移的关键约束至少在实际开发库验证，不仅依赖 SQLite。有限验证即可，不循环压力测试或恢复旧锁等待观察器。
