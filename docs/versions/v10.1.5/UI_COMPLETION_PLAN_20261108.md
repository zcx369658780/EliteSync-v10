# v10.1.5 用户界面收口｜2026-11-08

Owner反馈：“我查看了当前app，很多ui布局依旧是调试状态。”随后明确：“请先修好目前功能的问题，UI最后你按照上面的次序调整即可。”因此先解决功能问题，UI统一后置，顺序为“我的和设置 → 消息列表和聊天 → 首页及主要导航”。此问题纳入v10.1.5剩余工程，功能分项通过不能代替正常用户界面完成；不启动v10.1.6或正式发布。

本清单依据当前源码与Owner实际反馈，**不是截图设计审查或UI验收**。以下项目尚未完成界面修正，实际布局、视觉层级、间距、字号、键盘/小屏适配仍需用具名页面截图核对。必要设备动作继续遵守具体授权与STOP，不为界面工作复活旧测试。

| 页面 | 已发现的用户可见开发态问题 | 收口方向 |
|---|---|---|
| 我的 | “本地恢复功能”“本地开发环境”等工程分类直接出现 | 按用户要完成的任务组织入口，恢复与主导航一致的产品语言与层级 |
| 本人状态/申诉 | “内部Safety不公开”等内部术语混入入口说明 | 保留隐私与本人最小状态边界，用用户能理解的说明表达 |
| 准备状态页 | synthetic projection/readiness authority等开发演示描述 | 区分开发演示与真实资格，正常流程不得把演示状态当真实结果；不伪造可用性 |
| 消息列表/聊天 | “服务端允许读取”“独立生命周期”等工程表达，状态说明偏实现 | 保留连接/消息同意的实际语义，提供清楚的空态、错误状态与下一步操作；统一加载、锁页与操作区布局 |
| 设置 | 条件展示开发者预览，说明包含“不写DB/不接AppShell”等实现信息 | 核对入口实际可见范围，将开发工具与普通用户设置区分；不擅自删除功能、放开权限或改变受保护流程 |

功能问题处理后，按上述顺序逐页核对现有设计与恢复资产，使用现有组件和样式，避免只改文案就宣称布局完成。其它原版有效功能入口的恢复义务保留，不因本清单被省略；保留真实服务/持久化链与安全提示，重大产品取舍仍由Owner决定。每个界面节点记录实际改动和截图/运行证据，不以本计划新增审批层或降低冻结AC。
