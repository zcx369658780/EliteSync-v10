## 3. 五项补充工作

### R1-01 自有SFU故障与RTC持续稳定性

**已知事实：** 当前报告记录5次`authority_monitor TimeoutError`，服务曾耗尽3次自动重启后退出；恢复Room0只证明一次恢复。旧bd4c出现ANR/堆耗尽，后台快照修复后26c观察240.906秒、最终0bad观察120.843秒，长时风险仍未闭环。

**需要完成：**

1. 从已有本机原始日志定位超时发生阶段、调用依赖及可复现条件。修复确认的自有服务/资源问题；无法立即定因时补必要的有界诊断，不能只把重启次数或超时无限放大后称已修。
2. 保留鉴权失效时停止媒体的约束。针对确认的故障做一条有限恢复链，观察房间/采集收尾、旧令牌拒绝、服务恢复及随后正常短通话。不能通过关闭authority监控或降级授权来稳定服务。
3. 在最后候选做一次有限持续观察，覆盖后台来电轮询、页面进退、来电过期/拒绝、前后台与熄屏恢复。时长与循环数由旧故障触发条件确定并写明；工程上可从20—30分钟窗口开始，若原故障更晚出现则按证据调整，不建立新的永久压力测试门禁。
4. 记录正常运行内存趋势、可比较静稳时点的保留对象、峰值与回落、进程身份及ANR/OOM。端点GC可用于比较保留对象，但不得仅凭手动GC后的回落掩盖运行期间持续增长；无需要时不反复抓完整堆。

**完成标准：** 已确认的问题完成修复，并有与故障机制匹配的正常/故障恢复证据；有限观察内未重现旧快照累积或持续不可解释增长。若SFU仍重复退出或根因仍未知且影响正常功能，应保持未解决，不通过更换标签结项。
