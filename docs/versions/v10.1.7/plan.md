## 1. 本版完成后，用户能做什么

本人在 APP 正常补齐必要资料、确认关系目标和择偶偏好，保存到真实后端；问卷继续使用现有服务端题库和提交链。本人明确报名后，现有管理端和 consumer 按双方输入生成并公布候选。APP 能说明当前是准备不足、等待、无候选、可选择还是失败可重试；用户能接受、拒绝、撤回、暂停或退出，并重读自己的匹配历史。

本版交付可用的后端功能和必要界面。已有 Showcase 审核/发布、问卷草稿、轮次/提案、连接及消息同意继续复用；不另建推荐平台，不重做全 APP，也不在本版扩展相识后工具。

## 3. 输入、用途与默认值

### 3.1 一份权威的婚恋输入

本人资料、私密匹配输入与公开 Showcase 保持用途边界，采用一致的读取/保存服务及版本。APP 不维护另一份假状态。匹配输入保存、准备度和普通候选生成均不得以出生时间、出生地点或星盘计算成功为前置；共享生日等字段时，不能因隐式重算特色工具而阻断本版主链。

| 内容 | 本版范围与默认规则 |
|---|---|
| 生日、性别、现居城市 | 复用本人字段。普通慢约须能确定年满 18 周岁；按后端业务日期计算周岁，业务时区固定为 Asia/Shanghai，回归用受控时钟。性别模型与相容规则沿用现行合同，不从名字、照片或 MBTI 推断。城市用一致、可核对的规范键；旧自由文本不能可靠映射时提示本人确认，不借出生地或定位推断现居地。 |
| 关系目标 | 保持 `marriage/dating/friendship` 的 API 兼容；本版明示 marriage=以婚姻为目标，dating=认真交往、以长期关系为方向，friendship=仅交友。前两者可参与普通婚恋慢约，彼此不互斥；仅交友保留交友用途和历史，不能静默当作婚恋报名。首次使用本版语义须本人确认。 |
| 对方年龄 | 支持本人明确选择“成年范围不限”或明确上下界；不限表示最小 18、上界无额外限制，不等于未填写。具体区间下界不得低于 18，上下界须自洽。新输入未经确认时不默认赋予完整偏好。双方设置必须同时满足。 |
| 地域 / 异地 | 两个清楚选项：仅同城、接受异地。表单可预选仅同城以延续旧范围，但必须由本人保存确认；未填写不能当作接受异地。任一方只接受同城时须同城，异城候选须双方都接受异地。无需 GPS、公网地理服务或全世界地址系统。 |
| 可选本人资料 | 补最小身高、学历、职业、婚姻经历、生育状况/未来生育意愿，支持未填写及适用的暂不确定/不愿透露。做正常保存、清除和回读；默认私密。它们本版不成为新增硬门槛、隐藏权重或独立筛选器。若纳入展示，必须由本人主动选择进入既有 Showcase 草稿/审核/发布，不能自动公开。 |
| 20 题与自由意图 | 复用现有题库、按账号草稿、答案/可接受项/重要程度、版本校验和历史。自由意图保留文字用途，本版不通过模型猜测成硬条件。不得要求重做未受影响的整份问卷。 |

旧资料只可预填；新用途和新偏好要本人确认，不批量制造报名、实人核验或同意。既有生日仍是私密资料，匹配需要周岁不等于公开生日或出生时间。成年、城市和目标确认是普通慢约的参与条件，不扩成登录、保存草稿、独立好友/搭子、退出、举报或拉黑的前置；本版自述年龄检查不冒充真实年龄认证。

### 3.2 消除关系目标的双重来源

本版关系目标须有唯一可执行真值及确认版本。基础资料与问卷对应题通过同一契约做一致写入或派生映射；不能一处保存 marriage、另一处仍按 casual 排除。

保留历史原答和旧版本，不把 `friendship` 自动映射成 `casual`，也不悄悄重释历史 `dating`。旧问卷 `long_term` 可作为长期关系的待确认预填；旧 `casual`、冲突或缺失均提示本人重新确认当前目标。仅更新受影响题目的版本/映射和必要确认，其他仍有效答案继续有效；保持现有当前有效 20 题的准备合同。

旧 `casual↔marriage` 独立硬筛以及旧目标不一致的隐藏倍率退出本版普通匹配路径。Showcase 的公开文字不能反向替代私密匹配目标；公开草稿需要本人主动更新。

## 4. 后端如何真实选择候选

### 4.1 先资格，再双方硬条件

沿用账号状态、运营参与资格、当前问卷、本人报名及参与代际、拉黑/已有业务排除等必要约束；加入本版输入完整性、成年及目标用途检查。`approved` 仍只是开发环境中的运营参与资格，不等于真实实名。Showcase 发布、真实身份供应商、SFU、Push 不是普通慢约报名或生成的前置。

候选须同时满足双方显式年龄区间和地域要求。年龄或城市无法确定时不能冒充满足条件。原全局同城规则由双方地域规则替代；原性别相容合同保留；14 天内已配对排除和每人一个未结提案槽位沿用。保存偏好不自动报名；后台不能越过本人参与意愿。

### 4.2 冻结一个有界、可复核的排序基线

本版普通慢约使用已有 `questionCompatibilityDirectional` 的方向相容计算，消费双方**当前有效题目与选项**的主动回答、可接受项及重要程度。不能继续把全部历史答案混入计算。

- 重要程度 0/1/2/3 沿用权重 0/0.33/0.66/1；方向分为加权接受程度的均值。分母为 0 时取中性 0.5，包括没有正权共同有效题的情形，不能把未知表述为不合。
- `rank_score = (A 对 B 的方向分 + B 对 A 的方向分) / 2`。实际选择与记录的排序字段一致，内部数值不包装成婚姻成功率、权威兼容性或“命定”结论。
- 沿用现有配对/consumer 结构，以稳定顺序处理参与者；分数相同时用稳定 pair key / 用户标识消歧并记录规则。保留每人一个候选的当前合同，不宣称全局最优或已验证的公平分配。
- 本版默认排序不叠加旧年龄差、关系目标、活跃度、星盘或 MBTI 隐式倍率，也不输出另一个未被实际使用的“公平调整排序分”。现有曝光信息可保留为内部诊断。本版不恢复已关闭的人格测试产品或其权重。
- 普通匹配路径须实际绕开强制星盘计算，不能只将权重设为 0 而运行时仍先调用星盘服务。既有 MBTI、盘面与独立特色工具能力保留，后续按 v10.1.10 产品化。

在实现报告中记录实际生效的规则/配置版本、排序公式和覆盖来源；本机遗留环境值不能悄悄切回旧默认。一个小型确定性排序对照足以证明规则被消费，无需建立新模型、离线训练或大样本推荐质量项目。

### 4.3 轮次、输入变化及正常触发

新输入包含 revision / 确认版本，纳入现有 source versions、freeze、finalize、reveal 的一致性检查。生成中或揭晓前改偏好、生日、城市、目标、有效答案或参与代际，不得继续将过时结果当作当前可选候选；以现有可恢复终态/失效原因收口并通过正常重试生成。不将前端隐藏当作后端校验。

已揭晓提案不得悄悄换人、延长期限或重写当时理由；保留生成版本，并继续在读取与决策时校验账号、撤权、拉黑、参与状态及当前必要资格。若未结提案已不合法，按明确失效/撤回结果释放槽位，不伪造对方拒绝；既有双方接受的历史事实不改写。暂停按第5节专门规则处理：暂停本身不撤回未结提案、不释放槽位，保留原状态与期限，暂禁接受/拒绝，仍允许本人撤回；退出、实际资格失效及其他撤权条件分别按对应合同处理。仅更新偏好不会撤销已建立的独立 CN、MC、好友或正式关系。历史保留当时事实，不按新输入回填成“当时就如此”。

正常开发链使用既有 Web 创建/准备具名轮次、execution request、实际队列或 `app:matching:execute-pending` consumer、终态及 reveal。允许在正常后台设定可立即处理的开发轮次。不能直接插入一对匹配、改库批准、跳过真实 consumer 或用 TEST_ONLY 提案冒充这条链。

匹配仍是有限轮次，不新增无限刷卡、全站人员搜索或持续抢配。沿用当前提案默认 168 小时有效期；这是提案期限，不是“全站每周一定匹配一次”的承诺。等待页展示真实轮次状态/已配置时间；没有下一轮时如实说明，不伪造倒计时或必定有候选。

## 5. 必要 APP/Web 旅程与历史

APP 只新增或补齐四处：**我的匹配输入、准备度补齐入口、现有慢约页、本人慢约历史**。从“我的”和慢约准备进入同一个输入契约；缺项可直达相关编辑/现有问卷，返回后重新读取服务端准备度。保存失败保留输入；过期会话、切号、迟到响应不能覆盖另一账号状态。保持现有四个顶层入口。

| 状态/动作 | 本版应观察到的行为 |
|---|---|
| 准备不足 | 显示服务端原因和可执行补齐入口；保存资料不自动报名 |
| 已报名、等待/处理中 | 显示真实阶段，正常刷新/重进可恢复；未到揭晓时间不泄露候选 |
| 本轮无候选 | 表示本轮没有满足条件的结果，可查看本人偏好与参与状态；不得显示成系统失败或身份被拒 |
| 执行失败 / 网络失败 | 业务运行失败与 APP 读请求失败分开；显示合法重试/刷新动作；重试不重复产生活跃提案 |
| 可选择 / 已接受待对方 | 保留现有服务端期限、revision 与幂等语义；接受、拒绝、撤回后双方重读一致 |
| 双方接受 / 拒绝 / 撤回 / 到期 | 持久化并进入本人历史；匹配不自动授予普通私信、好友、CN、MC或正式关系 |
| 暂停 | 沿用当前语义：停止后续参与，未结提案保留原状态与期限、可撤回，暂停时不可接受/拒绝；不撤销既有独立社交关系 |
| 恢复 / 重新报名 | 有未结提案时提示先明确撤回，沿用 409 约束；新报名产生新代际，不静默恢复旧提案或同意 |
| 退出 | 按当前合同撤回未结提案并释放槽位；记录本人退出，不写成对方拒绝或负面 Safety 结论 |

历史必须来自持久后端，支持本人分页列表及必要状态详情。保存轮次/提案标识、时间、本人选择、当前终态、安全原因码及内部版本依据；不是复制一份永不撤回的对方资料。

新历史、候选摘要、详情、图片及命令重放均复用 v10.1.6 R1 的当前发布/受众/关系判定。对方撤回 Showcase、缩小受众、关系失效或拉黑后，旧链接和历史不能继续给出其受保护文本/图片；APP 清理本版相关失效投影，不将缓存当作新的授权。本人过程事实可以保留。资料不可见时保留仍然合法的当前提案和选择控件，打开历史不得复活终态写操作。

候选理由只概括真实依据，例如“已满足双方填写的基本条件”“根据已填写问卷进行排序”。不泄露对方原始问卷、精确偏好、出生信息或安全记录；不把缺失输入写成共同点。更具体的公开资料仍依赖本人授权的 Showcase。

Web 复用现有轮次与运行页面，补齐本版所需的真实阶段、失败/重试及规则版本信息即可；不重建管理平台或另加全站敏感资料查询。
