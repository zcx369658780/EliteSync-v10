# v10.1.17开发思路对齐文件

## 1. 当前授权

Owner已正式接受v10.1.16 B2第二轮顾问验收，R1-01 CLOSED、NO_R2。当前唯一新授权为V3.0阶段B3 / v10.1.17「全APP低操作成本重构与功能整合」。

Owner整体实机验收安排在B1+B2+B3完成后。B4和阶段C未授权。

## 2. B3不是加功能，而是重组现有能力

当前问题主要是功能入口、状态摘要、准备状态、生活方式、自动化和关系旅程分散在Home、Progress、Me及SlowDatingJourney等页面。B3要做减法和整合，不复制第三方社交平台功能数量。

## 3. 目标四入口

- Home：当前状态 + 一个最重要的下一步 + 少量可选体验入口；
- Progress：准备、偏好、参与、轮次、提案、Connection、消息同意、Conversation、Relationship各自独立的关系旅程；
- Messages：仅展示当前用户有权访问的会话；通知与聊天分开；
- Me：资料、偏好、隐私/分享、账号安全和可选工具。

默认保留四个底部入口，不新增第五入口。

## 4. 状态来源必须统一

优先使用B2 `/api/v1/user-state`及其`next_actions`。客户端只负责映射稳定code与导航，不重算资格、匹配或关系事实。B2状态中心和自动化页面只有一个规范入口，其他页面可上下文跳转，不复制完整状态控制。

## 5. 必须保护的权限边界

Match ≠ Connection ≠ Messaging Consent ≠ Conversation ≠ Relationship。Buddy独立于恋爱匹配。社区保持有限相互了解场景。不得自动接受匹配、分享、发消息或确认关系。保留ConversationAccessGate、block、隐私、私有缓存、媒体授权和账号切换保护。

## 6. 操作成本必须测量

先建立九项代表旅程基线，测量页面跳转、输入、确认、重复字段、失败恢复。目标至少6/9减少一个不必要步骤，至少4/9总操作减少20%以上。不能为了达标移除必要授权/确认。

## 7. 视觉和权限

沿用Owner冻结的低分辨率、色块、几何构成、低刺激色彩和二次元/构成主义方向；本版不重新设计美术风格，不为装饰生成新素材。Android位置/相机/麦克风/照片/通知权限按用途触发，不首次一次性请求。

## 8. 禁止范围

不做B4运行时AI，不接阶段C身份/征信/芝麻信用/蚂蚁积分/Push/支付，不改变匹配算法、候选排序或关系状态机，不合main、不发布、不开展真实内测/运营，不操作Owner手机。
