# v10.1.11计划：账号支持与功能质量收口

日期：2026-11-14（北京时间）。状态：TASK_ISSUED。依据：Owner本会话授权进入下一版本；范围承接路线图V2.0的v10.1.11章节。

## 1. 目标

收口现有产品中尚未形成真实可用闭环的账号支持、隐私设置、帮助/反馈和必要的功能质量问题。优先复用既有认证、权限、消息、通知、管理面板及持久化能力；只修复当前源码中可确认的断点，不借“质量收口”重构全系统。

用户出口：用户能够在既有账号生命周期内完成可用的凭据管理与支持反馈；隐私设置真实保存并按用途生效；支持人员能在获准后台处理真实反馈；跨模块切换、拒绝、登出/重登和有限离线状态不泄露旧数据或产生假成功。

## 2. 固定边界

- 先从当前源码、ACTIVE_STATE和直接相关报告确认现存能力与缺口；本计划不是对旧版SRC_ONLY/未测项目的自动判失败。
- 不引入新的邮件、短信、身份核验、Push或其他外部供应商，不产生费用。若账号恢复必须依赖未接入的外部验证渠道，应明确记录不可用/NOT_RUN，不伪造验证成功。
- 不把本机偏好与账号级隐私授权混为一体；逐项确认数据归属、默认值、受众、用途和撤回语义。不得扩大头像、资料、展示、好友、连接、私聊、媒体或RTC受众。
- 不改变Match、Connection、Messaging Consent、Conversation、Relationship等既有独立语义；Block、Report和Finding保持区分。
- 不重新打开已接受的v10.1.6—v10.1.10功能链；仅对本版修改或新发现的具体缺陷进行定向验证。
- 真实Push继续REAL_PUSH_PROVIDER_PENDING；历史非注入SFU/RPC精确根因继续UNKNOWN。只有发现与本版具体改动直接相关的新证据时，才进行有界诊断。
- 不开展公司、内测、运营、收费或正式发布；不合main、不操作手机、不自动进入v10.1.12。
- 整体UI、导航结构、视觉系统和全局文案统一仍留在v10.1.12；本版仅提供真实操作必需的最小界面和准确状态反馈。

## 3. 六项验收标准

### AC11-01 账号凭据与会话生命周期
从普通APP入口核验当前账号注册/登录（仅在本版直接影响时）、密码修改、登出、当前设备会话撤销、重新登录和必要的会话过期行为。成功操作必须由真实API和持久状态支持；修改密码后旧凭据应按既有安全规则失效，新凭据可正常登录。不得记录或公开密码、token、JWT或原始认证材料。

### AC11-02 账号恢复与失败边界
盘点现有账号恢复/找回流程及其验证渠道。若已有可用的内部恢复流程，补齐真实请求、验证、状态变更与防滥用限制；若必须依赖未接入的邮件/短信/身份服务，则不接入新供应商，明确显示不可用状态及现有替代路径，AC按实际能力限定接受或NOT_RUN，不以本地跳转、固定验证码或受控响应冒充恢复成功。

### AC11-03 隐私设置真实持久化与生效
梳理现有隐私中心和相关用途控制，区分本机偏好、账号级设置和对象/字段授权。对本版确认的账号级控制完成真实保存、重登读回、撤回/拒绝后的实际访问边界验证；默认受众保持最小化。未被设置控制的字段不得假称已受其保护。

### AC11-04 帮助与反馈真实业务闭环
将现有仅本地草稿/复制的反馈能力（如当前源码仍如此）收口为普通用户可提交的真实支持/反馈记录，持久化提交者、来源功能、类别、内容、状态和必要时间信息；提供本人可读的提交回执/历史及明确隐私提示。不得把剪贴板复制或本地草稿描述为已提交。

### AC11-05 支持后台处理与状态回流
若AC11-04产生真实记录，补齐现有独立Web管理面板中的最小权限后台处理：获授权管理员可查看、分类、更新状态并留下必要处理记录；普通用户只读本人允许公开的回执/状态。验证真实后台写入与APP/API读回。无后台需求的字段不额外建设。禁止向普通用户暴露内部安全案卷、举报材料或其他用户反馈。

### AC11-06 跨模块功能质量与安全收口
围绕本版改动及当前源码可证实的断点，定向检查账号切换/权限撤回/明确拒绝/超时或离线/重登后，资料、隐私、反馈、消息与已接受模块不会展示或操作旧账号/失权数据；失败不丢失合法输入、不假报成功，重试遵守幂等语义。仅修复具体发现的问题，形成受影响模块的最短真实APP/API/DB链及必要反例。

## 4. 实施顺序

1. 最小盘点：检查认证与会话、账号恢复、隐私设置、反馈草稿、Laravel管理路由/页面、相关模型/迁移和定向测试；输出直接相关文件与真实断点，不全库考古。
2. 先修AC11-01/02的账号支持边界，再完成隐私设置；然后建立反馈提交与后台处理的真实闭环。
3. 最后针对本版变更进行跨模块拒绝、撤权、切号、重登和离线/超时定向检查。
4. 优先真实APP/API/持久化链；后台操作通过真实Web/API和管理员权限执行。测试替身只作为反例补充。
5. 只分析改动代码并运行必要定向测试；有跨APP/API/DB变化时做最短真实开发链。只有新改动、失败或具体风险扩大验证，不重复全项目回归。
