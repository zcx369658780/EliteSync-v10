## 1. 设计目标与授权边界

设计一个低操作成本、可返回、按需补充资料的完整产品主旅程：

`访客官方内容 → 注册/登录 → 首次可跳过Lifestyle → 内容与社交体验 → 用户主动进入匹配 → 完成Lifestyle/真实身份与其他必要资格 → 自主报名或独立授权自动参与 → 等待真实轮次 → 当前有权候选提案 → 本人决定 → 双方Connection → 独立Messaging Consent → 有权Conversation`

全过程：
- 仅对真实业务强门槛收集必须字段；
- 资料来源可授权复用，但不会自动公开；
- 星盘可自动计算但不作为Match资格；
- Chat/Notifications两频道，独立未读；
- 待办通知来自当前有效业务状态，不能凭历史通知自动执行；
- `Match ≠ Connection ≠ Messaging Consent ≠ Conversation ≠ Relationship`；
- 真实身份供应商尚未接入：目标旅程中的身份核验、正式真实匹配后续部分目前不可实际全链走通；不得以QA/运营/假凭据替代。

## 2. 用户模式与可用范围

| 状态 | 可用路径 | 关键限制 |
| --- | --- | --- |
| GUEST | 官方公开精选/专题正文只读 | 不能访问用户公开作品、好友动态、评论/点赞/收藏/举报/站内反馈、聊天、通知私人信息 |
| AUTHENTICATED_COMMUNITY | 精选、站内公开作品、按好友受众查看好友动态、合法社交互动 | 已登录≠实人已核验≠匹配已报名≠私聊许可 |
| PREPARING_MATCH | 查看匹配条件、填Lifestyle、核验占位/未来服务、补必要匹配输入 | 未过实人门禁不得报名真实匹配，星盘/MBTI不得成为附加硬门槛 |
| MATCH_PARTICIPANT | 已通过门禁并明确报名/授权；可查看有权轮次和提案 | 候选接受需本人决定，不自动建Connection |
| CONNECTED_WITH_CONSENT | 双方独立建立Connection与Messaging Consent | 才能按实时gate进入Conversation；不意味着正式Relationship |

以上是概念用户状态，**非新后端枚举或已执行的迁移**。

## 3. 正常主旅程：从访客到聊天

| Step | 用户眼中看到的画面/任务 | 用户必须操作 | 系统自动处理 | 归属、门禁、证据口径 |
| --- | --- | --- | --- | --- |
| J00 | 访客看到官方精选和专题正文 | 可浏览；若想互动需登录 | 只返回PUBLIC_EDITORIAL | Home；访客不能提交任何互动或读取其他用户作品 |
| J01 | 注册/登录 | 提供账号必要信息并同意应阅读的协议 | 安全建立当前用户会话 | Auth；1011804已有login/register入口，新注册全链本轮NOT_RUN |
| J02 | 首次Lifestyle欢迎与五场景卡通问题 | 选择作答或跳过 | 保存五场景偏好并提供简短摘要 | Lifestyle；跳过不妨碍内容浏览，后续真实匹配需要完成 |
| J03 | 默认回到首页精选；可切到好友 | 浏览官方/公开作品，按权限评论、点赞、收藏、发布 | 独立加载官方、站内公开、好友内容并核受众 | Home；用户新作品默认FRIENDS，公开作品功能属未来增量 |
| J04 | 用户点击「匹配」并看到准备概览 | 主动选择开始准备 | 读取已有L/身份核验/必要资格事实，给缺失项清单 | Match；不因进入页面自动报名或发送资料 |
| J05 | Lifestyle尚未完成时，直达当前未完部分 | 回答缺失的问题，或先离开匹配 | 保存并从原匹配准备位置恢复 | 匹配前必需；不强迫注册阶段完成 |
| J06 | 真实身份核验 | 未来供应商接入时，用户主动开始核验与必要授权 | 仅核对供应商实际返回的有效核验事实和来源 | 当前供应商未接入，显示不可用/未核验，严禁测试凭据伪装真实资格 |
| J07 | 匹配偏好与必要资料 | 查看已有预填，只补缺失或变化项，确认用于匹配 | 按来源/版本/用途核对User和MatchingInputs，保存有版本的匹配输入 | Match准备可直达Me唯一字段编辑入口，返回原任务；原合同revision/hash仍保留 |
| J08 | 可选特色资料 | 用户首次给予独立星盘计算用途授权、或保持跳过 | 足够出生资料且授权有效时自动生成；缺字段、计算失败继续显示真实状态 | Me自我探索；星盘不阻断Match；1011804动态星盘失败原因UNKNOWN |
| J09 | 资格全部满足后，选择参与方式 | 明确「参加本轮」；若希望持续参与，则**另行明确授权** | 后端检查L+真实身份+必要资格+当前轮次与有效授权，给幂等回执 | Match/B2唯一自动授权页；无权限或UNKNOWN不得显示成功 |
| J10 | 等待轮次/候选 | 无须重复填资料、重复确认；可随时查看/暂停规定操作 | 按既有匹配流程运行并汇总真实当前状态 | Match；不能制造候选或用网络失败冒充无候选 |
| J11 | 当前有权查看的候选提案 | **本人明确接受/拒绝/撤回** | 在当前提案、受众、版本/到期/权限下记录决定 | Match；双方接受不直接建立Connection |
| J12 | 双方表达继续认识的意愿 | 双方分别按合法流程同意建立Connection | 建立独立连接事实，不默认开启Conversation | Match/Connection；不可用旧Match结果代替当前双方许可 |
| J13 | 是否开启私聊 | 双方独立完成Messaging Consent | 服务端生成/更新独立消息许可并核当前gate | Connection/Consent；未满足不得读取或发送消息 |
| J14 | 进入聊天列表和有权会话 | 用户打开Conversation，可选择输入发送 | 安全读取有权消息、独立计未读、必要回执与本地账户隔离 | Messages/聊天；不得自动发送、自动通话或推断Relationship |
| J15 | 日常通知 | 用户打开「通知」频道、查看需要处理的真实事项 | 当前有效待办排前，普通通知按时间；点击后目标服务重新验权 | Messages/通知；通知点击不执行匹配/好友/Buddy决定 |
| J16 | 如双方未来要建立正式关系 | 双方另行明确作出Relationship决定 | 独立验证关系/身份/分享范围 | 不属于完成聊天的必要步骤，不能由聊天时长自动推断 |

## 4. 三级导航与单一责任归属（ADVISOR_PROPOSAL）

- **Home**：官方精选/问题专题、仅登录用户公开作品、好友动态、作品详情、创作入口；本人匹配摘要为轻量跨域捷径。登录门禁由内容受众控制。
- **Match**：准备清单、一次报名、自动参与控制入口、轮次与提案、本人决定、Connection及关系相关管理；仅展示有当前业务权利的操作。
- **Messages**：聊天/通知双频道，默认聊天、独立未读；通知待办优先、普通按时间；详情与权限由原业务所有者负责。
- **Me**：顶部形象卡、个人资料、我的偏好、自我探索、社交与内容、隐私授权、系统安全；跨页只指向唯一资料编辑来源。
- **B2持续参与控制**：Match和Me均可链接，但只保留已有**一个**授权控制页面。
- **后端业务真值**：各域仍按自身Controller/Service/受众/version判断；视觉合并不合并事实表或许可。

## 5. 用户操作压缩方案（ADVISOR_PROPOSAL）

### 5.1 从「重复填写」到「只补缺失」
1. 同一事实如生日、出生地点以有来源的原值为基础；不同用途分别获授权后使用，不做静默跨用途复制或公开。
2. 「匹配准备」不再将用户派到多个表单自行寻找字段，而是列出一个当前缺失清单，点击直达Me对应字段编辑；保存后回到原来Match准备位置。
3. 法定姓名、社交昵称、匹配昵称各自语义不同；当前城市不代替出生地点；出生日期不代替出生时刻。
4. 社交/匹配形象默认引用主头像昵称；当主形象修改时更新**本人预览**，对外匹配展示仍以有效发布版本和受众确认控制；单独覆盖字段保持不变。

### 5.2 从「重复确认」到「有权利的明确决定」
- 不重复要求已经有效的同一用途授权。
- 仍必须明确：认证/资料用途、作品发布及扩受众、报名与自动参与、候选决定、Connection、Messaging Consent、Relationship、账号/权限撤销等。
- 不用一个「全部同意」替代多域独立权利。
- 请求超时或结果UNKNOWN时先按既有幂等键/服务回执核对，不诱导用户重复提交。

### 5.3 文字与视觉操作
- 首屏提供**一句当前状态+一个主操作**，把细节/规则折叠到「为什么」「更多说明」「权限与说明」。
- 选中/按下按钮文字必须保持可读，不用高亮遮挡文字；动态效果可用减少动态效果替代。
- 每次跨域进入资料编辑、查看通知回流之后应安全返回原用户任务，不重置已输入草稿。
- 不以巨大状态清单、内部UUID、枚举状态码或revision直接暴露给用户。

## 6. 关键异常与可恢复分支

| 情况 | 目标界面反应 | 禁止 |
| --- | --- | --- |
| 新用户跳过Lifestyle | 进入内容首页；参与真实Match前再引导完成 | 一注册就锁全部APP |
| 身份供应商尚未配置 | 明确「真实身份核验尚未开放」并保留准备资料入口 | 使用测试/运营核验冒充真实核验成功 |
| 核验失败/超时 | 显示可恢复状态及符合实际服务能力的重试/人工入口 | 永久拒绝或假成功 |
| 缺出生时刻/地点 | 星盘显示可补充/精度不足，Match不因星盘被阻断 | 推测出生时刻，虚构命盘 |
| 星盘失败 | 保留失败/UNKNOWN和重试，匹配如其他条件满足仍可继续 | 把星盘故障直接变匹配资格失败 |
| 没有匹配候选 | 真正无候选就显示等待/本轮无候选 | 把请求错误显示成无候选 |
| 提案已过期/被撤回 | 提示提案不可用，刷新当前Match | 允许操作过期候选 |
| Connection未成立 | 进入合法的连接决定界面 | 自动授予Messaging Consent |
| 消息许可被撤销 | 当前写入和被撤销后的读取受权限约束，旧内容按既有合同清理 | 继续发送/用旧缓存查看无权资料 |
| 网络中断 | 显示离线/旧数据状态；确认当前账户授权，必要时可重试 | 将超时解读为对方拒绝 |
| 账号A→B切换 | B不能读A聊天、通知、草稿；异步旧回执废弃 | 显示跨账号数据 |
| 评论权限失效或被拉黑 | 内容与通知目标重新验权，失权即清相关显示 | 通过旧通知继续读评论/媒体 |
| 待办已处理/过期 | 从待处理上移走或更新有效状态，保留必要历史通知 | 把未读误等同仍可处理 |

## 7. 低操作成本验证方法（建议的未来指标，不是当前成绩）

历史UI-AUDIT-01仅提供具名导航点击和源码/模拟器观察，不等于从注册到聊天的完整业务操作次数。因此不在本稿宣称「已将X步降至Y步」。

等Owner批准旅程并授权实现时，选定有界QA用例，分别比较：
- 注册到可浏览内容的用户必填字段数、完成动作数；
- 注册跳过Lifestyle后再次进入Match的恢复跳转数；
- 匹配准备中资料重复填写次数与从缺失项到字段的点击数；
- 手动报名与自动授权的分别确认数；
- 有提案时到Connection和合法Conversation的业务必经明确决定数；
- 通知待办进入原业务详情所需的额外导航数；
- 已有资料修改后多页面重新填写次数；
- 字号放大/减少动态效果/屏幕阅读器下完成性。

目标是减少**不必要**操作，不追求减少真实授权和关系决定数量。
