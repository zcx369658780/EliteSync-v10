## 1. S01 首次Lifestyle欢迎

| 核查字段 | 当前建议 |
|---|---|
| PURPOSE | 一眼理解：用五个生活场景了解偏好；这是可跳过的轻探索，不是实名认证和婚恋报名 |
| CURRENT_STATE | 刚完成注册、首次引导是否应展示；答过几题必须依据当前账号有效记录，不从旧缓存猜 |
| PRIMARY_ACTION | `开始探索`，进入当前可进行的第一道场景题 |
| SECONDARY_ACTIONS | `以后再说`清晰可见；不要求先填写MBTI/出生时刻/完整匹配资料 |
| AUTHORITY | Owner已确认注册后首次出现且可跳过；具体“仅一次”账号级跨设备记忆和技术存储仍OPEN |
| RETURN_PATH | 跳过→当前账号有权的首页精选；完成五场景后的Home落点为已有V0.2顾问方向，具体动画/页数未定 |
| RECOVERY | 登录/注册结果及初次状态未知时不可假称已完成，账号切换不共享引导/进度；不得每次登录错误强制重新提示 |

**受控设计提醒**：首次引导的“仅一次”已是Owner产品意图，但并不证明后端支持跨设备一致的`SEEN_SKIPPED`持久记录；不能擅自写成已经实现。

## 2. S02 Lifestyle单题与恢复

| 核查字段 | 当前建议 |
|---|---|
| PURPOSE | 当前五场景中的哪一题，带情境插图和**三项**清晰可读选择 |
| CURRENT_STATE | 已确认保存进度、当前题目版本、选中但尚未确认的本机答案区别展示 |
| PRIMARY_ACTION | 本题选择答案；仅服务端确切确认保存后，顾问建议自动进入下一题，减少无意义点“下一步” |
| SECONDARY_ACTIONS | 返回上一题/改选（仍需当前有效版本）、稍后继续、查看当前安全保存状态 |
| AUTHORITY | 当前账号、题目版本、已确认答案与进度；无法确认写入时保持UNKNOWN，旧设备或旧账号不能回填 |
| RETURN_PATH | 从欢迎页开始者完成后回合法内容首页；从Match/Me进入者完成后返回原任务并重读进度，不自动报名 |
| RECOVERY | 保存中不自动前进；失败/UNKNOWN保持选择与稳定说明，在能确认安全条件后才重试；无需强迫用户重选相同答案 |

**S02-D1 新的明确Owner审阅点**（与此前已认可的异常/进度原则不同，尚不是对具体交互默认批准）：

> 默认采用“点击一个图文答案即提交该题；**确切保存成功后自动到下一题**；保存中/UNKNOWN/失败停留本题，允许安全返回和稍后继续”。不强制另加一个常驻的“下一题”按钮。若存在额外敏感确认或题目本身具名授权要求，仍需独立动作，不能一键覆盖。

最终题目具体文案/图像、答题回退确认、自动进题动效和数据版本机制仍OPEN。

## 3. S03 访客首页精选

| 核查字段 | 当前建议 |
|---|---|
| PURPOSE | 浏览允许公开的官方精选/专题正文，而非进入访客可见的站内用户社交区 |
| CURRENT_STATE | 当前会话为访客；只渲染`PUBLIC_EDITORIAL`已授权正文 |
| PRIMARY_ACTION | 阅读官方精选或官方专题 |
| SECONDARY_ACTIONS | 登录/注册、允许的返回/内容导航；反馈/评论/收藏/点赞/举报等站内互动不可用 |
| AUTHORITY | 每份官方正文当前公开许可；媒体、搜索预览、深链与缓存同门禁；官方专题评论正文对访客不开放 |
| RETURN_PATH | 阅读返回官方精选，主动登录后重新按当前账号和受众生成合法首页 |
| RECOVERY | 官方内容缺失/断网时显示安全、无用户私密缩略图的空态；登录/切号失败不可从旧账号缓存补内容 |

此页既有权限属于Owner已确认；卡片排列、空态文案与登录引导位置尚未逐项确认。访客不因可读官方专题正文而可以读评论。

## 4. S04 有效登录用户的精选/好友首页

| 核查字段 | 当前建议 |
|---|---|
| PURPOSE | 精选频道查看官方内容与当前合法用户公开作品；好友频道查看有效双方好友的动态 |
| CURRENT_STATE | 账号有效，首页首眼内容优先；后台按受众、Block、评论策略以及媒体权限提供合法数据 |
| PRIMARY_ACTION | 阅读本人当前有权的内容/进入原作品详情 |
| SECONDARY_ACTIONS | `精选/好友`切换、按合法策略互动、发作品入口、低干扰匹配入口 |
| AUTHORITY | `PUBLIC_EDITORIAL`和`PUBLIC_AUTHENTICATED`分域；`FRIENDS/SELF`依法定当前受众；编辑推荐只指向原作品并不升权 |
| RETURN_PATH | 详情页返回原频道/滚动位置是顾问优化方向；跨页资料/匹配返回以当前账号及安全栈为准 |
| RECOVERY | 用户失权/Block/下架时移除相应内容及预览，旧评论附件/引用不得因原作品公开扩大可见，迟到请求不能回填 |

**S03/S04-D2 新的明确Owner审阅点**（尚未确认）：

> 首页内容不足或无法核验受众时，显示只针对当前账号权限的**安全空态/重试说明**。访客不出现用户作品可识别占位、登录用户也不能借旧缓存展示失权卡片；空态不应暗示“好友关系已失效”或泄露哪位用户设置了Block。进入登录账号后重新取得合法可读内容，不将原访客/前账号状态当作有权数据。

不会强制登录才能读官方公开正文，用户匹配捷径必须保持低干扰。当前没有批准卡片具体大小、排序算法、图像占比、推送或精确布局。

## 5. 四屏联动与QA检查（静态预案，未执行）

| 代表路径 | 合法预期 | 防误判 |
|---|---|---|
| 注册成功→首次欢迎→跳过→首页精选 | 可跳过且正常浏览当前有权内容 | 跳过不变成Lifestyle已完成或实人核验PASS |
| 欢迎→第2题选答案→写入UNKNOWN | 停留当前题，先只读查已确认结果 | 不自动跳题或重复写入 |
| 已确认2/5→从Match继续Lifestyle→完成 | 只补缺题，成功回原Match重新核实资格 | 真实核验未接入依然不能报名 |
| 访客浏览官方专题→看评论/用户站内公开作品 | 不能读取未获准内容，也不能提交互动 | 评论正文、受限缩略图或直链都不得泄漏 |
| 已登录浏览好友内容→对方Block/权限变更 | 当前不再有权时安全撤去 | 不留历史正文/媒体/引用预览 |
| 切账号后旧精选请求迟到 | 不将前账号首页及私密媒体渲染给现账号 | 不因缓存命中跳过当前受众门禁 |

QA未来按D/I/N/A/W、字体放大/读屏/减少动效/系统Back/横竖屏/异常分别记录真实`PASS/FAIL/NOT_RUN/UNKNOWN`与证据，不能从本草案推导测试PASS。
