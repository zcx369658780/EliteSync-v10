# EliteSync V2｜O09 跨设备会话、权限重验与写入UNKNOWN一致性（顾问设计V0.1）

日期：2026-11-19（Asia/Singapore）  
状态：`ADVISOR_PROPOSAL / OWNER_REVIEW_PENDING / DESIGN_ONLY / NOT_RUNTIME_VERIFIED / CODEX_NOT_AUTHORIZED`

## 0. 目标及已有权威

O09不是要新造一套独立同步服务，而是说明跨设备、通知深链、后台回流和结果UNKNOWN时，APP如何不误导用户或暴露不再有权的内容。目标仍是：**第一眼看清当前任务、尽量少无意义操作，真实权限与业务决定优先**。

已有Owner原则：
- [A6.6 Owner确认](../decisions/OWNER_A66_CONCEPT_REVIEW_20261119.md)：账号切换后不保留旧账号私密视图和迟到响应、权限撤回即时移除失权内容、异常稳定但安全、写入UNKNOWN先只读查权威结果再决定是否重试。
- [A6.7 Owner四项](../decisions/OWNER_A67_CROSS_PAGE_CONSISTENCY_ACCEPTANCE_20261119.md)：内容失权和账号失效分开、旧通知重验、核验供应商未接入和用户缺项区分、跨页一律先身份/权限后业务/受众/有效版本再主操作/安全返回。
- [O04/O05 Owner确认](../decisions/OWNER_V2_O04_O05_DATA_REUSE_AVATAR_PUBLICATION_20261119.md)：当前资料来源/具名用途/受众/已发布版本独立；新匹配形象默认面向未来新候选，既有合法候选不自动换版。
- [O08 Owner确认](../decisions/OWNER_V2_O08_SAFE_FEEDBACK_ATTACHMENTS_DRAFTS_ACCEPTANCE_20261119.md)：反馈附件默认不上载，当前有效会话内暂存，不承诺跨进程或跨设备恢复；反馈UNKNOWN不自动重放。
- [完整用户旅程草案](ELITESYNC_V2_REGISTER_TO_CHAT_USER_JOURNEY_V0_2.md)：通知只导航不代替关系决定；Match/Connection/Messaging Consent/Conversation/Relationship各自独立。
- 固定1011804与UI-AUDIT-01的历史证据；目前**未运行跨设备同步/权限测试**。真实身份供应商和真实Push未接入。

## 1. 权威一致性框架（顾问设计，不是新数据库合同）

页面允许呈现的状态依赖于以下五项，缺一不可时不能凭旧缓存猜测：
1. **当前会话身份**：当前设备登录账号、账号有效性及数据所属账号；
2. **当前读取权限**：Block、受众、会话/消息许可、当前业务必要权利；
3. **当前业务事实及版本**：当前提案、资格、资料版本、通知对应事项是否仍可执行；
4. **具名用途和已发布快照**：资料本人编辑并不等于对外已发布，合法复用不扩大用途；
5. **安全动作与返回**：只显示有权的当前主操作；异常与失权返回合法安全页面。

“已显示的旧客户端内容”“已发送的本机请求”“通知未读”“已点击提交”都不自动升级为有权、可操作或已经写入。

## 2. 七个代表情景（不代表同一账号的连续成功旅程）

| 情景 | 有风险的误判 | 建议界面与恢复 | 未来QA要求（未执行） |
|---|---|---|---|
| 01 同一账号，设备A更新匹配资料，设备B仍打开旧匹配准备 | B沿旧资料允许报名或显示完成 | B重新进入/刷新任务时核对当前权威资料、用途、资格；明确展示新结果或需补项目；不可凭A本地动画宣布成功 | A确切保存与UNKNOWN分支；B重读前后状态、资格禁用 |
| 02 设备A撤销消息许可或Block，设备B还打开有权会话 | B继续阅读/发信或复用旧媒体链接 | 一旦知道失权即移除私密内容与写入入口；重新访问/发送必须重验当前权限；没有可靠可用权限时对受保护动作安全阻断 | B远程失权感知、数据隐藏及服务端拒绝链；传播时效实测 |
| 03 同设备切换账号QA-A→QA-B，QA-A请求迟到 | 旧账号回包/草稿写入B | 切号立即清空隔离旧私密视图及受控历史；迟到响应不能渲染；B加载自己的合法状态 | 切号前后缓存/导航/媒体/草稿与迟到请求 |
| 04 旧通知/深链从锁屏或外部返回 | 通知显示对方私密身份、旧接受按钮仍可用 | 受限入口先检查当前身份、受众/Block、事项有效版本；有效才进当前业务详情；失效只显示安全摘要或隐藏，不能直接接受 | 访客、别的账号、失效事项、拒绝、撤销、媒体 |
| 05 设备A提交修改后网络超时，设备B似乎已经看见新版 | A把B的画面当作已收到权威成功回执 | A仍显示“结果未确认”；从当前具名业务权威读取/比对实际版本后才能确认；不因B的截图或缓存直接推断 | 已成功但回包丢失、确实未成功、无法查询、幂等冲突 |
| 06 离线重入受保护页面 | 本地缓存被当作长期有效许可 | 当无法核查必要的当前访问权时，**建议**显示安全占位和“暂无法确认访问权限”，不允许高影响写入；既有已获授权离线只读能力若存在须在未来单独定义边界 | 无网/恢复网络、账号切换、过期、授权撤销、系统Back |
| 07 反馈草稿与附件在账号切换/重启/另设备访问 | 展示旧账号或用户以为反馈已同步 | 按O08仅当前有效会话内安全暂存，换号/失权隔离；无跨设备或跨进程恢复承诺；提交UNKNOWN不得自动重传附件 | 切号、登出、失权、重启及未知提交的边界 |

以上是未来目标与QA设计，不能声称已经实现实时跨设备推送、远程擦除、强一致服务端版本、离线权限证明或通用幂等API。

## 3. O09-R1：受保护跨设备内容的“重验再展示”规则（待Owner审阅）

**建议**：当发生切号、深链、设备恢复、业务返回、权限版本改变、或受保护操作前需要确认当前资格时，客户端不能将已有缓存当作权限证明。
- 需要核查而结果未返回时，显示低密度的安全“正在核对访问权限/暂时无法确认”占位，不在等待期间继续渲染不再能证明有权的私密正文；
- 确定仍有权且业务版本有效后，才展示对应当前内容/操作；确定失权时立即隐藏并安全返回；
- 确定失权不等于当前账号整体失效，能否反馈仍按O08独立资格判断；
- 旧账号迟到回包/旧导航栈不能跨账号显示；新账号任何状态不得从旧账号缓存推断；
- 实际远程撤权通知、接收速度/强一致性门限/预加载策略属于未来工程和产品合同，**不得承诺“所有设备零延迟同时更新”**；
- 如果未来存在已正式批准的离线只读授权，需独立界定其有效性和失权条件，本提案不直接推翻历史合同。

## 4. O09-R2：写入UNKNOWN和跨设备一致的确认语义（待Owner审阅）

**建议**：一个关键写入只有“服务端可核验已完成/未完成/UNKNOWN”三类用户可知语义。跨设备画面不能作为唯一提交证明。
- 回包丢失、断网或超时只意味着结果UNKNOWN，不自动推断操作失败；也不自动用另设备的旧缓存宣布成功；
- 主操作是“检查当前结果”（只读查询当前有权的权威业务版本/请求身份）；查询不到继续保持UNKNOWN，允许安全退出与脱敏复制；
- 若确认成功，显示确切完成结果并刷新该任务的当前业务状态；若确认没有成功，且服务端/请求幂等与当前授权仍支持安全重试，才显示新的明确重试动作；
- 若双方状态冲突、身份或权限改变、幂等事实无法获取，应停止自动重放并向用户清晰说明结果未知/需要核对；不执行提案接受、Connection、消息许可、对外发布、反馈附件等重复高影响写入；
- 每类写入是否具备请求幂等标识、权威查询与版本冲突处理是未来实现合同/工程证据，**不假定现有API已具备**。

## 5. O09-R3：资料与发布版本不得因恢复流程合并（既有Owner原则的延续）

从匹配准备编辑字段后，确切保存才回原业务重新计算资格；个人预览与对外发布独立；O05-X方案A默认新形象仅面向未来有权候选；不能因设备B读到新头像就自动替换既有候选快照。该节不作为新的Owner取舍，继承O04/O05。

## 6. 未来可执行验收门槛（定义检查范围，未运行）

- 两个账号×两个设备的授权和隔离矩阵；
- 同一账号跨设备源资料更新/用途撤销/候选版本展示；
- Block、Connection、Messaging Consent失权后受保护阅读/媒体/RTC/发送是否被正确门禁拒绝；
- 通知已读/待办/深链校验、退出与安全错误状态；
- 写入成功但回包丢失、真实失败、重复请求、服务端查询不可用；
- Android系统Back、横竖屏、字体放大、减少动态效果、进程回收；
- 必须对每项报告`PASS / FAIL / NOT_RUN / UNKNOWN`和实际来源，不能将静态设计当测试结果。
