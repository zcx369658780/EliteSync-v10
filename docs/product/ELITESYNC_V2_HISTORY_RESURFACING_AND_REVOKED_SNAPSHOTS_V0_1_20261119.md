# EliteSync V2｜历史评论再展示、旧候选快照与用途撤销的权限边界 V0.1

日期：2026-11-19（Asia/Singapore）  
状态：`ADVISOR_PROPOSAL / OWNER_REVIEW_PENDING / DESIGN_ONLY / CODEX_NOT_AUTHORIZED / A6_MEETING_DEFERRED`

## 0. 本轮意图与权威分层

本轮不是讨论“统一保留几天”的任意技术数字，而是解决**对象在用户改变受众、撤销许可之后，还能被谁看到、什么时候会重新可见**。

已确认的前提：
- [Owner CMT-T1方案A](../decisions/OWNER_V2_CMT_T1_SELF_TO_FRIENDS_COMMENTS_20261119.md)：普通FRIENDS+FRIENDS_ONLY；SELF特殊默认OFF；SELF→FRIENDS时可在保护显式OFF的前提下推荐好友可评论。
- [O01/O02历史评论与媒体边界](../decisions/OWNER_V2_O01_DEFAULT_COMMENTS_O02_MEDIA_REFERENCES_20261119.md)：作品扩大受众不自动提高旧评论/附件/引用的可见性，评论作者的权利不能由作品作者单方替代授权。
- [O04/O05发布快照方案A](../decisions/OWNER_V2_O04_O05_DATA_REUSE_AVATAR_PUBLICATION_20261119.md)：新匹配形象默认仅面向未来合法候选；既有候选是否可看旧快照始终受当前权限、Block、版本约束，不能永久访问。
- [O07撤销具名用途及派生历史](../decisions/OWNER_V2_O06_R2_R3_O07_R2_ACCEPTANCE_20261119.md)：撤销后停止失去许可的用途下继续读取/使用；纠错相关派生结果“需要核查”；合法历史读取权与数据保留/删除分别决定。
- [O09权限再核与UNKNOWN](../decisions/OWNER_V2_O09_CROSS_DEVICE_AUTH_UNKNOWN_ACCEPTANCE_20261119.md)：旧客户端缓存、通知/深链与跨设备旧画面不能证明现时仍有权限。

**以下HIS-D1/HIS-D2只是新顾问审阅建议**。既有Owner原则在当前继续有效，不将此稿当法律留存政策、数据schema、已实现的服务端恢复或真实QA PASS。

## 1. 三种概念状态不可混同

| 名称 | 应表达的含义 | 不能由该状态推断 |
|---|---|---|
| 当前不可阅读 / 已隐藏 | 当前受众、Block、用途或版本条件不允许该用户读取 | 不能推断服务器上的历史记录已永久删除 |
| 当前允许查看历史 | 当前**另有合法历史查看权**且原记录边界仍满足时，可只读访问合规范围 | 不能推断历史可面向所有新受众公开、不能自动改回当前有效结论 |
| 实际删除 / 到期清理 | 依据未来具名存储、删除、例外及实际完成回执产生的结果 | 没有真实回执不能显示“已永久清除” |

前端“无法继续查看”不得伪装为“已删除”或“有人拉黑你”；通知/错误摘要若可能推断私人关系，宁可隐藏而非暴露。

## 2. HIS-D1（新建议）：受众收窄后再扩大，历史评论不得自动扩大或突破当前权限

**场景**：作者作品在`FRIENDS`时曾收到好友评论 → 改为`SELF` → 日后再次设为`FRIENDS`或`PUBLIC_AUTHENTICATED`。

顾问推荐：
1. `SELF`生效期间他人不读取作品，也不通过旧通知、缩略图、原媒体URL或旧缓存读取评论和附件；这不自动证明其底层原始评论已删除。
2. 之后作者**再次明确扩大作品受众**，旧评论若仍存在，能否重现必须至少同时满足：**当前作品读取权、该旧评论原有历史受众/当前仍适用的访问限制、Block/账号条件以及任何额外合法保留/可读前提**。不把仅曾经是好友的人永久视为当前好友。
3. `PUBLIC_AUTHENTICATED`新增的非好友读者可以合法读当前作品时，**不能因作品公开就自动获得历史好友评论、附件与引用**。
4. 作者不能借重新公开自行替历史评论作者赋予更广的权限；若某条旧评论的原受众/版本无法可靠重建，**默认不展示该条历史受保护内容**，不声称已恢复所有评论。
5. **作者本人对历史内容的查看也应与第三方评论者的相应权利、已撤销授权和合法留存范围分开**；不假定评论作者拥有无限期查看整篇作品或所有别人评论的权利。
6. 界面建议：给作者最小提示“原有评论可能受原权限限制”，对不再有权用户只显示安全空态，避免“X条评论仍隐藏”这种可能揭露私密活动的数量提示。
7. 评论历史是否留存、保留期限、作者或评论者可请求删除/撤回的具体政策、跨设备传播时限，继续OPEN。

**对照可选路径**：
- **A（推荐）**：当前读取权 ∩ 原历史评论边界，满足时才允许合法重现；无法核验默认隐藏。
- **B**：任何再次扩大作品受众一律不重现旧评论，安全但用户可能失去合法历史互动回顾；具体内容真实删除仍属另一决策。

## 3. HIS-D2（新建议）：撤销或收窄已发布候选快照时，安全状态优先而非旧版永续

**场景**：用户合法发布匹配形象V1给已有候选，随后发布V2（O05方案A仅未来新候选），或对某个候选Block、收窄对外受众、撤销相应用途许可。

推荐分开：
- **只发布V2**：如果既有候选仍有权读取V1，则仍按其当时合法有效的V1快照展示；不自动同步V2，也不把旧候选读取权限扩大到V2。原版是否继续保存及多久是另一合同。
- **Block/收窄受众/撤销必要许可**：一旦按当前权威确认旧候选**已无权**读取V1，立即停止继续展示V1敏感内容；该候选的旧缓存、媒体地址、通知和深链均不能作为永久通行证。
- **界面状态建议**：若该候选当前仍有权访问对应的非敏感业务页面但无权访问形象媒体，可仅显示不会推断Block或敏感关系的中性文案“相关资料当前不可查看”；如果该页面本身已不具合法访问权，整个受保护入口隐藏或安全返回。
- **不得伪称已删除全部历史**：撤销展示权限与服务器真实删除/证据留存是两件事；已有候选不因不能看头像就自动解除合法独立的Connection、Messaging Consent或Relationship。
- **UNKNOWN或传播不确定**：不能宣称远端所有设备已同步清除；设计目标是每次受保护访问重验当前权利，实际传播时效需工程检验。
- **派生结果类比**：O07具名用途撤销下的派生内容即时隐藏、纠错后实际受影响结果标需核查；不得将历史快照隐藏等同于重算结果、永久删除或自动撤销独立用途。

**两条候选政策**：
- **A（推荐）**：失权后敏感快照彻底退出可阅读界面；只有业务入口仍合法时才可展示最小中性状态，否则隐藏入口。与既有O05/O09边界一致。
- **B**：无论业务入口是否合法，一律留一张“先前匹配形象已撤回”历史卡；更方便回顾，但可能泄漏本不应暴露的关系事实，不推荐。

## 4. 用户可感知的最简文案（建议，非冻结文案）

| 情况 | 显示 | 不显示 |
|---|---|---|
| 作品从SELF恢复FRIENDS且旧评论有权可读 | 当前有权评论、合法原历史评论 | 原受众以外评论附件/链接 |
| 作品恢复公开但无法核验旧评论受众 | 当前作品正文、可选“部分历史互动暂无法显示”（仅不会泄密时） | 假称全部旧评论已恢复或已删除 |
| 合法候选仍可看原V1快照 | 原有效合法V1 | 默认替换成V2 |
| 候选已失权但业务页仍合法 | 中性的资料当前不可查看状态 | V1敏感形象、Block原因 |
| 候选连业务页也无权 | 安全返回或隐藏入口 | 可识别历史关系/候选卡 |
| 用途撤销确认 | 当前用途已撤销的安全状态（本人仍有权时） | 不再被许可的派生正文、虚假的“全部删除完毕” |

## 5. 下一轮最小Owner审阅

1. **HIS-D1 A**：受众再次扩大时，历史评论及附件只有在**当前有权阅读作品且满足旧评论原受众**的交集范围内才可重新显示；不能核实时默认隐藏。
2. **HIS-D2 A**：旧匹配形象快照在既有候选仍合法有权时遵守O05方案A继续显示原合法版本；发生Block/收窄/必要许可撤销等失权时隐藏敏感快照。只有原业务页面仍有权时才可显示不泄密的中性状态；否则隐藏入口并安全返回。

**注意**：这些条款不决定实际留存期限、彻底删除、法定审计例外、技术缓存清理时效、旧候选改用新版或历史评论自动迁移。不能将两个A方案未经Owner确认写成正式合同。
