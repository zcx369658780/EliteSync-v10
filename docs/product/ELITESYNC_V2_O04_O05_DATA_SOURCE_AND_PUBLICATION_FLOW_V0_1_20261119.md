## 1. O04：资料真实来源和具名用途授权

### 1.1 四层概念（仅产品语义，不是数据库表设计）

1. **事实来源**：字段的真正含义、有效值/版本、来源和可能的纠错入口。不得混合“法定姓名/主昵称”“当前城市/出生城市”“生日/出生时刻”。
2. **用途许可**：该字段是否可以用于当前具名任务（如匹配必要资格、本人星盘计算、社交展示）；已存在不等于所有用途都允许。
3. **受众许可**：字段可以向谁显示及在何业务场景显示；匹配用途许可不等于向候选公开，社交可见也不等于匹配公开。
4. **发布版本**：本人正在编辑/预览的值不等于当前向外部提供的有效版本。业务授权与发布快照不得靠UI自动合并。

### 1.2 典型字段作用样例（示意，正式映射仍OPEN）

| 字段 | 事实用途区别 | 可能的具名用途 | 显示风险与界限 |
|---|---|---|---|
| 法定姓名 | 身份核验事实，不是展示昵称 | 未来真实身份核验（供应商未接入） | 不自动展示给候选/社交 |
| 主昵称、主头像 | 本人基础形象 | 本人预览、在许可下作为社交/匹配默认形象 | 默认继承只代表本人预览，非扩大对外可见性 |
| 当前城市 | 生活现居地，与出生地不同 | 当前匹配准备/具名资格 | 仅合法复用匹配所需字段，不自动公开精确位置 |
| 出生日期/时刻/地点 | 不同精度的个人事实 | 仅在当前具名授权下供占星等计算 | 不因输入存在自动传给候选或全部计算工具 |
| Lifestyle五场景答案 | 当前生活偏好而不是MBTI | Lifestyle探索、正式匹配准备 | 注册可跳过，参与真实匹配前完成；对外披露仍须单独控制 |

示例仅用于映射思路，不主张目前已有某个具体字段API、共享数据库表或默认授权状态。

### 1.3 从匹配准备缺项到完成的最短合法路径

`匹配准备（缺当前城市） → 打开该字段的权威编辑页 → 合法预填并按需申请当前用途授权 → 保存结果明确确认 → 自动返回原匹配准备并重新核实资格`

- 若已有有效当前用途授权与可靠值，直接预填/复用，不要求重复提交同一授权；授权缺失或被撤回，不悄然恢复，明确提示并由用户选择。
- 保存结果 UNKNOWN 时先只读查询权威结果，不自动重复提交；保存成功不等于核验PASS、自动报名、候选公开。
- 若从“我的”进入编辑，成功后回“我的”的原层级；从匹配进入则优先回匹配的原任务，不把两个入口做成两份字段来源。
- 来源纠错与撤销用途独立；撤销不默认删除所有源事实，也不暗中传播到其他用途。
- 非必要字段（例如可选星盘精确出生时刻）不能阻断已满足其他合法资格的匹配；真实身份核验未接入时，报名继续不可用。

## 2. O05：主形象、场景覆盖、对外发布版本

### 2.1 状态的可见区分

| 状态 | 用户看到 | 对外含义 |
|---|---|---|
| A 本人主形象编辑 | “主头像/昵称”与新的本人预览 | 使用主形象默认值的社交/匹配**本人预览**可以更新；已覆盖字段不受影响 |
| B 社交/匹配单独覆盖 | “使用主形象 / 单独设置”清楚标明字段来源 | 修改某一场景预览不自动影响另一个场景，不自动创建候选公开目录 |
| C 对外显示检查 | “当前已发布版本 / 待发布预览 / 谁能看到”分别展示 | 有效发布、受众、Block及用途许可决定当前可读范围 |
| D 明确发布确认 | 用户确认本次对外生效的场景、字段与受众 | 发布成功须以权威回执为依据；UNKNOWN不展示假发布 |
| E 撤回或更改受众 | 单独呈现撤回、收窄或扩大范围的后果 | 不自动撤销Connection/Consent，也不保证已留存的历史副本被物理删除；具体保留与效果须未来合同 |

### 2.2 推荐的最小操作流

**只修改本人预览**：
`我的 → 编辑主昵称/头像 → 保存并看到本人预览`；无需强迫用户发布新版本，不自动覆盖社交/匹配字段，也不扩展公开。

**需要对外更新**：
`我的 → 社交形象或匹配形象 → 对比待发布与当前发布 → 选择/确认当前允许受众 → 明确“发布更新” → 获取确切回执`。对外发布与主形象编辑是不同的用户意图，避免“保存=自动公开”。

- 建议预览阶段用两行清晰标签：“仅我可见的预览” / “目前对外生效的版本”，不用技术revision或UUID。
- 默认不勾选新的更大受众；扩大可见范围必须明显单独确认。
- 若某个场景头像或昵称已作独立覆盖，更新主形象时不得覆盖其字段；“恢复使用主形象”需用户主动选择后才改变该场景预览。
- 发布成功前后均遵守当前业务有效性、Block、场景权限与旧发布版本。对现有候选/历史展示是否自动同步新版本**不得在本方案中擅自推断**。

### 2.3 面向Owner的核心剩余取舍

**O05-X：已发布匹配形象更新后，对既有候选的展示版本如何处理？** 这是可能直接影响隐私与关系体验的产品政策，当前未冻结：

- **A（推荐）**：新发布版本默认仅面向未来新形成的合法候选展示；已存在候选继续遵守其原业务发布快照/权限。若需更新已有候选，须在支持该能力时单独明确确认。优点是防意外传播；代价是部分现有候选看到旧展示。
- **B**：新版本在所有当前仍有权的既有候选中同步生效，但保持原有受众边界。优点是一致；代价是可能意外更新已经被展示的信息，需更严格影响提示和验证。
- **C**：发布时逐次选择“仅未来候选 / 包含现有合法候选”。控制更精确但操作和理解负担较高。

这些是**候选交互选项**，不是Owner决定或已有后端能力说明。任何一种都不能追溯改变历史许可、自动公开已失权对象、自动替代关系决定。应先检查既有真实发布合同、已形成的候选快照与保留要求，再把选定规则转为实施合同。
