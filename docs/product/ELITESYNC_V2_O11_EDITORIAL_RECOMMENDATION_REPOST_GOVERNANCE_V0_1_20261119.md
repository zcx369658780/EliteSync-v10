## 1. 容易产生的权限误读

**用户把作品设置为`PUBLIC_AUTHENTICATED`，不等于准许平台把作品内容复制进访客可读的`PUBLIC_EDITORIAL`。**

如果在访客可见的“官方精选”中直接引用该作品的原图、视频、正文、评论或敏感昵称，就可能绕开用户原先只允许有效登录账号读取的受众边界；即使卡片旁边写着“用户精选”或“官方推荐”，也不能自动替代作者的许可。

对访客可读官方页面，应避免泄漏未获访客公开授权的用户作品元数据、缩略图、正文、评论、媒体链接及作者身份。

## 2. O11-D1｜官方精选与用户公开作品严格分域（顾问推荐）

建议在“首页 > 精选”中把两类内容清晰分为：
- **官方精选/官方专题**：平台自行创作或已具适当公开许可、允许访客读取的`PUBLIC_EDITORIAL`正文。官方专题仅指定场景开放登录用户评论；访客不读取评论区。
- **用户公开作品**：`PUBLIC_AUTHENTICATED`，只有有效且有权的登录账号能看到作品正文、缩略图、附件及相应受众许可的评论。

平台可以在**已登录、有权用户**的推荐界面给站内公开作品增加“编辑推荐”标识或排序权重，但这只是**指向当前受众受控的原作品**，不可通过编辑推荐把它复制为访客可读的公开内容。

推荐UI：
- 访客首页显示官方专题及官方精选，不展示用户作品可识别预览、评论或媒体；如有引导登录按钮，不得附带已受限的作品信息。
- 登录用户在同一“精选”频道内看到明确分开的“官方精选”与“用户公开作品”，避免制造第五个一级入口。
- 点击用户作品入口仍按当前受众/Block/版权与业务状态重新核对，权限变化时移除展示，旧缓存不得继续提供受控信息。

## 3. O11-D2｜平台转载用户内容需独立具名授权（顾问推荐）

“平台推荐原作品链接”与“平台把用户作品复制/重制/转载为官方可访客阅读内容”分开：

| 场景 | 权限建议 | 不可默许的行为 |
|---|---|---|
| 登录用户内部的“编辑推荐” | 推荐卡仍指向原受众受控作品，原作品更改/撤回时按当前权限更新 | 不把用户PUBLIC_AUTHENTICATED变成访客可读的PUBLIC_EDITORIAL |
| 官方专题引用用户作品 | 如果要向访客披露用户作品的文字、图片、影音、作者身份/昵称，需作者对具体素材、用途、目标受众及有效发布版本的**单独明确授权** | 不以作者将作品站内公开替代访客公开转载许可 |
| 已获准的转载快照 | 转载用途、目标受众、授权范围及撤回/变更处理规则须明确；平台原生文本和用户授权素材分开记录 | 不自动扩大评论附件、私聊证据或其他第三方作品的授权 |
| 作者撤回或收窄原作受众 | 平台推荐原作品入口应重新验权；授权转载快照如何撤回/保存另按具名授权合同 | 不默认假设所有已产生的复制件都能瞬间物理删除，也不继续无权新传播 |

本轮不预先确定法律条款、版权许可证措辞、收益分配和平台转载操作系统；这些属于Owner后续另行决定的产品/法律/运营边界。

## 4. O11-D3｜内容排序不以参与度最大化为默认目标（顾问推荐）

- 官方精选优先由**可追溯的编辑选择和专题时间/新鲜度**构成，而非未经说明的AI匹配评分、道德评分或刷屏增长算法。
- 用户公开作品可以先用简单、可解释的时间排序和人工精选标识；不得以私人身份、私聊、Safety/举报材料或玄学推断作为默认排名输入。
- 任何后续个性化、互动加权、AI筛选或自动重排，需要另行具名功能决定、数据用途授权及QA/内容治理审查。本方案不建立实际后台编辑员、审核员或推荐算法。

## 5. 建议的访客/登录对照

| 首页模块 | 未登录访客 | 当前有权登录用户 |
|---|---|---|
| 官方精选/专题正文 | 可以阅读明确开放的正文 | 可以按当前权限阅读 |
| 官方专题评论 | 不读、不发 | 只在当前授权的指定专题可阅读/互动 |
| 用户站内公开作品正文/媒体 | 不可读，不展示作品敏感预览 | `PUBLIC_AUTHENTICATED`范围内按当前服务端权限阅读 |
| 编辑推荐的用户作品 | 不以访客可读方式露出正文/媒体/作者身份 | 仅展示当前有权原作品入口 |
| 转载为官方内容 | 没有独立授权不得向访客展示用户素材 | 仍须按具体转载许可、受众及历史附件/评论边界判断 |
