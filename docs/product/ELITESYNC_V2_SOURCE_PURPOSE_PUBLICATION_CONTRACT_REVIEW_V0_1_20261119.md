## 1. 四层概念之间的必要隔离

| 层 | 用户要理解的事情 | 不可默许的跳步 |
|---|---|---|
| SOURCE 事实来源 | 当前有效的原始资料是什么、来自哪项本人输入/合法来源、纠正入口在哪 | 现居城市不能当出生地点，法定姓名不能当展示昵称 |
| PURPOSE 具名用途 | 这份数据被允许用于**当前这一项**任务或计算吗 | 已供身份核验使用，不等于获准用于占星、社交或候选展示 |
| AUDIENCE 当前受众 | 本人/好友/站内当前有权候选等谁能看到某个对象 | 允许匹配计算不等于允许向候选公开原始出生详情 |
| SNAPSHOT 已发布版本 | 哪些数据/衍生形象真正经本人确认对外生效、对哪些已形成候选可用 | 本人编辑或预览更新不自动覆盖旧候选版本 |

展示的“当前有权”应按实际账号、适用业务版本、Block及具名许可重新核验，不能因为数据已输入就自动认定新用途有权。

## 3. DATA-D1：首次跨具名用途复用时的最小授权确认（新顾问建议）

### 问题
某用户在“我的”曾填写了合法来源的出生日期，现在进入自我探索工具。值已存在，但该工具的**具名用途许可**是否有效与字段是否存在是两个问题。重复问用户生日会增加无谓输入；直接用旧字段计算又可能越过原用途。

### 推荐方案A（待Owner审阅）
- 如果当前具名用途已经合法有效授权，**直接复用**，不反复索要相同信息或同意。
- 如果值可信但**当前用途未经授权/已撤销**，页面只说明“可使用已有的哪些字段完成哪一项任务”，以**这一具名用途**呈现必要字段清单、当前授权影响和独立明确许可选择；用户可以拒绝、返回或按需修正来源值。
- 仅对当前任务**必要且有合法依据的字段**提出用途许可，不把“进入星盘”一键捆绑八字、紫微、匹配公开和社交展示，不预勾额外外显受众。
- 若该工具为可选功能，拒绝其授权不会自动阻断无关的内容浏览或其它已满足资格的匹配条件；若确为真实匹配必要资格，则准确显示“本项所需授权仍未满足”，不能因按钮外观虚构已完成。
- 权威回执确认后重读当前用途有效状态；UNKNOWN不自动重试；已撤回许可不可由后台预填偷偷恢复。
- **不在本设计阶段决定**最终每字段单独弹窗数量、授权记录schema、适用法域的真实同意依据和数据处理者合同。

备选B：每次跨工具直接复用所有已有资料，统一在全局隐私政策中说明，不提供具名新用途的选择。操作更少但破坏O04用途隔离，**不推荐**。

**与O04的差异**：O04已确认“具名用途复用合法资料”；DATA-D1新建议只细化**首次缺用途许可时的页面呈现与最小授权分组**，不是再次请求批准O04本身。

## 4. DATA-D2：事实纠错后，受影响的新对外发布应如何显示（新顾问建议）

### 问题
用户更正出生时间或其它来源事实，某个派生结果依实际依赖关系标为“需要核查”。既有O07已禁止自动重算/重发布，但**用户此时再主动准备向新受众发布依赖该旧结果的内容**，界面应如何处理尚需具体交互原则。

### 推荐方案A（待Owner审阅）
- 新外显内容**确实依赖已标为“需要核查”的派生结果**时，不能将该旧派生结果标注为“当前已验证有效”并直接发给新受众。明确显示“相关结果需核查”，阻断仅该**受影响**结果作为“有效新发布内容”进入外显，直到依真实用途、计算能力与版本完成合法核查/更新并由本人明确决定发布。
- 无依赖关系的其它有效字段/合法发布动作**不全局冻结**；不能用一个出生时刻纠错来锁死用户所有社交内容、好友关系、Conversation或独立合法用途。
- 对已有候选原有效快照，仍依O05/HIS-D2逐个核对当下权限；本建议不是自动删除旧快照、自动同步新版或解除已成立Connection。
- 不能因为“重新核查”这个词就假定后台具有计算接口、真实星盘提供者或一键刷新能力。若不能真正核查，只能保持受影响内容的待核查/不可新发布状态，提供安全返回或查看不受影响内容。
- 对外发布与本人编辑仍是独立明确决定，写入UNKNOWN先只读核权威结果。

备选B：任何来源更正后允许旧派生结果作为已确认的新内容继续外发，只附极小提示。操作更便捷，但可能让已知过时数据误导新受众，**不推荐**。

**与O07的差异**：O07已确认“纠错→相关结果需核查、不自动重算/重发布”；DATA-D2建议进一步明确**用户主动尝试新的对外发布时**受影响部分的可发布状态，未被Owner另外确认。
