## 一、已确认的前提

- 消息一级入口默认`聊天`，内部`聊天/通知`双频道，未读独立；当前有效待处理事项优先，普通通知按发生时间排列。
- 通知只是通向当前有权业务页的导航；每次回流重验账号、Block、受众、Connection/Consent及业务版本，不在旧卡片上直接履行高影响许可。
- 已读`READ`与业务待办`ACTIONABLE`互相独立；过期、撤销或无权的事项必须离开可执行待办区；有权可保留不泄密历史摘要，失权则隐藏敏感数据（A67-R2，Owner已确认）。
- 用途撤销与来源事实纠错不同；事实存在不能被推导为所有用途许可；对外受众和已发布版本仍独立。派生星盘/测评结果不自动被视为事实或匹配硬门槛。
- 一切错误稳态可退出、可留非敏感摘要，失权优先隐藏敏感内容；写入UNKNOWN先查权威结果再决定是否可安全重试。

## 二、O06 通知频道交互（顾问方案）

### 2.1 只分两个信息区

- **当前待处理**：当前有权、确需本人处理且服务端业务有效的事项；例如仍有效的匹配提案、好友申请、Buddy待处理申请。即使通知已读，仍属于待处理；只有业务完成、过期、撤回或失权，才从此区移出。
- **普通通知**：非待处理提醒及仍有权阅读的非敏感失效历史。默认按事件时间倒序，失效条目只能呈现“已结束/不可处理”之类安全状态，不能保留旧“接受”动作。未经授权不能显示对方身份、私聊或敏感预览。

### 2.2 建议的标读时机（待Owner决定）

建议采取**打开单条通知详情并实际呈现合法内容后，将这条通知标记为已读**；仅切换到“通知”频道、不自动把所有条目设为已读。可另提供用户明确触发的“全部标为已读”，但仍不会消除业务待办。
- 如打开详情的权限核验失败/失权，不能先把私密正文呈现出来；标读行为须遵守真实权限及失败状态。
- 旧通知进入当前合法业务详情后，本人仍需另行决定是否接受/拒绝，已读不能当成业务结案。

### 2.3 建议的待办内部排序（待Owner决定）

简化成“紧急期限明确者优先（需真实可核对的到期时间），其余按业务创建或变更时间倒序”，并避免使用未定义的“重要程度AI打分”。当没有可靠截止时间，统一按时间倒序，不虚构紧急性。保持低密度单卡一个下一步。

### 2.4 失效与留存

- 失效即刻离开可操作待办区，原则上不主动弹出大量解释。
- 若仍有权读取不敏感摘要，可在普通通知历史中看到“已失效/已撤回”，否则移除内容或以不会泄漏身份的占位态表示（展示策略未定）。
- 历史保留周期、通知合并/静默、标读批处理、是否需要显示一个失效占位仍OPEN；本稿不规定永久保留，也不把真实Push当成已可用。

## 三、O07 撤销用途/纠正事实后的派生结果（顾问方案）

### 3.1 两条独立操作

| 用户行为 | 即时产品表达（建议） | 不得假定 |
|---|---|---|
| **撤销某一具名用途** | 显示“已停止此用途的继续使用”——仅在撤销结果确切确认后；将受该用途限制的后续处理/新计算暂停，并重新核对相关派生结果的可见性 | 不等于自动删除所有原始事实、其他用途许可、旧安全记录或私聊许可 |
| **纠正原始事实** | 明确保存结果后告知“部分既有计算可能需要重新检查”，标注受影响结果的有效性等待核查 | 不等于自动重算全部星盘/八字、自动发布新版本、改变已成立的关系决定 |

### 3.2 建议的派生结果三状态

**VALID（当前可用） / NEEDS_REVIEW（输入变更或授权不支持当前用途，暂不可按原用途继续使用） / UNAVAILABLE（已按有效合同不可读取、已失权或尚未产生）**。这只是用户可理解的产品状态语义，**不指定数据库枚举或统一新服务**。

- 撤销用途或更正后，若某派生结果不再有合法当前用途，首先**停止该用途的进一步访问/计算/对外展示**，按现有权限合同隐藏受保护内容；不能为了保持历史图像而留在页面。
- 如果只是源事实变更导致计算陈旧，而当前仍有合法授权查看历史，可以用“需要重新检查”的脱敏状态提示代替继续把它当“最新有效”；是否显示完整历史结果取决于未来规则，不先作决定。
- 对外已发布结果、旧快照和第三方已有访问，需要依据受众、现有权利与后续撤回/更正合同分别处理，不能因为内部预览变化自动全局更新或自动保留可访问。
- 重新计算只在资料足够且具名用途当前有效时允许，不默认以撤销前的权限进行；失败保持真实UNKNOWN/UNAVAILABLE。

### 3.3 建议的用户界面路径

`我的 → 隐私与授权 → 选择具体用途 → 查看影响摘要 → 确认撤销 → 得到确切结果`。摘要只说明此用途和当前预计影响，不虚构历史删除已经完成；未知结果先查询。

`我的 → 个人资料 → 纠正事实 → 保存成功 → 显示哪些依赖计算需核查`。用户可选择以后再处理；可选计算不能自动变成Match硬门槛；重算和未来发布另需各自有效授权。

### 3.4 O07尚需未来合同明确

- 撤销后派生历史结果的实际保留/删除、法律/安全记录留存约束、受众快照是否及何时撤回、独立用途并存时怎样重用同一事实、重新计算对历史版本的影响、跨设备缓存处理和通知是否需要触发。
- 具体历史权限及动作需Owner与后续工程审查，不可用顾问表格代替数据流/真实API证据。
