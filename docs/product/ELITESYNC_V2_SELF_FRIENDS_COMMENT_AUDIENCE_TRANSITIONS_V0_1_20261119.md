# EliteSync V2｜SELF / FRIENDS作品受众与评论权限联动 V0.1

日期：2026-11-19（Asia/Singapore）  
状态：`ADVISOR_PROPOSAL / OWNER_REVIEW_PENDING_FOR_TRANSITION_RULES / DESIGN_ONLY / CODEX_NOT_AUTHORIZED`  
前提：[Owner SELF 默认评论澄清](../decisions/OWNER_V2_SELF_COMMENT_DEFAULT_CLARIFICATION_20261119.md)、[O01默认FRIENDS与O02历史受众](../decisions/OWNER_V2_O01_DEFAULT_COMMENTS_O02_MEDIA_REFERENCES_20261119.md)、[S15发布前影响摘要](../decisions/OWNER_V2_S15_D1_S16_D2_ACCEPTANCE_20261119.md)。

## 0. 不应再次混淆的两个独立控制

- **作品受众（谁可以读）**：`SELF`只有作者本人可读；`FRIENDS`是当前有权好友及作者；`PUBLIC_AUTHENTICATED`是当前合法登录且有权的用户，并非匿名访客。
- **评论策略（具备阅读权的谁能评论）**：`OFF / FRIENDS_ONLY / ALL_ELIGIBLE`。评论始终受限于**当前阅读权限∩作者设置评论权限∩账号有效∩Block/其它适用业务限制**。
- 逻辑上，给SELF作品配置FRIENDS_ONLY也**不能**让好友看到作品正文或允许好友评论；如果希望好友交流，就应该把作品受众设为FRIENDS。
- 已冻结：普通新作品默认`FRIENDS + FRIENDS_ONLY`；陌生人默认不能评论，有权好友可评论。`SELF`是作者主动选择的仅自己可读特例，默认`OFF`。从FRIENDS扩大到PUBLIC_AUTHENTICATED不自动把FRIENDS_ONLY扩大为ALL_ELIGIBLE；历史好友评论与附件引用原权限不升高。

## 1. 精简的“可阅读 × 可评论”状态矩阵

| 当前作品设置 | 有权好友能看到正文？ | 有权好友可评论？ | 非好友登录用户可评论？ | 访客可阅读/评论？ |
|---|---|---|---|---|
| 新作品默认FRIENDS+FRIENDS_ONLY | 可以，需符合当前好友与Block条件 | 可以 | 不可以 | 都不可以 |
| SELF+OFF（本轮范围内已确认） | 不可以 | 不可以 | 不可以 | 都不可以 |
| PUBLIC_AUTHENTICATED+FRIENDS_ONLY | 可以 | 可以，仍需符合当前评论条件 | 不可以（可读不等于可评） | 都不可以 |
| PUBLIC_AUTHENTICATED+ALL_ELIGIBLE（作者另外明确选择） | 可以 | 可以 | 只有当前有权且未被Block等限制才可评论 | 都不可以 |
| 任意受众+OFF | 仍由作品受众决定 | 不可评论 | 不可评论 | 都不可以 |

上表仅为概念权限矩阵，实际好友关系认定、历史评论可读范围、媒体签名链接和服务端实现需未来独立验收。

## 2. 作者改变受众时：新一轮顾问候选规则（尚待Owner审阅）

### CMT-T1：新建时选择SELF，之后改为FRIENDS

**推荐A（低操作成本、尊重显式选择）**：

- 作者主动将一篇只自己可见的作品扩大为FRIENDS时，发布前可见性摘要清楚显示“改为好友可见；评论建议仅好友”。
- 如果该作品的`OFF`只是**系统因SELF特例提供的隐式默认状态**，而作者未主动选择关闭评论，则可在同一确认中明确呈现`FRIENDS_ONLY`作为新受众的推荐评论设置，作者可以改为OFF；不得暗中修改他明确设置的OFF。
- 如果作者此前**明确主动关闭评论**，则继续保持OFF，并在可见性摘要里清楚告诉作者好友可以看，但当前无法评论，若希望好友交流可手动开启FRIENDS_ONLY。
- 不新增默认让所有站内登录用户评论；从SELF到FRIENDS是作品受众扩大，必须由作者明确确认，不能因主形象/预览编辑自动发生。
- 上述是否能区分“隐式默认OFF”和“作者明确OFF”取决于将来字段/版本合同，现阶段不能假定后端能识别。**如果无法区分，就安全保留OFF并显示清楚提醒，由作者自愿开启好友评论**，不自动覆盖旧偏好。

**备选B（更保守）**：SELF改为FRIENDS始终维持评论OFF，作者必须另行开启。减少权限意外扩大风险，但可能让用户误以为所有作品默认关闭评论。

### CMT-T2：FRIENDS或PUBLIC_AUTHENTICATED改为SELF

- 必须明确确认收窄作品受众。之后任何好友/陌生人都不可读取作品，也不能继续评论；在SELF期间界面可以显示“仅自己可见 · 他人不可评论”。
- 这**不是**自动删除历史评论/附件、替第三方撤销或授权，也不是永久保存的承诺。旧评论在服务器保留/删除及再次扩大受众后谁可读，由独立历史合同决定。
- 为了将来安全恢复，可考虑区分“当前有效可评论性”和“先前作者明确设置的评论偏好”，但不假设现有数据库有对应字段。
- 不通过通知、媒体缩略图、缓存、分享预览泄露已收窄作品或评论。

### CMT-T3：FRIENDS扩大到PUBLIC_AUTHENTICATED（已获Owner明确确认）

- 作品新受众需本人明确确认；当前评论`FRIENDS_ONLY`保持不自动扩大。
- 历史好友评论正文/媒体/附件/引用不因作品受众扩大而自动变成所有有权登录者可读。无法隔离时限制不安全的扩大公开。
- 新有权读取作品的非好友登录用户**可以阅读当前有权作品**，但默认无评论权限；作者以后可主动选择`ALL_ELIGIBLE`，也不追溯扩大历史评论已确认受众。

## 3. 最简发布/修改UI候选（设计建议）

每次发布前只显示必要的两行：`谁可以阅读：仅自己/好友/站内有权用户`；`谁可以评论：不可评论/仅好友/当前有权用户`。

如果受众或评论权限**真的改变**，明确给出将生效范围摘要并让作者确认；不堆砌技术枚举。不将`FRIENDS_ONLY`误读为“好友无需作品阅读权也能评论”。若涉及历史评论保护或无法实施的受众隔离，则增加安全提醒并按既有S15-D1阻断不安全公开。

两个情境可展示：
1. “好友可见；仅好友可评论”——普通新作品默认，用户无需另开评论；
2. “仅自己可见；他人无法查看或评论”——SELF特例；切换“好友可见”时才能讨论好友评论。

## 4. 需要保留的未决内容

- SELF下作者是否可自评/留笔记、是否显示已过往评论历史（仅在仍有合法阅读权时）；
- 默认评论“隐式/显式”标记的真实存储、旧作品迁移、受众多次切换与历史快照；
- 后端能否安全隔离历史评论受众、附件/引用/通知/分享预览、临时媒体URL和Block变更；
- 评论权限变更是否允许影响**新评论写入**而不扩大旧评论阅读范围，既有历史作者同意的法律/产品合同；
- UI具体按钮/布局/无障碍与动态QA、真实V2内容域部署状态。

## 5. 本轮建议Owner只裁决一个新细节

**CMT-T1（推荐A）**：作者主动把SELF作品改为FRIENDS时，如果之前OFF只是系统SELF隐式默认、未被作者显式关闭，则在发布前摘要中建议并明确展示FRIENDS_ONLY；作者主动关闭过则保持OFF，不替作者取消其决定。若未来工程无法区分隐式默认和显式OFF，保守保持OFF并提示作者可手动启用好友评论。作品受众变化仍须由作者明确确认。

这可以实现Owner强调的“默认不让陌生人评论，好友仍能交流”，同时避免给SELF内容偷偷新增阅读权限。此为**顾问新建议、尚未获Owner确认的切换规则**。
