## 0. 目的和读取依据

目标：在不新增未经Owner认可的内容权限、删除承诺和工程接口前提下，将已经独立确认的[NEW-PC-01](../decisions/OWNER_V2_NEW_PC01_COMMENT_AUTHOR_WITHDRAWAL_OPTION_A_DIRECTION_ACCEPTANCE_20261119.md)、[NEW-PC-02](../decisions/OWNER_V2_NEW_PC02_AUTHOR_CONTROL_THIRD_PARTY_COMMENT_DISPLAY_DIRECTION_ACCEPTANCE_20261119.md)、[NEW-PC-03](../decisions/OWNER_V2_NEW_PC03_INITIAL_OBJECT_LEVEL_DELETION_REQUEST_ENTRY_OPTION_A_ACCEPTANCE_20261119.md)与[RET-D1/D2](../decisions/OWNER_V2_RET_D1_D2_REVOCATION_DELETION_CONCEPT_ACCEPTANCE_20261119.md)、[OBJ-D1](../decisions/OWNER_V2_OBJ_D1_POST_TAKEDOWN_THIRD_PARTY_COMMENTS_ACCEPTANCE_20261119.md)、[HIS-D1/D2](../decisions/OWNER_V2_HIS_D1_D2_HISTORICAL_ACCESS_AND_SNAPSHOTS_20261119.md)、[CMT-T1](../decisions/OWNER_V2_CMT_T1_SELF_TO_FRIENDS_COMMENTS_20261119.md)对齐。

本稿是**静态权限语义整理**；表内“动作”意味着产品意图或有证据时的合法行为，不意味着API、数据库、后台审核或APP实际存在。未经明确批准的UI行为只记`ADVISOR_PROPOSAL / OPEN`。首次V2工程任务仍未授权。

## 1. 权限主体 × 作用对象 × 动作 × 可说的事实

| ID | 权限主体与目标对象 | 独立动作与当前已确认的概念 | 什么时候允许表示操作成功 | 不能暗示/不得扩大 |
|---|---|---|---|---|
| C01 | **作品作者 / 本人作品** | 受众收窄、改SELF、撤下：停止对失权用户的正文及依附受控内容展示（OBJ-D1、HIS-D1） | 受众/撤下的权威事实确认后，只表述受众变化 | 不自动删除第三方评论原件/合法留存，不使旧媒体/缓存公开 |
| C02 | **作品作者 / 本作品下他人的评论** | 隐藏评论在**本人作品内的展示**（NEW-PC-02，Owner方向接受） | 必须具备当前合法身份/业务权利与权威操作结果，实际能力`NOT_CHECKED` | 不能代评论者永久删除、篡改或扩大第三方评论原受众；安全证据/申诉仍独立 |
| C03 | **评论作者 / 本人评论** | 撤回本人评论的当前**对外展示**（NEW-PC-01 A，Owner方向接受） | 权威结果确切确认后才可向相关有权受众称撤回；UNKNOWN只读核验 | 不自动删除自己/他人原始记录与合法独立回复，不改作品受众 |
| C04 | **作品作者 / 本人作品数据** | 首期优先**规划**独立的对象级删除申请入口（NEW-PC-03 A），与C01独立 | 真实合法请求被权威受理后才可说“已受理”，核实指定范围删除后才可说“已完成” | 规划入口≠存在受理API；不能代评论者删除其独立原件，也不假称所有备份清空 |
| C05 | **评论作者 / 本人评论数据** | 首期优先**规划**独立删除申请入口（NEW-PC-03 A），与C03不同 | 同C04：受理与实际完成分别取得真实对象级证据 | 不把撤回展示当删除请求，也不对他人回复自动执行删除 |
| C06 | **合法权限主体 / 具名用途许可** | 在有权且有真实能力时，独立撤销当前具名用途许可（RET、DATA、O07） | 当前权威撤销成功后才显示该用途已撤销 | 不自动清除其它合法用途事实或全部历史，不将撤销与删除请求捆绑 |
| C07 | **当前有权读者 / 作品及旧评论媒体** | 读取必须符合当前作品读权 ∩ 评论原受众 ∩ Block/其它适用权限（HIS-D1） | 每次有权且原始边界可核实时显示；无法核实则隐藏 | 作品扩大到PUBLIC_AUTHENTICATED也不自动公开旧好友评论、附件或引用 |
| C08 | **平台具备相应合法权限的处理主体 / 必要安全/申诉与数据记录** | 可能需要独立合法的举报、处理、保留及复核；具体后台规则仍OPEN | 只能根据真实合法处理回执与范围说明结果 | 作品作者或评论作者的展示控制均不可伪称已删除必要安全记录或全局所有副本 |

注：C02/C03的实际“隐藏”和“撤回”作用于何处，回复树、引用、通知、媒体URL、作者本人视图、审核视图的差异**仍为OPEN**；表格只说明已确认的业务边界，不能把它当成详细权限状态机。

## 2. 应避免的常见混用

| 用户意图 | 产品表达允许的最小事实 | 不允许的替代说法 |
|---|---|---|
| “我不想让其他人再看我的作品” | 有权撤下/改变受众并取得权威结果后，陈述谁还可看 | “所有评论、缓存、历史记录均已永久删除” |
| “我不想在我的作品里展示这条评论” | 本作品内第三方评论展示管理权（NEW-PC-02方向），真实行为待证 | “我已删掉评论者原件、照片和申诉证据” |
| “我撤回自己写的这条评论” | 评论作者的当前对外展示撤回（NEW-PC-01方向） | “连其他人回复、引用的独立内容都被删除” |
| “请删除我的这条作品/评论数据” | 首期规划合法对象级请求，实际受理/完成只有真实回执才可描述 | “点击请求即已受理或物理删除完成” |
| “我撤销星盘/匹配等特定用途许可” | 当前有权确认的用途撤销，仅限该用途 | “自动清除所有源资料、其它用途数据和安全证据” |

## 3. 顾问发现的仍OPEN：不因此制造新Owner拍板负担

| 风险束 | 本次可以明确的安全默认 | 需等待的依据 |
|---|---|---|
| 隐藏/撤回后的回复树、引用、通知、恢复、申诉 | 不扩大原受众；失权内容隐藏；不冒充删除第三方内容 | `PRODUCT_CONTRACT_OPEN`；后续详细交互/合法例外和实际能力 |
| 删除受理与完成、合法期限、媒体/缓存/备份 | 没有权威回执就不能显示受理或完成 | `LEGAL_OR_EXTERNAL_FACT_OPEN / ENGINEERING_EVIDENCE_REQUIRED` |
| 评论作者身份、作者管理权范围、权限版本与写入UNKNOWN | 只读核当前权威事实，无法核验则保守返回，不重放高影响操作 | `ENGINEERING_EVIDENCE_REQUIRED` |
| 已公开作品的新受众与历史评论/附件 | 不自动扩大旧受众，无证据不重显 | 旧记录/媒体的原始受众、真实权限和迁移证据 |
| 账户级数据权利与旧匹配快照 | 不能以本次首期规划排除实际合法权利，也不能借发表新形象默认升级旧候选 | 适用法律/数据处理合同、后来独立Owner范围决定 |

**建议**：NEW-PC-01/02/03三项核心概念现已具名确认，避免再要求Owner整体批准本矩阵。下一阶段可把具体OPEN归入**依赖证据**或未来精确UI合同；只有真的新增独立管理权、合法重大取舍或批准解除工程STOP，才再次请求Owner具名决定。
