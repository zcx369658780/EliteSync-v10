## 1. S09 消息：聊天与通知

| 字段 | 逐屏检查建议 |
|---|---|
| PURPOSE | 打开消息页时，首眼聚焦有权聊天；切到通知才查看当前仍有效的待办与其他提醒 |
| CURRENT_STATE | `聊天/通知`两个频道、默认聊天且未读独立；通知分“当前可操作待办”和“普通通知”，已读≠业务已处理 |
| PRIMARY_ACTION | 在聊天频道进入有权会话；在通知频道进入**当前有效业务的详情**作本人决定，不从旧通知卡片直接接受 |
| SECONDARY_ACTIONS | 切换频道、返回、查看仍可合法阅读的失效历史、必要拒绝/撤回/权限说明 |
| AUTHORITY | 当前账号、双方当前Messaging Consent、Connection、Block、通知所指业务有效版本；失效通知只显示当前仍有权的安全摘要 |
| RETURN_PATH | 从通知进入业务详情并完成或取消后，安全返回当前账号有权的消息入口；原通知已失效时不恢复原可执行按钮 |
| RECOVERY | 通知单条详情实际合法打开后才标该条已读；UNKNOWN时只读查权威结果；切号、失权、迟到请求或旧深链不泄露内容 |

**已确认**：通知待办真实有效截止时间优先、其余按业务时间排序；普通通知事件时间排序；真实Push未接入；当前权限可保留非敏感失效摘要，但不能无限保留失权正文。

### S09-D1 新建议（待Owner审阅）：消息业务回流保留安全上下文

从`消息 > 通知 > 当前有权事项详情`进入其它页面后，用户处理完或取消，**优先回到当前账号的“通知”频道及安全可恢复的列表位置**，不把用户无故送回聊天首页；但必须先重新核对账号、业务和列表项目可见性，旧通知过期/Block/切号时只能回安全列表或合法首页，不能复活原敏感预览或旧按钮。

这是一项**导航回流偏好**，不是恢复不再有权的数据/滚动缓存的授权。实际列表位置持久化、同一待办合并去重与系统Back实现仍OPEN。

## 2. S10 我的：首页与资料/工具/权限入口

| 字段 | 逐屏检查建议 |
|---|---|
| PURPOSE | 一眼看到本人主形象预览及可管理的资料、偏好、自我探索、社交与内容、隐私授权、账号设置 |
| CURRENT_STATE | 主头像/主昵称及本人默认形象预览；社交和匹配形象独立覆盖、当前用途许可及对外版本有明确区分 |
| PRIMARY_ACTION | 当前本人任务是编辑基础资料/形象时，直达对应权威来源编辑，不把所有权限当同一页面主按钮 |
| SECONDARY_ACTIONS | 我的偏好/Lifestyle、自我探索（MBTI/星盘/八字/紫微）、好友与Buddy（同一导航分组但关系独立）、内容/草稿/收藏、隐私授权/Block、安全设置 |
| AUTHORITY | 当前登录账号的资料来源/已确认版本、用途和对外受众；不可把展示昵称误认法定姓名，也不把已输入出生事实默认公开 |
| RETURN_PATH | 从我的进入资料编辑，确切保存后回我的原分组；从Match进入同一权威字段编辑则优先回原匹配任务 |
| RECOVERY | 编辑UNKNOWN先只读查结果；退出/切号隔离旧内容与草稿；隐私撤销实时阻断失权展示，不能复制旧缓存 |

**已确认方向**：Me顶部个人资料卡；自我探索聚合各独立工具；好友与Buddy放在“社交与内容”导航分组但保持业务与权限独立。具体分组数及卡片排列仍OPEN。

## 3. S11 形象本人预览、场景覆盖与对外发布

| 字段 | 逐屏检查建议 |
|---|---|
| PURPOSE | 让用户分清“本人修改头像昵称”和“把社交/匹配形象发布给他人”是两件事 |
| CURRENT_STATE | 当前主头像昵称、各场景是否复用/覆盖、本人待发布预览、对外已发布版本与现行允许受众 |
| PRIMARY_ACTION | 本人预览模式突出“保存本人修改”；对外发布模式突出“确认发布此场景版本” |
| SECONDARY_ACTIONS | 查看当前已发布版本、合法的取消/返回、管理受众、主动恢复使用主形象；不能默认更大范围 |
| AUTHORITY | 当前资料来源/版本、具名用途、场景受众、当前有效发布快照及Block。O05方案A：新匹配形象默认仅供未来合法新候选使用 |
| RETURN_PATH | 本人修改成功回Me预览；已确认对外发布后回到相应场景的发布状态；从Match发起的编辑按原任务安全回流 |
| RECOVERY | 发布UNKNOWN先只读核查，不能显示假发布；撤销/收窄受众即时按当前权限移除失权内容；不能把本人预览更新当已对旧候选推送新版 |

### S11-D2 新建议（待Owner审阅）：发布前“影响摘要”而非重复权限向导

在用户从本人预览切到“对外发布”时，提供一眼可读的**待发布内容与当前生效版本差异**，并在确认按钮附近简明说明“发布到哪个场景、当前有权受众、匹配形象默认只影响未来合法新候选”；对已有候选不得用“立即同步全部”作为默认选项。发布需要一次具名明确确认和权威结果回执，但**不要要求用户在未改变已有合法授权时重复填写原始资料或重复同意同一用途**。

这里的“影响摘要”是UI文案/比较层级提案，不改变O05方案A，不批准任何既有候选主动同步能力、存储结构或默认更大受众。

## 4. S12 资料用途撤回、事实纠错与派生结果

| 字段 | 逐屏检查建议 |
|---|---|
| PURPOSE | 用户清楚分辨“撤销某项用途授权”与“改正原始事实”；不是一个全局数据删除开关 |
| CURRENT_STATE | 当前确切用途许可、资料来源有效版本、依赖变更输入的派生结果是否需要核查；无权内容立即隐藏 |
| PRIMARY_ACTION | 当前任务是撤销具名用途则确认撤销；纠错任务则保存权威源值（两个任务不合并成一键） |
| SECONDARY_ACTIONS | 事前查看影响范围、返回、稍后处理需要核查的可选派生工具、合法历史状态摘要 |
| AUTHORITY | 当前资料字段事实、独立用途授权、派生结果输入版本、已发布版本与有权受众；事实存在≠继续使用合法 |
| RETURN_PATH | 撤回确认后回授权管理；纠错成功后回原资料/发起业务并显示需核查结果；不自动重算/更新对外发布 |
| RECOVERY | 撤回或写入UNKNOWN先核权威状态；无权派生正文、媒体与历史快照必须脱敏；保留/删除依合法合同且未定，不虚构全部历史已清除 |

**S12与O07已确认关系**：用途撤销后停止不再被许可的后续计算/阅读/外显，纠错只使受影响的结果“需要核查”，不影响其它合法用途；实际历史删除/重算流程与审核留存仍OPEN。

## 5. S09–S12跨页审查实例（仅未来QA提纲）

| 代表路径 | 期望概念行为 | 禁止的误判 |
|---|---|---|
| 通知已读但好友申请尚有效 | 留在当前待办，进入详情由本人决定 | 已读即隐藏/自动接受 |
| 打开通知旧提案→被撤回→返回通知 | 受控安全历史摘要或隐藏 | 恢复旧提案操作按钮与对方私密资料 |
| 通知→合法待办详情→取消→消息 | 优先回当前账号通知频道、安全列表位置 | 强制回聊天顶层或跨账号旧滚动数据 |
| Me改主头像但匹配独立覆盖存在 | 本人默认字段预览更新，独立覆盖不变 | 自动改变匹配已发布版本 |
| Me匹配形象明确发布新版 | 默认只影响未来合法新候选 | 旧候选自动收到新版或将原权限扩大 |
| Me改出生时刻→星盘仍有许可 | 依赖结果标需要核查，不自动重算/公开 | 把旧结果立即当新结果或真实匹配硬门槛 |
| 撤销某用途时跨设备有旧结果 | 当前不再允许的读取隐藏，受限操作阻断 | 为留证保留已失权派生正文 |
| 发布/反馈写入UNKNOWN | 只读核查业务状态，不盲重放 | 假成功/重复发送 |

未来QA应按D/I/N/A/W及字体放大、读屏、减少动效、Back、账号切换，逐项报告证据的PASS/FAIL/NOT_RUN/UNKNOWN。本稿全部只是`NOT_RUN`范围提纲，不得称动态测试通过。
