| 区域 | 固定审计中已见现象 | V2简化目标 | 分类 | 重要边界 |
|---|---|---|---|---|

## 3. 第一批建议继续讨论的“最小化 UI 简化”设计包

按 **不需要先确定新增外部供应商、能够清楚对照旧版现象** 进行组织；这是顾问优先顺序，不是下发Codex的执行任务。

### P1：先减少视觉负担和误读（重点参考U05/U10/U11/U12/U14）
- 把用户可见的技术字段替换为清晰状态和人类可读说明，调试编号仅留在受控详情/证据层。
- 长页内容不再被底部导航或键盘遮挡；只有一个高权重当前主操作，拒绝/撤回/返回保持可见。
- 通知卡从“多个等权按钮”变为“当前状态+一项查看操作”；不在列表卡上直接同意提案、Connection或消息许可。
- 统一淡绿／淡蓝／灰青底色与深青主操作，减少纯白、高饱和红、大片无关装饰；带图Lifestyle保留五场景与三选项。

### P2：重新组织已有业务入口（重点参考U02/U03/U04/U07/U09）
- 首页用户任务从“看个人状态”改为“看有权内容”；**是否需要新增后端内容源**必须另行标记，不能用空卡片假装有正式平台编辑内容。
- 匹配准备首屏仅显示当前可补的必要条件、真正不可用的外部依赖，以及可合法操作的下一项。
- Me顶部个人资料卡；自我探索集中不同测评/盘工具的导航，避免同一工具在两处出现不同生效状态。
- Buddy权限关闭时给唯一授权入口，不使用户先退出再到处寻找设置；权限开关不能被悄悄开启。

### P3：需要功能或权限合同先成熟的部分（暂不视为纯UI工作）
- 官方公开精选/访客阅读、有效用户公开作品与评论受众。
- 实人核验供应商、回执、失败恢复、重试和真实报名门禁。
- 跨来源字段映射与用途授权，编辑后的派生数据失效/对外发布版本。
- 真实Relationship对象选择、来源/资格与双方独立确认。
- 通知待办排序、标读时机、失效通知分组和Push等尚未确定事项。

## 4. 四个入口的一眼用途与操作预算（顾问建议）

| 一级入口 | 首屏一眼目的 | 当前主操作示例 | 不应该重复出现的东西 |
|---|---|---|---|
| 首页 | “看看有什么内容” | 浏览官方精选、在授权下切好友 | 大量匹配技术状态、未登录可互动控件、重复内容入口 |
| 匹配 | “我现在离参与匹配还差什么 / 需要作什么决定” | 继续当前必要准备，或在具备真实资格时作本人决定 | 星盘硬门槛、假核验按钮、并列的五个主按钮 |
| 消息 | “与允许聊天的人交流 / 看还有什么待处理” | 进入有权会话，或点通知查看当前业务详情 | 把已读当同意、通知直接替人作高影响决定 |
| 我的 | “管理我自己及授权” | 进入唯一资料/形象编辑位置 | 同一个生日/地点到处要求重填、本人预览=对外发布的误导 |

**操作成本仍按 D（必要业务决定）、I（输入）、N（额外导航）、A（系统自动工作）、W（等待）分别衡量。优化优先压低N与不必要I，不牺牲D。**

## 5. 未来对齐验证的最小样例（目前均未在V2运行）

1. 首屏可用一句话说出任务；高亮行动不遮挡文字、没有冒充可用的外部服务。
2. 已登录用户从首页进入匹配时，一份当前服务端事实驱动所有匹配入口；访客作品/媒体无越权。
3. Lifestyle只完成2/5且实人核验不可用时，能补未完成题但不能报名；不会出现真实提案。
4. 从匹配补城市：只补合法必要字段，保存后回原任务；失败不假成功，不自动报名或扩大对外资料。
5. 已读但未处理通知仍在有效待办区；过期通知不能再次执行旧操作。
6. 双方Connection有效但任一方消息许可缺失：不会生成可写Conversation；独立撤回必须有效。
7. 登录切账号/Block：前一账号缓存不泄漏，当前页面重新判定授权。
8. Android动态字体、系统减少动态效果、低亮夜间阅读、长文本/安全区等需要未来实测，不能用静态概念图称PASS。
