# EliteSync V2｜A6.6 跨页面状态一致性与恢复（顾问设计 V0.1）

日期：2026-11-18  
状态：`ADVISOR_PROPOSAL / OWNER_REVIEW_PENDING / NO_IMPLEMENTATION_AUTHORITY`

## 目标

用户在账号切换、通知回流、网络结果未知、资料编辑返回、权限撤销等情况下，看见的始终是**当前有权访问、当前业务有效**的状态，而非过期的本地缓存或上一个账号的结果。

延续已认可的 A6.5 原则：异常页面**稳定，便于截图与复制安全问题摘要；返回路径明确，不强迫用户重试**。但当账号、Block 或权限发生变化时，应立即隐藏失权数据；稳定保留的仅是安全的错误说明，而不是私人内容。

## 五个独立代表状态

| 画面 | 触发条件 | UI 当前真实信息 | 主操作 | 退出/安全约束 |
|---|---|---|---|---|
| 01 账号切换 | 当前账号发生变化 | 上一账号会话/候选/通知/草稿不再显示；当前账号状态待重读 | 进入当前账号首页 | 旧账号异步请求回包不得写入新账号UI；保留安全返回 |
| 02 旧通知回流 | 深链通知对应的事项过期、撤回或不再有权 | 该事项当前不可处理，旧“接受”操作移除 | 返回通知列表 | 通知仅为导航；目标重新检查服务端业务有效性、受众及Block |
| 03 写入结果未知 | 超时或断网，尚不知服务端是否成功 | 「结果尚未确认」，不冒充成功或失败 | 检查当前结果 | 先查状态/请求幂等事实后才能安全重试；提供复制安全摘要和返回 |
| 04 编辑返回匹配 | 从匹配准备编辑某项必要资料后，收到确切保存成功 | 回原匹配任务并刷新资格；示例仍为Lifestyle 2/5、实人核验未接入 | 继续生活方式探索 | 返回不等于自动报名、不自动发布资料；如果未获确认不得标为保存成功 |
| 05 查看中权限被撤销 | 账号注销登录、Block、受众/消息许可变化等 | 私密正文、个人身份及失权媒体立即隐藏；安全错误摘要可保留 | 返回安全页面 | 可复制无敏感摘要和正常退出；不可为截图继续保留失权内容 |

各屏为**互相独立的场景示例**，并非同一个账号、同一个轮次或一条连续成功旅程。图中假设的城市保存成功、Lifestyle 2/5只是具体示例数据，必须按真实服务端事实渲染。

## 建议的跨页面状态更新顺序（顾问方案）

1. **身份优先**：先确定当前账号与会话；一旦切换，旧账号私密视图立即清空，拒绝旧异步响应回填。
2. **权限先于展示**：对深链、旧通知、会话/媒体、关系提案等重新核对当前权限，失权的私密内容不得继续呈现。
3. **结果先于下一步**：写入超时只表示 UNKNOWN；查询到有效权威结果后再决定是否可继续、回退或重试。
4. **保存成功才刷新**：跨页资料编辑有确切确认后返回发起任务并重新读取资格；不自动产生报名、Connection或Messaging Consent。
5. **稳定异常与安全留证**：显示固定、安全、可复制的错误摘要和返回路径；不承诺持久草稿、自动上传日志或真实错误编号。

## 未来可验证的检查场景（未执行）

- QA-A 已打开候选/通知，切至 QA-B：立即隐藏 QA-A 信息；QA-A 延迟响应不得污染 QA-B 页面。
- 通知已读但待办仍有效：打开通知重验后由本人决定；通知已过期或被撤回时，不能执行旧按钮。
- 资料更新 PUT 超时但服务端已成功：界面不能盲重发重复写入，应先获取当前结果/修订并按既有幂等合同处理。
- 匹配补当前城市成功：返回原 Match 准备并刷新当前资格；原场景未完成和核验供应商未接入等状态保持真实。
- 正在查看有权Conversation时消息许可撤回或发生Block：停止读写、移除已失权私密正文，并允许安全地返回/复制无敏感摘要。
- 每个异常页：横竖屏、系统 Back、字体放大、屏幕阅读器、减少动态效果、退出/反馈入口等须将来专项验证，不凭静态图判断PASS。

## 既定业务边界

Match、Connection、Messaging Consent、Conversation、Relationship继续独立；访客不提交站内反馈；实人核验真实供应商未接入，不能启动真实匹配报名。A6.5 所提错误留证不构成保存未授权私密数据的许可。
