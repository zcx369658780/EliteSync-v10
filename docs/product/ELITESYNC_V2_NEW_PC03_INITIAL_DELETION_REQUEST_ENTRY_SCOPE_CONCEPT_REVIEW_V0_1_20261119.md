# EliteSync V2｜NEW-PC-03：首期删除请求入口与对象范围——顾问概念审阅V0.1

日期：2026-11-19（Asia/Singapore）  
状态：`ADVISOR_PROPOSAL / NEW_PC03_OWNER_REVIEW_PENDING / EXTERNAL_AND_ENGINEERING_GATES_OPEN / DESIGN_ONLY / CODEX_NOT_AUTHORIZED / A6_MEETING_DEFERRED`

## 0. 只需Owner选择的产品问题

当用户需要管理自己的作品、评论和其他资料时，**V2首期在APP产品设计中应优先规划哪些可达入口**？

已获Owner接受：
- [NEW-PC-01方案A](../decisions/OWNER_V2_NEW_PC01_COMMENT_AUTHOR_WITHDRAWAL_OPTION_A_DIRECTION_ACCEPTANCE_20261119.md)：评论作者可撤回本人评论的**当前作品内对外展示**。
- [NEW-PC-02方向A](../decisions/OWNER_V2_NEW_PC02_AUTHOR_CONTROL_THIRD_PARTY_COMMENT_DISPLAY_DIRECTION_ACCEPTANCE_20261119.md)：作品作者可管理本人作品内第三方评论展示，**不因此删除他人原件**。
- [RET-D1/D2](../decisions/OWNER_V2_RET_D1_D2_REVOCATION_DELETION_CONCEPT_ACCEPTANCE_20261119.md)：具名用途/受众撤权、删除请求获得**真实受理**、指定范围**核实完成删除**三种语义绝不混用；对象、主体、用途与合法例外分别判断。
- [OBJ-D1](../decisions/OWNER_V2_OBJ_D1_POST_TAKEDOWN_THIRD_PARTY_COMMENTS_ACCEPTANCE_20261119.md)：作者撤下作品不代表永久清理第三方评论及必要留存。

**本题不要求Owner裁定实际保留天数、数据处理法域、物理删除能力、现有API是否存在或已实现状态。**

## 1. 方案A｜首期优先规划作品/本人评论的对象级申请入口（顾问推荐）

- **本人作品**：在当前合法可访问的作品管理位置，清楚区分“收窄受众/撤下作品”（展示管理）和“请求删除本人作品的指定数据”（请求行为）。后者只有在真实合法受理机制存在时才允许确切提交/查询受理，不能生成假成功。
- **本人评论**：保留已接受NEW-PC-01的“撤回对外展示”语义；如需申请物理删除本人评论相关数据，是**另一条独立请求**，不从撤回动作自动推导出删除请求已受理或永久删除完成。
- **具名用途与许可**：已有有效权利下的用途撤销/范围管理在相关授权管理入口单独提供，与删除原始资料或独立合法记录不默默捆绑。
- **未具备受理能力时的真实替代**：仅向用户说明目前可验证的合法请求途径、撤权/撤下可用性和限制；不做无后端的假按钮、假受理编号或假时间承诺。若有适用法律要求账户级删除、导出或数据请求渠道，应按其真实权利与义务提供，不得用“首期未开发APP表单”作为拒绝处理的理由。
- **分期边界**：账户级删除/导出、跨用途资料、旧匹配快照、安全/第三方素材、备份与媒体等精确入口及处理规则，需要后续依据适用法律、真实权限和工程证据另议。分期不是永久免除适用权利义务。

**利弊**：用户可以区别“隐藏、撤回、申请删除”，减少误操作；但真实受理链/副本清理/申诉能力较复杂，需要在工程阶段再核证。**方案A是首期规划优先级，不是已上线承诺或工程任务。**

## 2. 方案B｜首期只依赖确实可用的撤权/撤回与合法现有请求渠道

- 不在APP里优先规划对象级删除申请/进度追踪新功能；产品仍提供已证实可执行的作品撤下、个人评论展示撤回、用途许可撤销（若现实系统具备），其余请求遵循届时合法可用的独立渠道。
- 法律规定必须提供的数据权利行使渠道仍须真实可达，不能因为APP没有按钮而排除用户。
- 不创建假删除API或未被授权的账号删除界面。

**利弊**：设计及系统依赖较少，但用户需跨入口理解“撤回展示”和“删除请求”的区别，过程不够自然，未来可能返工。

## 3. 推荐仅确认的范围与尚待证据

**推荐NEW-PC-03方案A作为首期产品规划方向**，但严格附带条件：
- 本次只确认首期产品设计**优先考虑**“本人作品数据删除请求、本人评论数据删除请求”的对象级入口，与其展示撤回/受众收窄操作明确区分；
- **何时可以激活提交按钮**须依真实合法受理机制、有效身份/对象权利、回执与UNKNOWN只读验证；尚无机制时必须显示真实限制或实际合法请求途径，不能假装系统有能力；
- 任何账户级删除/导出与数据保留权利若受适用法律约束，不得由分期建议替代合法判断；
- 后端表/schema、平台运营/审核、保留期、备份/缓存处理、申诉、跨设备传播、QA及正式上线均未授权/未核。

若Owner仅选择A的**方向**，下面仍保持`OPEN / EXTERNAL_DEPENDENCY_OPEN / ENGINEERING_EVIDENCE_REQUIRED`，不创建研发任务。
