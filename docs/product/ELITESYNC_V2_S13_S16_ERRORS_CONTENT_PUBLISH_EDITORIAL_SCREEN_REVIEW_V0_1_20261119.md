## 1. S13｜写入结果UNKNOWN及合法反馈

| 检查字段 | 顾问逐屏审查内容 |
|---|---|
| PURPOSE | 用户一眼看到“这次操作结果尚未确认”，知道下一步只能核查当前真实结果 |
| CURRENT_STATE | 区分服务端已证实成功/已证实未成功/UNKNOWN；超时不等于失败，另一设备新画面不等于权威成功回执 |
| PRIMARY_ACTION | `检查当前结果`：在当前账号有权的前提下只读查询权威业务事实/版本；不能查时继续UNKNOWN |
| SECONDARY_ACTIONS | 安全返回、复制非敏感错误摘要、当前有资格登录用户主动反馈；可明确放弃当前页面，不能借退出推断操作已撤销 |
| AUTHORITY | 当前账号、具名业务权限、服务端真实状态/版本、既有幂等事实；无法核实时不得显示已受理/已同意/已发布 |
| RETURN_PATH | 若确认完成则回原任务并重读当前状态；未完成且幂等/授权均允许时才出现明确安全重试；UNKNOWN仍可安全退出 |
| RECOVERY | 网络/后端/账号异常保持稳定脱敏状态，不自动重复提案接受、形象发布、授权、反馈附件或其他高影响写入 |

**既有Owner已确定**：UNKNOWN先只读查状态、不盲重试；安全摘要不能夹带私聊正文、原日志、他人身份等；未授权访客不能提交站内反馈。完整幂等查询API是否存在仍OPEN。

## 2. S14｜失权、切账号、Block、旧通知或深链

| 检查字段 | 顾问逐屏审查内容 |
|---|---|
| PURPOSE | 说明当前为何不能继续查看/操作，同时保护失权内容与安全退出 |
| CURRENT_STATE | 区分“当前内容已失权”“当前账号无效/登出”“暂无法核验访问权限”，三者不能混为相同状态 |
| PRIMARY_ACTION | 已失权→`返回安全页面`；权限未知→`检查当前访问状态`（仅有权时）或安全返回；账号无效→受控登录/恢复 |
| SECONDARY_ACTIONS | 可复制不泄密摘要；内容失权但账号仍有效且合法时可主动反馈；无账号资格不可站内反馈 |
| AUTHORITY | 当前账号、Block、作品/会话受众与有效发布版本、独立Messaging Consent及业务版本；缓存不是授权证明 |
| RETURN_PATH | 落到当前账号有权首页/通知或登录恢复入口，系统Back不能重新出现已失权旧视图 |
| RECOVERY | 账号切换立即隔离旧账号私密导航/媒体/草稿，拒绝迟到回填；旧通知只导航并重验，失效事项不可执行旧动作；无法核验时安全占位 |

**既有Owner已确定**：安全、稳定、可退出且失权立即隐藏；内容失权≠整账号无反馈资格；不承诺零延迟跨设备传播或永久离线访问。

## 3. S15｜用户作品与评论受众编辑、确认发布

| 检查字段 | 顾问逐屏审查内容 |
|---|---|
| PURPOSE | 让作者清楚“这篇作品会被谁看到、谁能评论、是否会扩大过去内容可见性” |
| CURRENT_STATE | 新作品默认受众`FRIENDS`、评论`FRIENDS_ONLY`；作者可主动设`SELF/FRIENDS/PUBLIC_AUTHENTICATED`及`ALL_ELIGIBLE/FRIENDS_ONLY/OFF`（须满足现有业务限制） |
| PRIMARY_ACTION | 审阅当前拟发布受众后明确发布/保存；扩大受众不能默默更改评论策略 |
| SECONDARY_ACTIONS | 返回编辑/草稿、查看受众及评论设置、取消/放弃、安全处理未保存内容 |
| AUTHORITY | 当前作者、作品有效版本、各评论的历史受众、附件/媒体/引用各自的合法许可、Block/账号有效性 |
| RETURN_PATH | 发布成功后回自己有权作品详情/作品管理；若发布UNKNOWN则只读查版本后再更新；不会自动创建公开个人Profile或聊天资格 |
| RECOVERY | 作品从FRIENDS扩大到PUBLIC_AUTHENTICATED时历史好友评论及附件/引用/缩略图不自动升权；不能可靠隔离时限制不安全扩大并提示，不靠旧媒体URL绕过 |

**仍OPEN**：`SELF`作品评论默认或是否允许设非OFF（先不把默认OFF当Owner决定）；旧评论作者许可与迁移策略、附件实际URL失效、删除/留存时限，尚需具名合同。

### S15-D1｜本轮顾问新建议（仅待Owner审阅）

**将作品受众和评论范围放在同一发布前“可见性摘要”中，默认只展开最重要的当前值；当用户主动从FRIENDS扩大到PUBLIC_AUTHENTICATED时，单独提示“历史好友评论及附件/引用不会随作品公开，评论范围仍保持当前设定”，需要当前作者明确确认这一受众变化。** 如果未来系统不能保证历史内容隔离，禁止将不安全发布呈现为成功；不用重填未变化、已合法授权的作品资料。

这只是可见性摘要与最短确认路径建议，**不批准任何新的历史评论自动变更机制**，也不替评论作者扩大许可。

## 4. S16｜官方精选/专题、用户作品推荐与官方转载

| 检查字段 | 顾问逐屏审查内容 |
|---|---|
| PURPOSE | 让访客/登录用户明白看的是官方公开正文，还是仅登录后可阅读的用户原作品 |
| CURRENT_STATE | `PUBLIC_EDITORIAL`官方正文仅明确开放的部分访客可读；`PUBLIC_AUTHENTICATED`用户作品仅当前有权登录用户可读；访客不读官方专题评论 |
| PRIMARY_ACTION | 打开有权正文或用户原作品；若是内部编辑转载任务则按具名许可流程进行，不冒充普通用户可随意转载 |
| SECONDARY_ACTIONS | 切精选/好友、登录/注册、内容返回；官方专题登录用户按实际条件讨论，普通精选不默认开放评论 |
| AUTHORITY | 官方原创/合法访客公开许可、用户作品当前受众与Block、编辑推荐只指向原作品；将素材转载为PUBLIC_EDITORIAL必须另有作者对素材/用途/受众/版本的明确许可 |
| RETURN_PATH | 返回原合法首页频道；用户内容收窄或撤回后，推荐入口不保留原失权缩略图 |
| RECOVERY | 失权即隐藏，访客/匿名深链不可读站内用户作品；第三方历史评论/附件/引用不得借编辑推荐或官方转载扩大公开 |

**既有Owner已确定**：官方/用户作品分域、具名转载授权、内容初期可解释排序，不默认参与度最大化；真实编辑账号角色、审核流程、转载条款、授权到期及历史快照处理仍OPEN。

### S16-D2｜本轮顾问新建议（仅待Owner审阅）

首页“精选”频道对**当前有权登录用户**用清晰的“官方专题 / 用户作品（含编辑推荐）”来源标识，点“编辑推荐”仍只进入受众受控的**原作品**；访客端仅呈现合法官方正文，**不放置会泄漏用户昵称/缩略图的半遮盖用户作品卡片或带敏感预览的登录诱导**。在需要正式转载许可的内部流程中，明确区分“推荐原作品入口”与“获作者具名授权后复制/转载为官方内容”，不能让同一个“推荐”按钮自动完成转载授权。

本提议只确定**来源标识与动作分流**，不批准后台审核、版权条款、排序算法、实际编辑角色或新的用户公开目录。

## 5. 四屏交叉检查场景（未来QA提纲，均NOT_RUN）

| 场景 | 有效行为 | 禁止表现 |
|---|---|---|
| 对外发布/反馈提交超时 | 显示UNKNOWN→只读核查真实状态 | 自动重新提交或伪造成功 |
| 私聊阅读中消息许可撤回/Block | 移除私密正文与媒体，安全返回；有资格时安全反馈 | 为截图保留受限正文/媒体 |
| 切账号后旧通知深链返回 | 当前账号权限优先，旧私密响应不回填 | 自动接受旧账号申请或显示历史敏感卡 |
| FRIENDS作品扩大站内公开 | 作品变更需作者明确确认；旧评论及附件仍按原受众 | 把旧私密评论、缩略图或直链一起公开 |
| 编辑推荐用户站内公开作品 | 有权登录用户仅进入原受控作品 | 访客看到受限预览，推荐自动升级官方PUBLIC_EDITORIAL |
| 官方要在访客专题转载用户照片 | 必须单独取得针对素材/用途/受众/版本的合法明确许可 | 以“作者曾站内公开”替代访客公开转载授权 |

未来正式验证要逐项记录`PASS/FAIL/NOT_RUN/UNKNOWN`、D/I/N/A/W与字体放大、读屏、减少动效、系统Back、安全区等证据。当前仅顾问文档，**没有新的运行时测试**。
