## 1. 单一UX流程：先权利与事实，后展示和安全返回

所有入口遵循：**当前账号核验 → 当前作品/评论权限和受众/Block → 评论展示控制来源与权威结果 → 对仍有权对象显示最小内容和合法操作 → UNKNOWN先只读查询 → 无法证明则安全返回**。

权利交集优先于作者的管理界面偏好；禁止通过旧缓存/通知/媒体直链恢复失权内容。EDGE-D1仅在独立回复合法可读且不泄密时保留，EDGE-D2仅在评论作者自身有权且无敏感推断时显示中性状态。评论隐藏、撤回、删除申请受理、删除完成仍为不同事实。

## 3. 统一文案候选与恢复优先级

| 意图/状态 | 简短候选文字 | 风险与准入 |
|---|---|---|
| 本人看到评论展示受限 | “这条评论当前不在原作品中展示。” | 只有合法历史访问权、不会泄漏关系时；不能断言“作者已隐藏你” |
| 无权限/断网无法核对 | “当前无法确认查看权限，请稍后再试。” | 不出现任何敏感缩略图、昵称、Block线索 |
| 父评论无法展示、回复合法独立 | “这段讨论中的部分内容暂不可显示。” | 如占位会泄密则直接折叠，不显示占位 |
| 显示撤回已确切完成 | “已停止展示这条评论。” | 仅权威确切确认后；不声称数据已永久删除 |
| 删除申请无法受理 | “当前未提供此处直接申请，请查看现有合法申请渠道。” | 仅实际渠道存在时可链接；不要伪造 |
| 结果UNKNOWN | “暂时无法确认结果。” | 允许只读查询；禁止自动重发或显示成功 |

单次操作恢复顺序（顾问目标）：**身份/权限重验 → 查询当前权威事实 → 合法状态/返回；若仍UNKNOWN保持UNKNOWN**。不让用户反复确认独立已获准的基础资料，但也不合并评论撤回、作品隐藏、删除请求等不同权利。

## 4. 本批可合并处理而非继续拆门禁的细节

- **UI**：评论树占位样式、空态密度、返回位置、读屏顺序、字体放大、未读与业务待办分离，可在之后正式A6会议/获得权限时一并细化；目前为顾问候选。

- **工程**：查询身份、权限版本、数据结构、幂等、请求回执、跨设备传播、历史媒体签发、原43 PNG真实性等，将来另获Owner授权后合并验证，不因本稿启动Codex。
