# EliteSync-v10 当前工作方式

生效依据：2026-10-12 Owner 工作流迁移决定。本文仅保存长期角色、冻结、独立验收与安全边界；不记录具体版本或当前任务状态。实时状态见 [CURRENT_STATE](../../CURRENT_STATE.md)，版本验收与集成状态见 [版本登记](../versions/README.md)。

1. Owner 保留目标取舍与方向决定。同一 ChatGPT 项目中的网页 GPT 6 Astra 是长期管理者：负责路线图、版本计划制定/审议、最终独立验收和每版本偏差复盘。旧 Work 停止实时管理，不转 Dot。
2. Codex 是 Owner 指定会话的版本实现负责人。版前 Astra 给目标草稿，Codex 根据真实代码、当前测试、历史接受与环境反馈可行性；集中解决实质分歧，再冻结正式版本。版前按实际必要的范围区分 `ALREADY_ACCEPTED`、`IMPLEMENTED_NOT_ACCEPTED`、`REJECTED_NEEDS_CORRECTION`、`LOCAL_ONLY_UNVERIFIED`、`MISSING`、`PAUSED_OR_PROTECTED`、`UNKNOWN`，优先复用确已接受且仍适用的成果，避免重复开发。这是现有版前协商内容，不新设全面历史审计或中途审批门。
3. 正式版本冻结目标、范围、验收标准、关键科学/产品契约和已接受限制，登记冻结提交。Astra、Work、Codex均不得因执行不理想追改本版计划。路线图仅为未来版本更新。计划错误保留原件，必要时结束本版、另立后续版本。
4. 范围内的实现顺序、内部拆解、相关代码/测试、普通调试及修复由Codex自主调整。失败优先进入诊断、修复、重测循环；不用逐步骤批准或反复请求继续。保留有效测试、原始失败和实际验证，不为绿色结果降低标准。
5. 真正缺必要决定、越权、未授权不可逆操作或持续无进展/额度与环境阻碍时，保存状态并报告。会话交接续接原版本，不重新立项。旧暂停任务不因本迁移恢复；旧冻结预算和拒绝原件不复活。
6. 完成后集中提交候选代码身份、实际验证证据和剩余问题。Astra对照原冻结标准读取真实实现，批量反馈原目标内缺陷；修复续接同版，新需求/纯优化进入后续版。**Acceptance Status 与 Integration Status 分别记录**：独立验收不等于主线集成。集成还须分清 **GitHub 指定主线的具名 Git 对象已纳入 / 本地脏工作树已安全对齐 / 集成后目标代码已实际重测** 三种可独立取证的事实，不能互相推定；准确核验代码父基线、已有未提交成果和相应授权，不自动 merge/pull/rebase。Codex自测通过不等于最终验收，开发验收不等于生产发布。
7. 每版通过、部分完成、失败或终止都记录原因与证据，区分执行偏差、计划遗漏/错误、环境阻碍、验证不足、验收漂移。顺手记录可核实的起止时间、集中返修、人工阻碍和额度；未知写 `UNKNOWN`，不建自动监控或永久固定测试门禁。保留真实失败、stdout/stderr/退出码；**向 GitHub 发布前按需识别自动诊断日志里的本机路径、网络/设备清单及可能的凭据信息**，在安全本地保留原始字节、远端仅发布完成具名验收所需的安全原证或脱敏副本，标记证据层级/遗漏，绝不伪装失败消失或回写篡改已冻结历史原证。代码格式与 raw 证据完整性分开判断。
8. GitHub用于版本文件交换、代码定点集成、必要证据发布及备份，不是微步骤审批总线。冻结前尽量核对文档中的**真实路径和固定 Git ref**；冻结后发现仅导航/链接错误，以具名勘误纠正，不追改冻结计划/验收门。无顾问自动轮询、自动插单、实时监督、后台监听或自动调度。GitHub备份不代替生产数据、凭据及真实资产保护。

## 版本验收后的安全集成与本地基线（2026-10-13 Owner 长期授权）

Owner 已明确批准：**未来每个版本独立验收并关闭之后，默认接续“已接受成果的安全集成 → 本地可用开发基线对齐”，再提出下一版规划**；这项顺序与有界安全处理办法无需每版重复征求方向批准，但**不构成后台自动任务、越过人工派发、扩大已接受范围或覆盖脏主树的授权**。

- **远端代码整合**：Astra 对固定 accepted candidate 与 GitHub 真实 main 的共同父提交、路径差异和每个拟纳入 Git Blob 进行定向核实。只有来源已接受、无冲突、能保留正式冻结计划/原始验收/拒绝及现有主线成果时，才可将**必要代码/测试/有限复现对象**定点纳入 GitHub main 并回读。整支 merge/cherry-pick、自动取用未经接受的 LOCAL_ONLY、合并私密原始日志均不是默认动作。问题超出安全范围则停下报告。
- **本地可用基线**：Owner 通过既有手动消息给 Codex 安全对齐任务；Codex 先准确比对远端已集成对象与本地 HEAD、默认 index、dirty tracked、untracked 及受保护成果。优先在独立的干净 worktree/等效隔离路径建立**从固定新 main 开始**的开发基线，再有界识别需要携带的旧本地独立成果。不得因为同名而盲拷、默认执行 `pull/reset/rebase/clean/stash`、删除旧 worktree 或覆盖原 root。若能在不侵入原 root、且没有身份或权限冲突的条件下完成独立基线，可在 Owner 手动派发的本任务内自主实施；发现需取舍的两份有效不同内容、不可逆风险或正式代码/数据/环境权限变化则停止相关写操作，保留证据等待 Owner 决策。
- **三个事实独立登记**：`GITHUB_MAIN_SCOPED_CODE_INTEGRATED`、`LOCAL_DEVELOPMENT_BASELINE_READY`（须指明实际本地路径、提交和已验证源集合；这**不等于** `ORIGINAL_DIRTY_MAIN_RECONCILED`）、`POST_INTEGRATION_RUNTIME_VERIFIED`（需实跑具名目标套件；未跑记 `NOT_RUN`）。即使新隔离 worktree 已可开发，原 `D:/EliteSync-v10` dirty main 仍可合法保持未对齐；不能把“新开发基线可用”冒写成“所有 LOCAL_ONLY 成果已吸收”。
- **默认收口**：在独立验收和远端代码集成后，优先安排同一版本的有界本地基线接续与必要直接回归；不另立版本、不为普通 Git/测试错误新增审批，也不自动启动下一产品版本。GitHub 连接不能直接触碰 Windows 文件，需 Codex 的实际回执确认；不得仅凭远端 SHA 宣称本地已对齐。

本长期授权**不解除** BE-12 消息默认拒绝、V57/H1/H2/D0 暂停、真实数据/生产/密钥/部署/SDK升级或其他受保护操作；Owner 仍负责真正有争议/不可逆的决定。

## 权威关系和边界

本规则替代当前入口中的纯流程冲突：旧Work/dot规划派发终裁职责、逐步STOP/单次读写/普通失败关窗、固定计数交接门、强制新增审查角色或多模型循环等不作为未来版默认要求。已有冻结版本的科学/产品语义、验收依据、证据身份、历史接受/拒绝与已耗预算原样保留。按变化风险做必要实际检查，不把旧版本所有测试复制成每次任务清单。

保留隐私、真实数据与授权数据边界；未授权的科学计算/正式实验、生产DB/API/SSH、凭据、真实备份恢复或删除、部署发行、重要资产删除、环境/依赖升级及UAC不因流程迁移放开。Match、Connection、Conversation、Relationship的分域与独立同意、消息权限、信息生命周期等以已接受原契约为准。旧EliteSync不能覆盖v10；第五章与DeepLearning-HANK均不属本项目，人口/人均恢复不构成劳动经济单位或完整数值桥确认。
