## 五、功能逻辑链盘点范围

至少梳理以下用户旅程；如某旅程在当前候选不可用，明确写出停止位置和原因：

1. 注册/登录/首次使用；
2. Lifestyle探索、跳过、完成、修改及与匹配资格的关系；
3. 社区浏览、内容详情、互动、发布及受众控制；
4. 个人资料、出生信息、匹配输入与隐私设置；
5. 匹配准备、参与、轮次、候选、提案及用户决定；
6. Match → Connection → Messaging Consent → Conversation → Relationship各自的独立链条；
7. 消息、站内通知、通知回流和权限重验；
8. Buddy发现、筛选、活动申请、创建人确认及退出；
9. MBTI与星盘/特色工具的输入、计算、结果、历史与分享；
10. 自动化授权、任务状态、暂停、恢复、撤销及提醒；
11. 账号切换、冷启动、缓存隔离和会话恢复；
12. 账号/隐私/权限说明及用户退出路径。

每条逻辑链尽可能记录：
- 起点和触发条件；
- 当前页面、路由及下一页面；
- 用户实际输入/点击；
- 系统自动执行的步骤；
- 是否要求用户确认、授权或等待；
- 读取的数据来源及权威状态；
- APP调用的API/route；
- 可核实的后端Controller/Service及数据库实体/表；
- 最终持久化结果和页面反馈；
- 空状态、失败、未知、拒绝、撤回和恢复路径；
- 当前操作步骤数、重复输入和页面跳转；
- 证据文件/代码路径；未能核实的部分写`UNKNOWN`或`NOT_TRACED`。

不得仅凭页面文案推断后端能力；不得把Widget/fixture/模拟回执说成普通用户真实业务链。只追踪与用户操作直接相关的关键路径，不做全仓代码考古。

## 六、Owner目标流程对照（只分析，不实现）

将下列Owner构想作为“目标流程假设”与当前实现逐项比较：

`注册 → 首次探索/人格总结 → 首页以社区内容为主、可免费浏览互动 → 用户主动选择参与匹配 → 实名认证入口（当前只允许占位，不得接真实供应商）→ 在用户明确授权后复用/预填姓名、生日、出生地点等已有资料 → 基于可用出生信息自动生成星盘等特色工具 → 进入匹配流程`

必须分别标明：
- 当前已经真实实现；
- 当前存在但入口分散/需要重复输入；
- 当前只有占位或未接真实供应商；
- 当前尚未实现；
- 需要Owner决定的产品规则。

特别注意：
1. 当前B1五场景Lifestyle Discovery不等于MBTI测试，不得将其描述为已生成MBTI人格类型。
2. 当前已有MBTI功能与Lifestyle偏好是不同功能，分别盘点其入口、输入和输出。
3. 实名认证真实供应商未接入，不得生成真实核验成功状态。
4. 姓名、生日、出生地点复用/预填及跨模块读取必须标注授权与字段用途；不能把用户填写一次理解为对所有用途的永久授权。
5. 自动生成星盘是Owner提出的目标方向，必须核对当前工具实际输入流程；不得把现有手动录入误写为自动生成。
6. 匹配、Connection、Messaging Consent、Conversation、Relationship继续分离；减少操作不意味着删除必要决定。
