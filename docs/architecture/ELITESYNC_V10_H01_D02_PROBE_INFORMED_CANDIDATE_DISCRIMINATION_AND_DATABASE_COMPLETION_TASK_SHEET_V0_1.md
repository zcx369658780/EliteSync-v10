## 7. Deterministic tokenization

Comparison uses ASCII-only deterministic tokens while the artifact retains the original bare identifier exactly.

For an identifier:

1. require `[A-Za-z_][A-Za-z0-9_]*`;
2. split on one or more underscores;
3. within each part split before an uppercase ASCII letter when preceded by a lowercase letter or digit;
4. split an acronym before its final uppercase letter when that letter is followed by a lowercase letter, so `HTTPClosure` becomes `HTTP`, `Closure`;
5. split letter/digit boundaries;
6. discard empty tokens and lowercase using invariant ASCII rules;
7. compare whole tokens only.

A matching token is exactly `close` or `closure`. Substrings such as `disclose` do not match.

URI and route-name tokenization first splits on every non-ASCII-alphanumeric separator, then applies the same camel/snake/digit rules to each segment.
