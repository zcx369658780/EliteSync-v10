## 4. Frozen H-01 identity, track, scope, and sixteen semantic clauses

### 4.1 Frozen H-01 identity and track

| Field | Exact frozen H-01 value |
| --- | --- |
| Purpose | Preserve a participating User's agency by ending the exact reciprocal Connection when that User no longer consents to continue exploring communication, without asserting relationship outcome or person meaning |
| Feature | Participant-initiated respectful closure of one existing reciprocal Connection |
| Environment | One existing reciprocal Connection in the current pre-alpha MVP product-policy context; this is not a runtime, deployment, production, or platform claim |
| Population | Either User who is a participant in that exact reciprocal Connection |
| Information class | One `User-authored` consent/control choice: that participating User's Connection-closure choice |
| Lifecycle | Starts when that User issues the closure choice; it stops future optional continuation under that exact Connection authority. It does not rewrite prior receipt or another person's independent authorship, and it creates no automatic reopening/reversal authority |
| Harm/control path | Harm is unwanted continued communication or false presentation of continuing reciprocal consent. Either participant may close the affected Connection; ordinary continuation stops for that affected scope, dependent ordinary effects are withdrawn or invalidated where governed, block/report remain distinct, and any Safety matter follows restricted minimum-necessary routing without guilt, punishment, reputation, or global person/account meaning |

Frozen track:

`API`

Accepted semantic-design scope:

`H-01 / API / cross-boundary closure-intent and closure-effect semantic contract only`

### 4.2 Frozen semantic clauses

The future review and every later mechanism artifact must reproduce and preserve these clauses byte-for-byte. They may not be revised, shortened, broadened, reordered for priority, combined, qualified away, converted into a target, or reinterpreted by technical convenience.

| Clause ID | Exact accepted semantic clause |

| SC-02 | Either participant in the exact reciprocal Connection has independent authority to author closure intent for that Connection without reciprocal agreement. |
| SC-03 | Closure intent affects only the one exact reciprocal Connection to which the authoring User's choice applies. |

| SC-05 | Future optional continuation under the affected Connection is not authorized once the authoring User's Connection authority is absent. |

| SC-07 | Closure does not revise, recall, or promise erasure of prior receipt that occurred before closure under then-current authority. |
| SC-08 | Closure does not revise the other person's independently authored information or transfer that person's meaning authority to the closing participant or product. |
| SC-09 | Closure creates no automatic reopening or reversal authority for either participant, the product, or a derived ordinary effect. |
| SC-10 | Closure, block, and report remain three distinct meanings; closure meaning is neither block meaning nor report meaning, and block meaning is not report meaning. |
| SC-11 | Ordinary closure is neither Safety evidence nor a Safety finding and creates no allegation, guilt, punishment, or verified-misconduct meaning. |
