# EliteSync v10 功能后端与集中 UI 路线图

版本：2.0。路线日期：2026-11-13（北京时间）；当前状态更新：2026-11-14。  
依据：[Owner最新决定](../decisions/OWNER_V10_1_5_CLOSEOUT_AND_BACKEND_FIRST_20261113.md)。  
本路线替代2026-10-19路线图的未来版本划分、运营展望和阶段执行安排，不重写历史实现与验收。

## 一 产品终点与实施顺序

整个v10完成一个功能完善、可持续使用的开发产品：统一APP、真实产品API、持久数据库、必要独立Web管理面板。先完成各业务功能和最小可操作界面，再集中打磨UI、信息结构与文案。v10不安排公司注册、真实内测、收费、真实线下运营或正式发布，也不以版本号到达某点自动触发这些工作。

“后端真实”按实际业务链判断，不按是否使用Docker判断。正常APP/Web操作必须产生真实持久状态；虚构账号可用于验证，夹具或受控响应不能冒充最终用户流程。既有Laravel/MariaDB/WS/SFU开发架构继续复用，不为功能落实另造后端或迁移环境。

普通功能版需要足以完成操作的界面、错误反馈和输入保留；整体布局、视觉风格和文字统一集中在v10.1.12。全局UI后置不意味着保留假按钮、不可操作页面或假成功提示。

## 三 v10.1.12范围说明

按“我的/设置 → 消息/聊天 → 首页/进展 → 匹配/社交/特色工具 → 必要独立Web页面”推进。先选代表性页面与共享组件建立规则，再扩展关键页面。优先改善清晰度、一致性、可读性、可操作性和状态反馈，不追求装饰性动效。

不新增大型业务，不重写API/数据库合同，不改变匹配算法、账号安全、隐私受众、关系状态、消息/媒体/RTC权限。必要功能缺陷可在同版修复并定向验证。相识后破冰、约见、共同计划、纪念日继续只留接口。

## 四 执行与交付方式

Codex在当前稳定目录和既有会话自主拆解，每版连续完成后端、持久化、必要管理端和APP消费端，再集中交付。普通修复、必要开发库迁移、定向验证、Debug APK和双模拟器沿长期授权，不逐动作请示。仅新增改动、失败或具体风险扩大验证。

每版提供简洁实施报告和必要候选身份，说明用户功能、实际运行链、检查、未完成项与最小后续动作。功能声明按实际软件链判断，不按页面数、接口数或测试数。同步失败记PENDING_SYNC，保护本地成果。

当前工作流见[CURRENT_WORKFLOW](../workflow/CURRENT_WORKFLOW.md)。本路线不授权main合并、手机、生产/真实数据、新供应商或费用、内测、运营或正式发布。
