## 二、v10.1.17 / 阶段B3正式授权

Owner授权v10.1.17「全APP低操作成本重构与功能整合」。

### 产品目标

以用户目标而非页面/模块数量重组Home / Progress / Messages / Me。整合匹配、社交、搭子、消息、特色工具，减少重复入口、重复填写、无意义确认、跨页面查找状态和失败后的重复操作。

用户只需表达意愿，系统利用B1偏好与B2状态/自动化完成已授权的准备、计算、整理和执行。涉及隐私、资料分享、匹配接受、消息同意、Connection、Relationship和不可逆动作仍由用户明确决定。

### 目标信息架构方向

- **Home：首页**：一眼看到本人当前状态和最重要的下一步；优先复用B2 `/api/v1/user-state`及其`next_actions`，不另造推荐/资格真相；社区和搭子作为可选的有限入口，不把首页变成无限Feed。
- **Progress：进展**：围绕本人慢约与关系旅程组织准备、生活方式、参与/自动化、轮次、提案、Connection、Messaging Consent、Conversation和正式关系。各状态仍独立，不把它们压成一个模糊的“关系进度”。
- **Messages：消息**：集中管理当前账号有权访问的会话与沟通入口；通知可以有清晰入口，但不得与聊天消息或消息同意混为一谈。
- **Me：我的**：集中个人资料、偏好、隐私/分享、账号安全与可选特色工具；避免重复放置状态中心、准备状态、生活方式探索和自动化的多套入口。

默认保留当前四个底部主入口；只有交互审计有证据证明其他安排更清楚且不增加用户负担时才调整，不新增第五个底部主入口。

### 交互目标

- 普通导航、查看、草稿保存和可恢复低风险操作尽量直接完成，不增加无意义确认；
- 已存在且权威的资料/偏好在适当场景安全复用，避免重复填写；用户可查看和纠正；
- 自动保存/恢复只在现有安全存储和业务合同允许范围内实现；
- 每个主要页面有清晰的当前状态、主要动作及可理解的结果；
- 保留明确的隐私、分享、身份、匹配选择、消息同意、连接、正式关系和不可逆动作确认；
- 权限按用途触发，不在首次进入时一次性请求所有Android权限；
- 不以点击数最少为唯一目标，必须兼顾可理解性、可撤销性和用户自主权。

## 三、Owner冻结的视觉方向

保持低分辨率质感、色块分区、几何构成、低刺激配色；生活方式探索保持二次元卡通/构成主义场景。避免写实摄影、过度线条、高饱和和视觉刺激。B3不重新开启美术方向会议，不为装饰而生成新素材。

## 四、整体实机验收安排

Owner整体实机验收在B1+B2+B3全部完成后统一进行。Codex在中间版本使用虚构账号、模拟器及真实APP/API/DB链完成工程验证，不操作Owner手机。B4为独立阶段，不自动成为该实机验收前置条件。

## 五、B3边界与禁止事项

- 不改变匹配算法、候选排序和资格权威服务；
- 不合并Match、Connection、Messaging Consent、Conversation、Relationship状态机；
- 不自动接受匹配、不自动发起或接受消息同意、不自动分享隐私字段、不自动确立关系；
- Buddy继续独立于恋爱匹配；社区仍为有限相互了解场景；
- 不建设无限陌生人Feed、短视频推荐、DAU/停留时长增长机制或频繁Push；
- 不接运行时AI，不把私聊或敏感资料外发给模型；
- 不接真实身份核验、征信、芝麻信用、蚂蚁积分、真实Push、支付或新付费服务；
- 不进入B4或阶段C，不合main、不正式发布、不开展真实内测/运营。
