## 二、v10.1.18目标

### 1. 用户语言
清理“账号可用”“本轮暂无候选，不代表被拒绝”等程序式/防御性表达。将内部状态码转成简洁、自然、准确的产品语言。不能通过删掉不确定性来伪装确定结果；未知状态仍需清楚表达“暂时无法确认”等事实。

### 2. 一级入口与匹配页
将底部一级入口「进展」调整为「匹配」，页面围绕当前轮次、候选/匹配结果、历史结果和用户需要决定的事项组织。恋爱关系的主观体验由用户本人判断，APP只展示有权读取的业务事实。保留旧路由兼容和现有四入口结构。

### 3. 统一交互色彩
建立统一按钮/选项状态色：默认、按下、选中、禁用、危险操作等。优先解决生活方式探索选中/按下后文字对比不足。保持低刺激、低饱和、几何色块方向，并验证正常/大字体和深浅主题（如项目现有支持）。

### 4. 自动化入口可发现性
Owner本轮未找到自动化入口。应在「匹配」和「我的」等合适位置提供明确、自然的上下文入口，但所有入口都指向B2唯一规范授权/控制页面；不得复制第二套开关或状态。

### 5. 说明与免责声明
将持续性解释、一般用途说明和长篇免责声明集中到「我的→权限/说明」等适合查阅的位置。首次参与匹配时可展示一次必要的简短说明。隐私分享、匹配接受、消息同意、Connection、Relationship和不可逆操作仍保留上下文中的明确决定，不能因为“少弹窗”而移除。

### 6. Buddy独立诊断
Buddy无法匹配的原因仍为UNKNOWN。独立核对入口、资格、请求、服务端返回、候选池和测试数据。Buddy与恋爱匹配保持独立。仅修复证据明确的路由、配置、接口或资格接线缺陷；若根因属于算法设计/参数或候选策略，不在本版擅自重做，提交诊断报告并保留UNKNOWN/待Owner讨论。

### 7. 冷启动与账号隔离
补充同一安装内A→登出→B登录、强制停止/冷启动、B→A切换等流程。检查用户状态、会话、消息、通知、缓存和草稿等账号范围数据，确保旧账号内容不泄漏。Owner本轮只观察到“新账号未显示旧账号消息”，不得扩大为完整隔离PASS；冷启动仍NOT_RUN，必须独立验证。

## 三、边界

- 不改变匹配算法、候选排序、资格权威服务和关系状态机；
- 不将Buddy并入恋爱匹配；
- 不增加第五个底部主入口；
- 不新增运行时AI、外部身份/信用、Push、支付或供应商；
- 不生成新美术素材，除非后续Owner另行授权；
- 不操作Owner手机；
- 不合main、不发布、不运营。
