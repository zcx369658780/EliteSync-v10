## 1. 产品总体原则

### 1.1 Owner确认的方向

- 先让用户体验产品价值，再按实际功能需要渐进式收集资料。
- 首页以内容与社交发现为主，不再以密集业务状态面板作为主要体验。
- 匹配是用户主动选择的独立旅程；用户必须知道何时提供资料、何时授权、何时报名。
- 系统可以自动整理、复用和计算已授权资料，但不代替用户作出匹配、连接、消息或关系决定。
- 视觉方向为**构成主义为主的二次元卡通画风**。
- 设计讨论图优先使用低分辨率设定图、低保真方向稿；不再以写实摄影、水面写实反光或玻璃拟态作为主视觉方向。

### 1.2 持续有效的业务边界

以下既有边界继续有效：
- `Match ≠ Connection ≠ Messaging Consent ≠ Conversation ≠ Relationship`。
- Match候选/提案不自动创建Connection。
- Connection不自动开放Conversation；Messaging Consent必须独立成立。
- Conversation活动不推断正式Relationship。
- Buddy保持独立于恋爱匹配。
- 用户公开作品、官方精选、好友动态是不同内容来源，不互相改变原始受众。
- 资料复用不等于资料公开；身份核验不等于跨用途授权。
- 自动计算不等于自动报名、自动接受候选或自动分享计算输入。

## 2. Home：首页内容架构

### 2.1 一级导航与首页频道 — OWNER_CONFIRMED

- 底部四个一级入口继续为：`首页 / 匹配 / 消息 / 我的`。
- 首页内部设置两个频道：`精选`与`好友`。
- 默认进入`精选`。
- `好友`是独立频道，展示当前用户按有效好友关系有权读取的好友动态。
- 首页可以有小型、低干扰的本人匹配状态入口；它只是状态摘要和跳转入口，不重新变成状态仪表盘，也不展示他人的私密身份或消息内容。

### 2.2 精选频道内容来源 — OWNER_CONFIRMED

精选频道包含三个明确区分的内容区域/来源：

1. **官方精选与官方专题（PUBLIC_EDITORIAL）**
   - 由EliteSync官方账号/平台编辑发布。
   - 平台精选内容允许未登录访客阅读。
   - 官方可以推送专题；专题采用问题引导式讨论（Owner选择讨论模式B）。
   - 普通精选内容：登录用户可点赞、收藏；不开放评论。
   - 指定专题：按内容类型开放评论；登录且符合规则的用户可以参与。
   - 官方内容与用户作品必须有清楚的作者/来源标识。

2. **用户公开作品（USER_PUBLIC_WORK）**
   - 在`精选`频道内设置独立的`公开作品`区域；不新增第五个底部一级入口，也不另建独立顶级Discover页面。
   - 用户主动选择公开的作品可在该区域被已登录用户发现。
   - 用户公开作品只允许已登录且账号状态符合访问要求的用户浏览；未登录访客不可访问，即使持有历史链接或媒体地址也不能绕过服务端权限。
   - 用户公开作品不因进入精选频道而成为官方精选；平台编辑推荐如有需要，必须与原始用户作品来源清楚区分。
   - 用户公开作品不建立全局公开用户Profile，也不因此公开用户的身份资料、生日、出生地点、星盘原始输入、匹配资料、私人动态或聊天内容。

3. **好友动态（FRIENDS_FEED）**
   - 主要在独立`好友`频道展示。
   - 读取范围由现有SELF/FRIENDS受众合同、当前有效双向好友关系、Block及账号状态决定。
   - 不能因为用户进入首页或好友频道，就扩大历史好友动态的受众。
   - 公开用户作品区域与好友动态频道分开，不将两者混成一个无来源区分的内容池。

### 2.3 访客权限 — OWNER_CONFIRMED

未登录访客：
- 可以阅读平台公开精选内容和官方专题正文。
- 不可以浏览用户公开作品。
- 不可以访问好友动态、私人资料、匹配信息或消息内容。
- 在APP任何地方都不能提交评论、留言、点赞、收藏、举报或其他互动/反馈。访客状态为只读；需要互动时引导登录。
- 不能通过直接URL、深链、旧通知、媒体内容地址或客户端伪造状态绕过登录门禁。

这里的“访客不能反馈”包括内容互动和产品内提交型反馈。账号登录/注册与必要的账号恢复入口属于身份流程，不属于匿名内容反馈。

### 2.4 登录用户权限 — OWNER_CONFIRMED

登录用户在账号状态允许且通过相应内容访问检查时：
- 可以阅读官方精选、官方专题；
- 可以阅读精选频道内的用户公开作品；
- 可以在好友频道读取本人和当前有效双向好友授权可见的动态；
- 可以按内容规则点赞、收藏、评论或举报；
- 不因登录而自动获得匹配资格、好友身份、Connection、消息许可或任何私密资料访问权。

## 3. 用户作品发布与权限

### 3.1 受众选择 — OWNER_CONFIRMED

用户发布作品时，目标受众选项为：
- `SELF`：仅本人；
- `FRIENDS`：仅当前有效双向好友；
- `PUBLIC_AUTHENTICATED`：站内公开，但仅登录且账号状态符合要求的用户可以浏览，访客不可访问。

**新用户新建作品的默认受众为`FRIENDS`。** 用户主动选择其他受众后才扩大或收窄范围。不得默认公开。

现有1011804后端仅接受`SELF / FRIENDS`。新增PUBLIC属于未来产品能力，不能把本设计决定描述为当前已经实现，也不能仅靠Flutter隐藏/显示按钮实现权限。

### 3.2 评论策略 — OWNER_CONFIRMED

用户作品的评论权限与内容受众分开设置，目标策略为：
- `ALL_ELIGIBLE`：所有符合账号条件、能够读取该作品且未被作者Block的登录用户；
- `FRIENDS_ONLY`：仅当前有效双向好友；
- `OFF`：关闭评论。

有效评论至少同时满足：
`Authenticated AND AccountAllowed AND CanViewContent AND CommentPolicyAllows AND NOT Blocked`。

受众优先于评论策略：内容不可见者不能评论。公开作品设置`ALL_ELIGIBLE`时，访客仍不可评论，因为访客不可浏览用户作品且不具备登录身份。公开作品设置`FRIENDS_ONLY`时，其他登录用户可以看，但只有好友能评论。关闭评论后禁止新增评论。

作者可以在发布时选择评论策略；评论策略默认值尚未由Owner确认，见第9节。

### 3.3 权限治理原则 — OWNER_CONFIRMED / EXISTING_BASELINE

- Block优先于其他受众和互动设置。
- 双向好友必须按服务端当前事实确认，不能信任客户端好友标记。
- 作者关闭评论后禁止新增；已有评论是否仍可见取决于内容可见权限及未来确定的评论生命周期规则。
- 用户公开作品不自动授予私信权限；评论、好友、Connection、Messaging Consent彼此独立。
- 用户把作品从FRIENDS改为PUBLIC时，历史评论是否维持原有评论者受众，不能未经单独设计就扩大公开范围。
- 内容读取、媒体字节、评论读取/写入、点赞、收藏、举报、通知回流、缓存清理均需在服务端执行当前权限验证；UI控件隐藏不能作为安全边界。
- 平台精选和用户作品应保持不同内容真值、发布权限、来源、审核及撤回流程。

## 4. 官方精选与专题

### 4.1 内容互动 — OWNER_CONFIRMED

- 普通官方精选：浏览、点赞、收藏；不开放评论。
- 指定官方专题：浏览、点赞、收藏，并可开放评论。
- 专题讨论模式采用问题引导（B类）：官方提出具体问题，用户围绕主题表达观点。
- 访客可以阅读官方专题正文，但任何访客都不能留言、评论或提交反馈。
- 评论开放与否按内容类型配置，不是所有官方内容默认开放评论。
- 官方专题与用户公开作品必须有明确来源区分。

### 4.2 官方内容治理 — ADVISOR_PROPOSAL / OPEN

顾问建议官方内容保留来源/版权、编辑责任、发布时间、复核时间、适用范围、评论开关、撤回状态和必要审核记录。建议生命周期为Draft → Review → Available → Stale/Withdrawn。具体编辑角色、审核权限、复核期限、评论区关闭后的历史评论处理仍待细化，不能视为Owner已批准的完整运营合同。

## 5. Matching：下一代匹配规则

### 5.1 渐进式用户旅程 — OWNER_CONFIRMED

目标旅程：
`注册/登录 → 可跳过的首次Lifestyle探索 → 首页内容与社交体验 → 用户主动进入匹配 → 按需完成匹配准备 → 用户明确报名 → 匹配轮次/提案 → 本人决定 → 后续独立关系流程`。

注册阶段可以跳过Lifestyle；用户可以先浏览官方精选、在登录状态下浏览公开作品、使用已开放的社交功能。只有在用户主动进入真实匹配参与流程前，才要求完成Lifestyle。

### 5.2 真实匹配准入 — OWNER_CONFIRMED

正式进入真实匹配参与流程必须满足：
1. **Lifestyle完成**：五场景探索已完成；注册阶段可以跳过，但真实匹配参与前必须完成。
2. **实人身份核验通过**：必须由未来接入的真实核验供应商按其实际合同和能力给出有效核验结果；自我声明、模拟账号或测试回执不能替代真实核验。
3. **其他必要匹配资格/资料满足**：按现行必要资格合同逐项检查；不得把非必要特色工具变成准入条件。
4. **用户明确参与**：本轮一次性报名或独立持续自动参与授权，二者不可相互推导。

真实身份供应商目前尚未接入。因此当前不得宣称真实核验可用，也不得通过UI占位绕过该门槛。未通过、待处理或未知状态不能进入真实匹配。

### 5.3 自动参与 — OWNER_CONFIRMED

- 自动参与默认关闭。
- 自动参与是独立授权；普通一次性报名不会开启自动参与。
- 普通报名只针对用户明确选择的当前轮次，不推导下一轮授权。
- 用户可以独立暂停、恢复、撤销持续授权。
- 暂停/撤销自动参与不自动取消用户已独立完成的一次性报名，也不自动撤销已经建立的Connection或消息许可。
- 自动参与只授权约定范围内的后续报名，不授权自动接受候选、创建Connection、开启消息或确认Relationship。
- 授权到期、资格失效、核验失效和执行失败的具体细节仍需沿用B2既有合同并在未来设计阶段核对，不在本文件另行重写。

### 5.4 星盘、MBTI与其他工具 — OWNER_CONFIRMED

- 星盘在有足够出生资料且用户已授权星盘计算用途时自动生成。
- 星盘不是匹配硬门槛；缺少出生时间、地点或星盘计算失败，不阻止用户满足其他条件后参与匹配。
- 不得推测缺失出生时刻/地点；必须保留资料精度和未知状态。
- MBTI是独立可选工具，不等同于五场景Lifestyle，也不替代Lifestyle准入条件。
- 八字、紫微及其他特色工具均不是匹配硬门槛，除非未来Owner另行作出明确决定。
- 自动计算不代表自动公开计算输入或结果，也不代表这些结果自动成为匹配算法证据。

### 5.5 匹配与关系业务边界 — EXISTING_BASELINE

- Match、Connection、Messaging Consent、Conversation、Relationship各自独立。
- 候选或提案必须由用户本人决定接受/拒绝。
- Connection需要独立的双方同意。
- Conversation需要独立有效的消息许可。
- Relationship不能由匹配次数、消息数量、互动频率或Connection时长推断。
- Buddy继续独立于恋爱匹配。

## 6. 个人资料复用方向

### 6.1 已确定的产品原则 — OWNER_CONFIRMED

- 尽量减少重复输入；在用户已提供且有权使用的资料范围内复用。
- 每个字段必须区分含义、来源、精度、用途和授权。
- 法定姓名不等于展示昵称；当前城市不等于出生地点；生日不等于出生时间。
- 身份核验通过不等于用户授权将所有核验字段用于匹配、星盘或公开展示。
- 新用途需要相应授权；撤销授权后停止后续用途处理。
- 仅补充具体功能真正缺少的字段，不要求注册时一次性收集全部资料。

### 6.2 Personal Data Hub — ADVISOR_PROPOSAL / OWNER_CONFIRMATION_PENDING

顾问建议建立统一个人事实资料来源（Personal Data Hub），并将以下概念分开管理：
- 私密身份资料；
- 出生资料；
- 匹配输入与偏好；
- 对外展示资料；
- Lifestyle与MBTI等用户偏好/测评；
- 星盘、八字、紫微等派生结果。

建议每个字段记录来源、确认状态、精度、更新时间、用途授权及生命周期。该数据架构尚未由Owner正式批准为实现合同；后续讨论「我的」页面时继续确认其信息架构和数据语义。

## 7. 匹配页面信息架构 — ADVISOR_PROPOSAL

顾问提出的候选结构为：
1. 匹配准备；
2. 参与方式；
3. 本轮匹配；
4. 连接与关系；
5. 匹配历史。

它是讨论方案，尚未被Owner逐项确认。无论最终布局如何，均须保留第5.5节的业务独立性，并避免把内部状态码、revision或用户ID作为普通用户文案。

## 8. 视觉与交互方向 — OWNER_CONFIRMED

- 构成主义为主的二次元卡通画风。
- 几何构成、明确色块、风格化人物与场景插画。
- 以图像/插画为主、短文案为辅；减少工程说明、AI式长段解释和重复免责声明。
- 颜色、字号、行高、触控面积、选中态可读性、按钮反馈和安全区在后续统一设计。
- 选中/按下状态不能遮挡文字或降低对比度。
- 讨论阶段优先低分辨率设定图、低保真页面方向稿；高保真成品稿留到方向确认后。
- 不把此前写实摄影、水面写实反光、玻璃拟态方向当作当前已接受基调。

## 9. 尚未冻结的事项

以下不能误写为Owner已批准：

### 首页与内容
- 用户作品评论策略默认值（顾问曾建议默认仅好友，Owner尚未明确确认）。
- 公开作品排序、主题分类、个性化推荐的具体算法与控制。
- 访客是否可以阅读官方专题的既有评论正文；Owner已确认访客不能留言/反馈，但没有明确决定访客能否查看评论区。
- 用户作品受众从FRIENDS扩大到PUBLIC时，历史评论的可见性与迁移规则。
- 评论长度、频率限制、是否允许回复、举报处理SLA等具体参数。
- 官方编辑、审核员和管理员的角色/权限合同。
- 用户公开视频是否可以被平台编辑另行推荐、转载或精选，以及所需授权方式。

### Matching与身份
- 真实身份核验供应商、核验等级、供应商实际返回字段、费用、失败恢复与申诉方式。
- 其他必要匹配资格的完整字段合同与数据保留要求。
- 自动参与授权的具体期限、适用轮次和到期行为，需对照B2合同细化。
- Lifestyle跳过后进入匹配前的具体问卷恢复/修改体验。
- 匹配页五模块是否最终采用，仍待Owner确认。

### 个人资料与我的页面
- Personal Data Hub的正式数据架构、字段模型和所有权合同尚未批准。
- 私密身份、出生资料、匹配输入、展示资料的具体页面组织尚未确认。
- 星盘自动重算触发条件、结果版本保留与删除策略尚需细化。
- 特色工具是否归入统一工具中心及其导航层级待讨论。

## 10. 与现有产品/架构的差异处理

- 现有1011804的好友动态后端受众为`SELF / FRIENDS`；`PUBLIC_AUTHENTICATED`是未来新增目标，不是当前功能。
