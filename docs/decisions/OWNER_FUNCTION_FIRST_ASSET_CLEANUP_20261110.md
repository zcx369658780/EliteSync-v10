# Owner 决定：功能优先、资产整理与简化测试

日期：2026-11-10。来源：Owner 在本会话明确要求先停下讨论，随后指示“完善 EliteSync 的 app 功能，然后进行安全性封装（包括通讯协议加密等）”；同时要求查清资产，删除多余旧分支与备份、保留各版本摘要，以及“测试从简，不再用当前的安全级别卡住开发进度”。

## 执行决定

1. 以产品功能为主线，随后集中做安全封装。现有鉴权、私信访问控制及数据隔离保留；不把新安全封装的全部验收作为日常开发前置条件。
2. 普通工程只做受影响验证，必要时一次最短功能验证。取消小修必经的重复冻结、副本、完整清单哈希、全量主机回归、逐步批准和多份报告。遇普通可恢复错误自主处理；风险没有变化时不重复扩大测试。
3. 清理确认冗余的分支、工作目录及备份，保留版本摘要。此前“所有旧副本永不删除”的笼统保留约定由本次明确清理授权取代。独有未提交成果、私有数据与必要运行依赖仍保留一份，不能假设 GitHub 可恢复。
4. 远端旧历史先归档再删除旧分支名；归档不合入 main，也不表示旧功能已获当前验收。仅本地存在的提交和必要私有文件放在一个固定私有整理目录，不公开上传。
5. 旧冻结测试链退役后不再作为现行开发入口。原始失败、停止和已耗记录不改写；目录清理不等于退款、重试或再次授权。Owner 要求停下之后 case08 未激活；本轮不运行设备、模拟器或后端。

本决定更新的是开发方法和冗余资产管理，不放宽真实数据、错身份、生产、外部服务、费用、正式发布及不可逆业务操作的边界，不宣称 v10.1.5 已完成。当前功能缺口仍见 PROGRESS。

具体结果见 [资产与版本摘要](../versions/ASSET_VERSION_SUMMARY_20261110.md)，当前入口见 [ACTIVE_STATE](../workflow/ACTIVE_STATE.md)。此前提交中的完整流程与报告保留在 Git 历史；当前规则以本决定、AGENTS 和 CURRENT_WORKFLOW 为准。
