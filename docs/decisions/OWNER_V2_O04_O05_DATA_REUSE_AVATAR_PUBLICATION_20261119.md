## 2. O04 最短合法回流

`匹配准备 → 缺失字段的权威编辑页 → 验证当前具名用途授权/合法复用 → 确切保存 → 回到原匹配任务重新计算资格`。

- 已有且可用于当前目的的事实不得无意义要求重新输入；仍缺合法用途许可时提示并由用户明确决定，撤销许可不得被后台默默恢复。
- 字段用途独立：法定姓名≠展示昵称，现居城市≠出生地点，出生日期/时刻/地点分别有语义和用途；匹配必要资料不能自动用于占星或展示给候选。
- 保存UNKNOWN时先查询权威状态，不自动重提或假装成功；保存成功后不自动报名、扩大受众、替换对外版本或假称实人认证成功。
- 具体事实存储/授权快照接口、字段映射、迁移方案仍须未来单独合同及工程核验，不预先指定schema。

## 3. O05 本人预览和发布版本

- `编辑主形象 → 保存 → 本人预览更新`；不会自动影响既有社交/匹配独立覆盖字段，且不等于对外发布。
- `选择社交/匹配场景 → 检查本人待发布预览、当前已发布版本、允许受众 → 本人明确发布 → 获得确切结果`。
- 扩大受众不能默认勾选，必须明确确认；若结果UNKNOWN，维持未知并查询真实生效状态。撤回/收窄受众优先遵守当前权限，不因方案A让已经失权者继续读取旧快照。
- **A的版本边界**：仅未来新匹配候选在当前可用、合法发布和授权都满足时读取新版本。既有候选不会因为发布动作自动切换；但旧快照是否被继续允许读取仍取决于当前有效受众、Block、必要保留/撤回和业务资格，不能当成永久访问或旧数据必须无限期保存。
- 如将来需要“向既有候选单独发布新版”，应另有明确交互与本人授权，当前未批准实现具体同步、撤回和保留机制。
