# Owner 决定 v10.1.5 收尾与后端功能优先

日期：2026-11-13（北京时间）。来源：Owner 在项目顾问会话中的最新两次明确决定。

## 已确认的方向

1. EliteSync 重置版 v10 已基本具备旧版主要功能，项目彻底完成交接，可以继续开发。
2. v10.1.5 视为收尾，剩余问题随之后的功能规划处理，不继续作为整个项目的开发阻塞。
3. 功能完善之前不注册公司、不启动内测；整个 v10 以 APP 功能、体验和 UI 完善为重心。
4. 相识后的新增破冰、约见、共同计划、纪念日等只留扩展接口，暂不开发完整业务。已有聊天、搭子、平台活动、正式关系生命周期与已有手填关系盘继续保留。
5. 先完成真实后端业务、持久化及必要 APP/Web 操作，再安排一个版本集中打磨 UI、信息结构和文字。
6. Owner 授权顾问修改路线图、决定版本划分，并在 GitHub 下达下一版本任务书。本地 Codex 在既有会话和稳定目录连续执行，集中交付后再进行顾问验收。

Owner 原话：

> 相识之后的这些内容我们暂时留一个接口就好，先开发周边的功能。后续的思路是先落实功能层面到后端（而非目前这样的docker模拟），完成后找一个版本集中打磨UI和文字等内容。

> 我授权你开始修改新的计划路线图，版本规划由你决定，完成后请下达下个版本的github版本任务书，codex离线完成后继续验收。

## 后端落地的具体标准

当前容器内的 Laravel、MariaDB、WebSocket 和 SFU 已是实际开发服务。虚构开发账号也不意味着业务是假实现。需要退出正常产品流程的是受控成功响应、直接改库批准、仅用于测试的业务前置、默认演示页面和不持久化的假成功动作。

后续功能的完成标准是：普通 APP/Web 入口调用真实产品 API，由真实鉴权和业务服务执行，状态写入持久数据库，正常重登/重启后可以读回；管理员通过真实后台处理业务，不以夹具代替用户操作。测试替身仍可用于单元和故障测试，但要与最终产品链分开记录。

本决定没有要求拆除 Docker、重装数据库、迁到公网或生产环境。默认延续当前稳定的本机开发基础设施；容器只是承载方式，不能作为业务完成或未完成的判据。普通本地开发服务、开发库迁移、虚构数据、必要构建及双模拟器沿用现有长期授权。
