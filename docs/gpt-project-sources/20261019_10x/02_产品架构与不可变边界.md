# EliteSync 10.x｜产品架构与持续边界

更新：2026-10-19。原2026-09-12设计和接受证据保留在06/07；最新前瞻决定在08，规划在09。新方向只在明确冲突处覆盖旧排程，不倒改历史接受。

## 核心产品

帮助用户建立长期恋爱关系；低频、高意图、少而清楚的慢约会。搭子是吃饭/学习等独立社交场景，不强迫参加婚恋。社区按关系授权帮助表达和了解，不默认建立无限公开Feed。

继续以`Home | Progress | Messages | Me`为已接受目标IA。社区/搭子/活动可先采用次级入口与独立进度，不在本次默认增加顶层Tab，也不声称现有全部页面已符合目标。

## 独立事实与授权

`Match != Connection != Messaging Consent != Conversation != Relationship`。好友、搭子参与、消息请求、正式恋爱同样分开。好友或请求接受不自动授予普通消息发送。正式恋爱需双方实人核验和双方确认，任何人仍可随时退出、举报或拉黑。

`Block != Report != Finding`，`Allegation != Finding`；`UNKNOWN != ABSENT`；`STORED != AUTHORITATIVE`；`PROJECTION != PERMISSION`。AI不推断已成立恋爱关系、不定罪，不以私聊或Safety资料默认计算排名/信用。

## 资料与社区可见

陌生人最小ID/头像；好友可见被授权动态；恋爱对象可见本人另行分享的喜好/生日/履历/星座等。关系是授权上限，不是全字段自动解锁；原始证件、生辰时地、私聊和内部风险记录保持用途隔离。匹配候选Showcase和搭子公共活动卡需要具名范围，不能从关系表越权。

拉黑须约束新请求、资料/动态查询、搜索、消息、媒体、通知与RTC的使用点；不允许被拉黑方重新加好友。解除拉黑不自动恢复旧好友/消息同意/恋爱关系。隐藏会话≠拉黑≠删除账号≠物理抹去所有历史。

## Safety与身份

内部安全/活动履约记录可核实、分级、可申诉，默认不对未来恋爱对象公开。正常拒绝、反悔、取消、拉黑不处罚；AI仅辅助，重大处置人工/具名规则、通知、复核和纠错。信用/征信不接入当前婚恋评分。

支付宝/微信等只作待核供应商候选；运营审核/支付实名/活体认证/信用不是同一证明。开发合成身份不得在真实用户环境冒认证成功。最低年龄、身份供应商、保留期及具体申请额度等仍在对应版本前决定。

## 数据与解释

Private Identity、Matching Inputs、Readiness、Showcase按用途分离。原设计13类受众/数据类别继续有用：PUBLIC_EDITORIAL、ACCOUNT_PRIVATE、PRIVATE_IDENTITY、READINESS_RESTRICTED、MATCH_PURPOSE_LIMITED、SHOWCASE_CANDIDATE_SCOPED、CONNECTION_SCOPED、CONVERSATION_SHARED_PRIVATE、RELATIONSHIP_SHARED_PRIVATE、USER_PRIVATE_REFLECTION、AI_DERIVED_PRIVATE、SAFETY_RESTRICTED、OPERATIONAL_MINIMUM。

沿用已接受三盘/动态盘及科学/流派/许可限制；comparison不改名composite；付费不提升科学确定性，不解锁他人资料。私密对话不默认交AI训练/外传，AI草稿可编辑、不代发。

已有按账号加密离线只读15/30天方向仍需可靠时间、凭据、撤权与清理实现证明，不能当完成事实。数据库和敏感原证不进Git；代码与安全文档本地＋GitHub；历史备份按具名权限恢复不推断所有真实账号已恢复。
