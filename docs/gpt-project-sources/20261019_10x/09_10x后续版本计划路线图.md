## 1. 产品承诺与本阶段终点

核心承诺是帮助用户建立长期恋爱关系：信息少而有用、匹配低频且有明确意图、双方自主推进，并能安全退出。独立搭子覆盖吃饭、学习等非恋爱社交需求；社区用于相互了解，不作为无边界陌生人信息流。好友、搭子、匹配、交流与正式恋爱关系分开。

本阶段的实物终点是：**一套功能成组可用的Android APK＋真实后端＋持久化数据库＋独立Web后台＋与实际实现一致的说明及演示材料**。Owner可手动截图/录屏发同事评估。此终点叫“开发评审版”，不是已备案、可公开运营或已验证所有真实第三方服务的内测版。

后续路径：功能完成与恢复收口 → Owner/同事质量会议 → 按结果修正 → 决定公司、备案、真实供应商与线下预算 → 获准的小范围真实试点 → 再决定公开上架/运营。旧半年至一年内测设想是届时可复核的运营假设，不是现在承诺的日程。

## 4. 已确认原则与三类证据

配套Owner决定文件的PD-1019-01～16是已确认产品方向。以下版本划分和默认交互是Astra规划；频率、额度、活动公开字段、账户保留期等仍待相关版前一次冻结。旧竞品图片和功能矩阵是来源，不是Owner授权。

1. 正式恋爱关系需双方实人认证＋双方确认；搭子、好友、消息同意不能自动建立恋爱关系。
2. 关系等级是资料分享上限，字段本人可控；原始身份、生辰、私聊和内部安全证据不自动公开。
3. 拉黑立即约束相关使用点；隐藏会话、静音、退出登录、撤回消息同意、退出关系、注销账户是不同操作。
4. 普通取消/拒绝/拉黑不构成过错。内部风险记录核实、分级、可申诉，不向以后恋爱对象提供负面档案。
5. AI辅助表达和审核，不代发消息，不定罪、不确立恋爱事实、不改变已接受算法事实层。
6. 实人认证、信用、付费、运营资质分别处理；没有已核定的支付宝/微信接入资格或信用数据用途，不承诺供应商可用。
7. APP/API/Web/DB同一业务事实；管理员使用独立Web后台，不恢复APP旧管理面板和同事SSH。
8. 本地/GitHub分层备份代码与安全文档；数据库备份和私密原证不进Git。当前已有云端运行库不因“数据库仅本地备份”而被删除。

## 6. 各功能包的主要范围与冻结出口

### 6.1 v10.1.1｜关系、可见范围与账号安全

复用已有Connection、Messaging Consent、block、禁用、Web权限与审计。先把好友、搭子参与和正式恋爱关系作为独立领域事实明确，再映射到已有消息能力；不新造一套与现有权限相矛盾的真假关系库。

范围：好友申请/接受/撤回；接收方可控消息请求；按字段/内容受众的展示；隐私中心保存与服务器投影；拉黑的全通路限制；隐藏会话而非注销；服务端登出/凭据撤销、设备会话与普通账号删除合同。删号必须区别于当前前缀启发式开发清理，默认不批量物理删历史争议或共享数据。

建议默认：未接受请求前不发送普通文本/附件/来电；消息请求仅在允许的场景可达，参数在版前冻结。好友接受也不暗授Messaging Consent；接收请求不能自动共享精确生辰。用户可以禁用请求；被拒/被拉黑不得用重发或改入口绕过。

出口：虚构A/B账号逐一验证允许/拒绝、保存/重登、撤权/旧缓存/旧链接/旧token、搜索/通知/媒体/RTC使用点一致；普通用户不能借客户端字段变成管理员、实人或恋爱关系。真实身份供应商此时只建可信状态适配，未接入不标已核验。

### 6.2 v10.1.2｜长期关系导向的慢约会全旅程

复用现有问卷、资格、轮次及匹配consumer，不重新发明黑箱总分。补足首次使用、关系意图、准备度说明、报名/退出本轮、等待、无候选/失败的区别、暂停/恢复、结果解释与后续行动。没有匹配时Home也有真实、少量且不制造焦虑的下一步。

正式恋爱关系由双方明确申请/确认且实人验证状态有效后建立；任一方可结束，不要求对方批准退出；结束后按字段/共享历史合同降权，不把分手记作风险。实人状态过期/撤回的关系和共享处理须版前定义，不自动把技术失效等同感情变化。

开发可用明确隔离的合成身份回执完成状态机正反例；真实provider尚不可用时，真实账号正式关系建立保持不可用/待核验，不能由普通管理员勾选或客户端boolean替代。是否在评审前申请正式身份产品不是本版前置。

出口：同一APP/Web/API/DB贯通全部选定状态；draft与历史不因暂停丢失，过期或无资格不显示假匹配；CN/MC/恋爱关系分别同意；说明频率与成功标准，不承诺匹配效果。

### 6.3 v10.1.3｜独立搭子与有限社区

搭子独立于恋爱匹配和恋爱意图，不迫使想学习/吃饭的人参加婚恋。建议首包覆盖吃饭、学习两类，以少量类型验证真实发起、条件、时间、申请/邀请、接受、取消、结束及举报/拉黑，不同时建设大型群聊/直播/虚拟经济。

好友社区复用状态发布、点赞和治理链，补选定文字/图片动态、评论或收藏、个人动态管理、作者删除和受众撤回。评论/收藏是Astra建议，版前按真实需求选定；不默认恢复无限Feed。陌生人不能借内容ID、搜索、转发预览、缓存或通知读取好友动态。

独立搭子如何被陌生人发现要明确一个小合同：可选择平台匹配式投递，或用户明确发布最小活动卡。活动主题/城市/时间/人数等是活动字段，不是个人履历公开许可；具体开放字段尚未获Owner逐项批准。身份证/精确住址不用于发现。是否形成群组、群发和互加好友另定，不自动开放。

出口：非恋爱参与者能完成一条真实搭子链；好友动态受众在发布、评论、搜索、撤权、拉黑后始终一致；只有被选定且有来源/新合同的能力计入接受。

### 6.4 v10.1.4｜平台线下活动软件与内部风险闭环

为未来平台出资活动建立地区/城市/场所、时间、容量、报名/候补、双方确认、取消、完成、费用预算与管理记录。开发使用虚构咖啡厅、预算和参与者，不代表全国已有合作场所或已发生补贴。

取消与失约分类必须公平：用户反悔、感觉不安全或不想继续有退出权；一方称对方未到只是举报/争议，不能自动形成违规。到场可采用双方自愿确认等低侵入设计，不能强制持续追踪或用定位缺失自动定罪。反复骗取活动资源与严重安全事件需证据、人工复核、明确后果和申诉。

内部工作流：接报 → 限权证据 → AI分类/摘要或规则辅助 → 人工决定 → 通知 → 申诉/复核 → 纠错与到期处置。AI只给建议，记录模型/规则版本及不确定性；没有第三方模型许可时可先由规则与人工完成实用流程。内部Safety数据不用于普通兼容性排序，不供未来恋爱对象浏览。

出口：Web操作在同库反映到APP的活动资格/状态；无依据举报、正常取消、拉黑、不回复不能自动产生惩罚；人工撤销处罚后纠正投影但不暗复活原CN/MC；真实线下招募与任何资金支付仍NOT_RUN。

### 6.5 v10.1.5｜通信质量、离线和授权Push

已有文字、图片、短视频和双端RTC继续使用，不把既有接受归零。补足发送状态、重试/去重、弱网重连、前后台、旧消息读回、挂断与权限撤回；针对已知AEC/回声、RTC返回地址限制、Android明文策略、WS实际端点差异做有界加固与测试。

保留既有离线设计的15/30天方向：按账号加密的已存内容只读、离线不发送；以最后一次成功在线登录为计时源，自动token刷新不冒登录。可靠时间、登出/撤权、共享数据保留/删除等在该版核实既有Owner合同后一次冻结，不根据记忆假设已实现。新“隐藏会话”不等于物理删除所有离线内容。

系统Push：通知授权、类别偏好、静默/暂停、token登记/轮换、去重、锁屏最小内容、点击时重新鉴权。拒绝通知不阻断匹配或消息；未获准的真实供应商只能记待接入，虚拟通知回执不得证明真实后台送达。申请/费用和SDK数据流在版前只处理实际需要部分。

语音留言不是RTC语音：先定点确认旧源；确为已实现且选定恢复则同版收口，否则列为新需求待明确，不默认为已具备也不无限寻找。地图/地点首先服务城市及活动位置表达；附近人/实时追踪不自动加入。

出口：受控设备与持久后端验证选择的质量场景、拒绝与恢复；设备/供应商缺口逐项保留。最终评审前不得用“代码写好了”声称真实Push或人耳音质已达标。

### 6.6 v10.1.6｜真实计算、关系解释与自愿AI辅助

复用v10.0.10/11的真实本命/动态盘。让用户看懂输入、计算来源、共享范围、结果层次和局限；只对新输入/视图/分享或新算法差异跑相关测试，不重开全部历史oracle。

## 10. 长任务模式与验收原则

一个功能版采用一份冻结计划、一份综合任务、一次集中候选与独立验收。Codex内部可并行安排前端、后端、数据库、Web和测试，关键权限/数学/数据变更用非作者复核；不恢复Work/dot实时监督，不要求Owner转发微任务或新增强制多模型循环。

每版以“用户/管理员操作→真实后端→持久库→再次读取/重启→正反权限结果”为功能证据。虚构数据可以用，前后端各自mock不算交付。未授权外部门禁以隔离替身开发测试时单列，不能将供应商模拟结果标实人/Push/支付/真实活动成功。

原冻结AC不倒改；无关旧失败保留而不自动每版全量返修；本版引入的回归须修。源码接受、main集成、当地工作树、部署运行、真实参与/公开运营分别记录。接受后的安全集成和本地基线接续按现行工作流，尽量合并收尾，不盲merge、不过度重复构建。

本次同步不新增功能版plan、不开发、不重验运行、不清理临时审阅分支。下一步只在同步完成后冻结建议的v10.1.1（或版前明确修订的首包）。
