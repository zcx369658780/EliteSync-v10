## 2. 已明确被替代的初始设想

- 不再实施“以后所有恋爱对象都能查看被举报、拉黑、纠纷、征信、失约明细”。保留内部可核查/可申诉记录与必要账号、活动安全处置。
- 不再实施“用户同意见面后反悔就自动记过”。正常取消与拒绝自由保留；到场争议、反复骗取资源等须区分事实与指控后处理。
- 不再实施“AI自行判定举报可信后直接处罚”。AI输出是审核输入，人工/规则决定、通知、申诉和纠错是独立流程。
- 不再实施“陌生人可以直接给普通会话发消息”。请求箱是前置邀请机制，不绕过Connection/消息同意。
- 不因恋爱关系成立自动披露全部资料；不因支付费用、实人认证、好友或搭子身份自动增加其他用途权限。

## 3. 不应混写为Owner已定的细节

下列是Astra建议，在涉及版本内一次冻结，不在本次同步中实施：请求箱默认关闭/仅特定场景开启、请求次数/冷却/有效期、可携带文本长度；好友/搭子关系如何映射既有Connection授权；恋爱关系单一/多重约束；认证时效及异常处理；公开活动字段；具体资料字段默认值；正常退出后的共享历史读权、删除保留期；活动城市和预算；Push/认证/支付供应商与许可；AI模型及是否外发数据；人工服务资质和最终经营范围。

建议默认采取最小披露、允许退出、消息不代发、实人状态服务端验证。具体参数未知不得补造成既定合同；只阻塞对应高风险分项，不重开整个项目。

## 4. 与旧目标设计的关系

2026-09-12的`Home | Progress | Messages | Me`是已接受目标IA，继续作为导航基线，不在本次新增第五/第六顶层入口。独立搭子可先置于Home的次级入口及Progress独立分区，社区放在好友/关系上下文；这只是Astra规划布局，不冒称现有APK已按此实现。

“陌生人只见ID/头像”是新的最小展示方向，不是全球可枚举用户目录。选定候选Showcase、公开活动卡或好友动态若需额外字段，必须说明具体用途与用户选择；旧Matching Inputs可供合法匹配计算，不自动变成可向候选披露的原始答案。

`Match != Connection != Messaging Consent != Conversation != Relationship`、`Block != Report != Finding`、`STORED != AUTHORITATIVE`、`PROJECTION != PERMISSION`继续有效。私聊与安全证据不默认进入AI训练、普通兼容性排名或公共声誉。
