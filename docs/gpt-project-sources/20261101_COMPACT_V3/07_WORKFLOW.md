# 现行工作流｜计划与工程执行分工

Owner确定目标、方向与权限；项目源GPT顾问制定项目计划和路线图；Codex据此自主完成工程拆解、实现、调试、验证和工程验收，在有意义的节点记录进度、同步可公开副本。重大取舍和保留事项交Owner决定。

不再采用网页GPT逐项派单、普通工程强制冻结任务单、A–D发布闭环、必读handoff或等待Astra工程终验。可按需咨询顾问，但不是普通修复和已批准工作的逐步审批。没有自动消息转发能力时，由Owner传递计划或咨询材料，不假定后台协作已经发生。

Codex依据实际代码、适用标准和测试证据验收；保留冻结AC和失败，不降低标准。自己的复查不得称为外部独立审查，不要求每项工作强制多模型审核。Owner接受、正式发布和生产操作保留独立决定。

实时进度只维护ACTIVE_STATE短当前块；详细矩阵使用既有PROJECT_PROGRESS_ALIGNMENT；Owner决定使用既有decisions。不为每个小改动新增重复CURRENT/MEMORY/HANDOFF或长报告。必要交接只写状态差异、目标、证据身份、未完成项和下一步，不递归旧材料。

普通失败在权限内自主处理。只有范围、重大方向、不可逆风险、真实数据、设备、供应商、费用或实际权限不明时暂停受影响部分，其余已批准工作继续。旧STOP和已耗预算不恢复；不得把本次规则整理当作产品开发或运行授权。
