## 起运比例与 Gregorian 交运

传统来源支持三日一年、一日四个月、一时辰十日及顺逆数节。它们不唯一规定现代 Gregorian 加法或 DST。沿用已接受 lunar-php 1.4.0 的口径，具名为 `lunar-php-1.4.0-sequential-gregorian-clamp-utc8-v1`，不改库以匹配另一流派。

1. 有规范出生瞬间时，年/月柱直接按 **TT 半开区间 `previous ≤ birth < next`** 判定；同一瞬间不随用户 TZ 或真太阳时开关变化。lunar-php 的节气原始 JD 实际是 `TT − 库ΔT + 8小时`，不能当作UTC＋8。逐根迭代恢复TT，再用已准入ERFA转为UTC＋8的起运端点；1960年前沿现有Skyfield模型UT1民用解释，`utc` 为null，未来保留实际闰秒UNKNOWN与固定时表假设。原始JD/库标签/ΔT/TT及转换身份均返回。安全区间内部代表时间只提取库年/月及对应扩展，绝不作为生日、日时柱或年龄锚。没有规范瞬间的旧内部输入保留 `compatibility_wall_time`，不给它虚构UTC。
2. sect 1 默认：把固定参考墙钟映为 `12 × Gregorian 日序 + min(11, floor((小时+1)/2))`。后端点减前端点的非负整数每 36 单位一年，余数每 3 单位一月，其余每单位十日；小时为零。**23 时在此兼容算法的末桶 11，而非用于时柱的子时桶 0**。分钟和秒不参与此折算；不能声称任意秒差会线性影响起运。
3. sect 2 可选内部规则：端点分别截去秒，再减整分钟。每 4,320 分钟一年、360 分钟一月、12 分钟一日、余一分钟两小时。是端点标签截秒，不是精确秒差再四舍五入。
4. 得到非负 `(年,月,日,小时)` 后，严格顺序执行：出生年加年，若目标年没有该日则截到月末；再加月，再截到月末；再加 Gregorian 整日；最后加小时。保留出生时分秒。年/月不得先合并：例如闰日先加一年会先变为二月二十八日，后续加月不会恢复二十九日。
5. Gregorian 闰年用 4/100/400 规则。主要域 1901–2100；交运结果可能延伸以后。lunar-php 的 1582 改历特殊行为不在此次现代日历证明范围内。
6. 以上算术从真实出生固定＋8日历标签执行，完成后转换为用户IANA TZ；1960年前的结果仍标模型UT1，`start_utc` 为null。1960年起以明确的UTC日历约定表示结果。此处是现代历法投影，不是把传统比例解释为持续的TT秒数。不存在将模型生日传给Yun的隐性锚；大运干支用校正月柱及原方向，公历出生年/交运年决定运限年份和名义年龄，流年为该年立春后干支标签。`pre_yun` 起运同年允许零条流年。不在DST用户墙钟上直接加年月，显示保留offset。
7. 返回的秒只是保留原出生秒，**不是邻节天文误差或真实交运时刻的秒级认证**。HKO 分钟表只能在分辨率足够的非边界样本证明折算桶；节令附近仍保留参考精度限制。

兼容实现来源：[lunar-php 1.4.0 Yun](https://github.com/6tail/lunar-php/blob/1.4.0/src/Yun.php)、[Solar](https://github.com/6tail/lunar-php/blob/1.4.0/src/Solar.php)。独立日期算术使用 [Python datetime](https://docs.python.org/3/library/datetime.html)、[calendar](https://docs.python.org/3/library/calendar.html) 和 [zoneinfo](https://docs.python.org/3/library/zoneinfo.html)，并保留非作者盲选样本；这独立于被测库，但不认证传统比例是自然事实。

时标适配 `lunar-model-ut1-via-tt-to-declared-civil-v1` 修正此前误标UTC的缺陷，保持day_sect、顺逆、离散起运比例与Gregorian顺序加法。ERFA转换对闰秒及舍入进入`:60`的端点明确拒绝，不把它夹到`:59`。元数据与同次西占time_context实际TT/时表/依赖严格核对；不可回退到旧误标框架。profile 1.0.2及新增源码hash触发缓存失效。原始失败不删除，节气根±1秒适配测试只证明半开区间实现，不是独立秒级准确性。

## 八字扩展与身宫丑支修正

胎元按给定节令月柱干进一位、支进三位，胎息按所选日柱干五合、支六合；不是受胎日期的医学推断。命身宫使用校正年干、节令月支和所选民用/太阳时支，维持现代节令月兼容约定；不冒称袁树珊《命理探源》的中气进月原法。手数定义与五虎遁参考：[鲲侯命宫](https://xuebz.com/baike/gongwei/ming-gong)、[身宫](https://xuebz.com/baike/gongwei/shen-gong)。该现代出版者的程序上游UNKNOWN，独立手数验证不等于已证明外部程序独立，也不证明玄学预测效力。

命宫按子位起正月逆数至生月，再将时支置该处顺数至卯；身宫按子位起正月顺数至生月，再将时支置该处逆数至酉。两者干均按**同一个校正年干的五虎遁**。`shen-chou-five-tigers-stem-v1`修正lunar-php 1.4.0身宫在丑位独有的`offset%12`环回：甲/己年应为丁丑而非乙丑，其余年干依同一规则顺推。地支、四柱及起运规则不改；API保留`engine_compatible_gan_zhi`与实际修正标识，旧失败和纯规则/出生输入对照分层保留。

## 恒星黄道与 Lilith 的具体定义

恒星黄道始终使用 `CRC1956-23.25-true-frame-anchor-IAU2000A-v1`。在 1956-03-21 00:00 **TT**，取真黄道/真春分点框架经度 23°15′、纬度零的单位方向；旋回固定 ICRS 方向，再在目标时刻真黄道/真春分点框架投影，该经度为减去的 ayanamsha。对行星和四轴/非整宫宫尖减同一偏移；整宫制在移动后的恒星 ASC 所在星座重新划分。速度使用各端点各自偏移，不把岁差贡献遗漏。

[IMD Positional Astronomy Centre 的 Panchang 说明](https://packolkata.imd.gov.in/panchang/en/explanation)提供 1956 锚值的背景，但不唯一规定本实现选择的现代框架、TT 和旋转。**这是具名自定义现代重建，未证明等于官方 Lahiri、Swiss Lahiri 或旧版逐位输出**；不把这些名字用作精度背书。产品页面须显示自定义标识。只有独立相同数学定义对照通过，才能说该定义的计算符合；不能由此认证其它标准等价。

`mean_lilith` 是 **mean lunar apogee**：IERS2010 Delaunay 基本角 `F + Ω − l + 180°`，以 TT 儒略世纪求值，再以 IAU2000A 黄经章动转到盘面真春分点。其零纬为盘面约定，距离为空；不是瞬时真实远地点、插值/振荡黑月、假想第二卫星，也不以同名证明旧版定义等价。基本角来源：[IERS2010 第5章式5.43](https://iers-conventions.obspm.fr/content/chapter5/icc5.pdf)。现有 ERFA 基本角分解对照独立于合并多项式，但共享 IERS 规范。

真北交点另定义为 DE440s 地月瞬时几何轨道平面与同一真黄道面的北向交线；南交点取其对点。它们不是平均交点，亦非对观测事件作时间插值。

Chiron 当前使用 Lowell `astorb.dat` 的署名许可元素及自产日心 ICRF/TDB 轨道，来源、固定元素、数据和构建 hash 见 `resources/natal/chiron-data-manifest.json`。`full` 实算十主体、真南北交、平均 Lilith 与 Chiron 共14点，四轴另列；Chiron 与其它主体使用同一地心视框架、黄道转换、落宫与相位处理。缺数据、准入/hash不符或超出闭区间时拒绝计算，不以其它点补位、不在线回退。JPL/NIMA 邮件仍未授予权利，本路线不使用其 Chiron 数据。Lowell 准入、Gaia外部初值/独立软件的采样对照及版本接受分别记账；有限力模型、共有行星数据及未传播协方差的限制保留，不据采样证明世纪连续物理误差界。

Python→Laravel 的 JSON 传输采用 ASCII Unicode 转义，解码后保留原中文字符串；不继承 Windows CP936 等终端码页。独立科学数值与计算口径不因传输转义而改变。

## 独立规则参考的新增覆盖与限制

`oracle/ziwei_classical_brightness_sources.json` 独立转录《紫微斗数全书》公开矩阵中的十四主星168格、昌曲火铃羊陀64格；`ziwei_brightness_reference.py` 将其与独立农历安星规则结合。它不导入产品或iztro，不从actual生成expected，输出来源表与位置规则依赖hash。七级别名只作同义字转换；羊、陀各四个未列支不补值，其它星曜亮度不由此推断。具体刻本与在线转录的对应尚未证明，同页太阴正文与矩阵异文保留；矩阵一致不能冒称整派、玄学效力或版本接受。

2024寒露另有Horizons DE441、Earth地心Q31、IAU76/80视黄道日期框架的公开太阳网格参考。195°被相邻UTC秒 `2024-10-07 18:59:58Z`、`18:59:59Z` 夹住。在该模型、局部单调与根括区间前提下，nearest-second后的两端均在+08的 `[01:00,03:00)` sect1起运桶；五个既有输入的离散起运及Gregorian结果可作条件化独立交叉核对。原HKO分钟参考的不确定记录不改写。采样分辨率和跨模型根差不是物理误差界，也不证明IAU76/80与IAU2000等价或精确物理秒。

本命农历岁首/早晚子参考与选定大限参考分开：前者按HKO给定日期及固定current-date子时口径；后者仅检查各局首限首年、末年与次限首年的7月1快照。不把年中快照称为童限、农历岁首或整年恒定证明。流年鸾喜公开规则只用于流年支，不能自动套给大限、小限或所有流曜。

### 选定运限的可重放参考与范围

`oracle/ziwei_selected_reference.py` 只消费独立农历出生输入及显式 `target_lunar_year`，不转历，也不把这个标签直接等同HTTP的公历 `target_year`。它按既有独立本命宫干/四化规则组合出大限、小限和流年参考；童限采用六龄角色表与现代五行局起限截断的**显式profile组合**，不冒称古籍同一段规定了该组合。童限四化/流曜仍为 `SCOPE_NOT_ESTABLISHED`；小限四化为宫干→四化表→本命目标宫的数学组合，不冒称古籍直接规定小限四化。

`oracle/ziwei_kong_reference.py` 分开输出截空/旬空的成对支及正旁角色。[中州派讲义“截空、旬空”节](https://www.guoxuedashi.com/a/22312bxfo/281042u.html)和[安星诀转录](https://www.ziweicn.com/show/3084.html)明确正支与出生年阴阳相同；这是具名派别证据，不推广为全部传本。现有60周期结果的截空pair和旬空正支均一致。**“产品截路=正空、空亡=旁空”是假设，不是已证名称合同**：它在30个阴干周期中失败，产品两名称实际固定于阳支/阴支。不能据这个假设交换星位或改expected；独立别名映射仍未关闭，原失败保留。

产品对大小限引擎有限表的未匹配哨兵明确返回 `NOT_APPLICABLE / OUTSIDE_DEFINED_PERIOD_RANGE`，不序列化默认甲子、负宫索引、空四化等假结果；流年负索引及畸形索引仍报错。有效本命及流年继续返回。小限表为1～120虚岁，大限为已注册12段；超出该表的处理不证明全历史/未来运限能力，也不把年龄范围外字段伪造为已验证。APP对不适用层不提供假详情，旧已存有效层仍可读。

运限岁首另有16个真实引擎组件边界例：按HKO固定日期覆盖2023～2025春节前后、元旦和2024立春次日；不是新增HTTP任意参考日期能力，不冒称已运行最新APP/持久DB。所有本节补证均 `NOT_BLIND`，不得叠加既有比较项成为新增盲测或完整AC通过数。
