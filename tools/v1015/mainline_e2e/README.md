## What actually executes after a future grant

`run.py` logs in ten fictional ordinary accounts (five independent pairs), checks
the server's login receipt/refresh anchor and rejection of the old token, uploads
a deterministic one-pixel PNG, posts/replays/conflicts a logical message, reads
message/attachment/notification counts from the actual database, and exercises
Block/MC/CN/disabled actors plus old media and old notice presentation.
The first POST response is recorded but deliberately withheld from the caller:
this is **application acknowledgement suppression**, not physical packet loss.

The PHP bridge seeds only an empty, already migrated new schema. It refuses an
existing populated schema rather than resetting it. All relationship transitions
call the actual LiveConsentService; no test HTTP fixture endpoint is added.
The fictitious ordinary rows use is_synthetic=false, matching the existing
bounded Feature fixture semantics; this is not a real-identity-provider claim
or a modification of its policy. No tests use old Seed or real users.

There is no bundled valid H.264 MP4 and no encoder/download path. A future operator
may supply a qualified task-owned synthetic MP4 <=128KiB and hash; the script then
uploads it through the real media endpoint and requires ready + HTTP206. Without
it that scenario remains NOT_RUN. Image/video picker, playback, process restart,
offline ciphertext/Keystore and deletion evidence require the actual APP/device.

APP evidence is collected separately using `app_observation.template.json` and
the six named APP observation scenarios. This source does **not** include an
automated device/UI tap driver. The future approved operator must perform the
listed APP actions and attach actual source/APK-bound artifacts; ingestion checks
origin/source/artifact hashes but is not independent verification of screenshot
meaning. It never treats API-only results as complete APP E2E.
The driver always emits `e2e_pass:false` and a bounded observation classification,
leaving functional acceptance to Astra. Physical15/30-day elapsed time and purge,
RTC/AEC and real Push remain distinct and open.

## Testing-only eligibility seam

The unchanged ordinary local gate only lists historical dev instances; the old
bounded MariaDB test guard is fixed to its old task. Reusing either would access
the wrong instance or leave the new harness unable to exercise business logic.
The production LiveConsentService remains final and gains a *testing-only*
named container qualifier. The test bootstrap registers a callback that verifies
the new live instance and source context; every parent business authorization
still enforces current accounts, CN, MC, Block, membership and media ownership.
Normal public/index.php does not register it. It is not controlled by request
headers, routes or client claims. Failed/false/non-boolean qualification never
falls back to an accepted environment. No old allowlist or budget is enlarged.

PHP path checks run before reading context, reject network/device namespaces,
check raw/canonical consistency and visible ancestors within the private root.
Python also checks native reparse attributes. Actual Windows native path/process
closure is **not qualified by the pure tests** and must be independently established
before the future launch. JSON consistency is not protection against an operator
who can alter all code/environment.

## Evidence and limits

See scenarios.json for AC mappings and exact required layers. HTTP raw records
contain request fields/response bytes, PHP snapshots include actual counts and
transaction identities, and the ledger records operation status/hash/exit.
These may contain credentials, so raw/ledger/context stay LOCAL_ONLY.
Only sanitized summaries/hashes belong in review artifacts.

Current real WS routing remains a 501/503 stub; the API driver does not invent a
WebSocket transport or report delayed-WS success. APP epoch/late-response
observations and the outstanding transport remain explicitly separate.
F3 cold-start locks until new online verification by design. Do not persist
untrusted grants just to make cross-restart offline reads appear successful.
